## 1. 목표 / DoD
DoD(계획서 원문): **MCP 직접 DB/RAG 호출 제거, REST·MCP parity, 오류 taxonomy·비밀 비노출 유지.**

즉 같은 기능을 REST와 MCP가 **서로 다른 코드로 두 번 구현하지 않는다**. 두 인터페이스가
동일한 유스케이스/포트를 호출해 결과가 일치해야 한다.

## 2. 현황 진단 — 실제 parity 위반 지점
| 기능 | REST | MCP | 상태 |
|---|---|---|---|
| RAG 답변 | `build_answer_question()`(Phase 1 유스케이스) | **`app.rag.qa.answer()`(레거시)** | **위반: 구현 2벌** |
| 벡터 검색 | `rag.service.search` | `rag.service.search` | 포트 미경유(백엔드 교체 불가) |
| 상품 카탈로그 | `db.query(Product)` (라우터) | **`db.query(Product)` (서버 직접)** | 중복 구현 |
| 커머스 도구 5종 | — | `commerce_tools`(에이전트와 공유) | OK(단일 구현) |

→ 핵심은 **RAG 답변이 두 벌**이라는 것. MCP를 유스케이스로 수렴시키면 레거시 `app/rag/qa.py`가
죽는다(= 메모리에 남겨둔 "Phase 8 레거시 수렴" 항목 해소).

## 3. 설계
### (a) MCP → 유스케이스 수렴
- `rag_qa` 도구 → **`build_answer_question(top_k)`** 호출(REST와 **동일 경로**).
  응답 shape는 MCP 기존 계약(ok/answer/sources)을 유지하되 내용은 유스케이스 결과로 채운다.
- `vector_search` 도구 → **`RetrieverPort`** 경유(composition에서 주입). 백엔드(FAISS/pgvector/
  hybrid/graph) 교체가 MCP에도 그대로 적용된다.
- `product_catalog` 리소스 → 상품 목록 조회를 **공용 함수 1벌**로 만들어 REST 라우터와 공유
  (서버에서 `db.query(Product)` 직접 호출 제거).

### (b) 레거시 제거(수렴 완료 처리)
- `app/services/order_service.py::create_order` — Phase 6 이후 **호출자 0** → 삭제
  (`list_orders`/`get_order`는 읽기 경로로 계속 사용).
- `app/rag/qa.py` — (a) 이후 **호출자 0** → 삭제. 단, 테스트 커버리지를 잃지 않도록:
  - 중복 테스트(빈 질문·abstention·출처 dedup·빈 응답)는 이미 `test_answer_question.py`가 커버 → 삭제.
  - **프롬프트 인젝션 방어 테스트**는 유스케이스용으로 **이관**(유스케이스 프롬프트에도 방어 문구 존재).
  - `test_pdf_parse_failure_raises_infra_error`는 qa와 무관(`build_index`) → **다른 파일로 이관**.

### (c) 유지해야 할 것(회귀 금지)
- MCP 오류 taxonomy(`[APPERR:<nonce>:<code>]` per-call nonce)와 HTTP 상태 매핑.
- 비밀 비노출: `runtime_config`에 API 키가 없어야 한다(테스트로 고정).

## 4. DoD ↔ 테스트 매핑
- **TEST-MCP-PARITY-001**: 동일 질문에 REST `/api/rag/qa`와 MCP `rag_qa`가 **같은 answer·sources**
  (동일 유스케이스·동일 fake 모델 주입으로 결정론 비교).
- **TEST-MCP-NOSECRET-001**: `runtime_config` 출력에 키/시크릿 문자열 없음.
- 회귀: 기존 MCP 8 + 오류 taxonomy 테스트 유지, CI 전체 유지.
- 레거시 삭제 후에도 커버리지 유지(인젝션 방어·PDF 실패 테스트 이관 확인).

## 5. Codex 점검 포인트
1. MCP 응답 shape를 유스케이스 DTO로 바꿀 때 **기존 MCP 계약 파괴** 위험 — 어디까지 보존해야 하나.
2. `product_catalog` 공용화 시 REST 라우터와 MCP가 세션 수명(요청 스코프 vs 자체 open/close)이
   다른데 공용 함수 설계를 어떻게 해야 안전한가.
3. 레거시 삭제(`rag/qa.py`)로 잃는 테스트가 정말 없는지 — 이관 누락 점검.
4. 놓친 parity 위반(ML 도구 3종·리소스·프롬프트)이 있는가.
