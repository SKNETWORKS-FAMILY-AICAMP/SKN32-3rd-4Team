# 지식 바운티 — 검증 모델 재설계 (원 기획 UC-03 교정)

- 작성: 2026-07-22
- 상태: **설계 교정**. 바운티는 현재 미구현(v3.1에서 범위 밖)이므로 코드 변경 없이 설계를 바로잡는다.
- 교정 대상: 원 v3.0 기획서 `docs/AI_에이전트_커머스_지식바운티_통합_구현계획서_LLM용.md`의 UC-03 / REQ-BNT-03

---

## 1. 원 기획의 결함

원 기획 UC-03은 이렇게 되어 있다.

```
Provider가 답변 + 출처 + 증거해시 제출
→ Validator가 **사실성**·정합성·중복·재현성 평가
→ 이의제기 기간 → 포인트 정산
```

`REQ-BNT-03`도 "Validator가 근거·정합성·중복을 평가한다"로 되어 있으나, UC 본문의
**"사실성 평가"** 는 근거 없는 가정이다.

**핵심 문제**: 대조할 정답(ground truth)이 없으면 참·거짓을 자동으로 판정할 수 없다.
우리가 가진 것은 세계의 사실이 아니라 제출된 텍스트와 우리 색인뿐이다. 따라서
"Validator가 사실성을 판정한다"는 설계는 특정 출처·관리자를 진실의 기준으로 삼는
**권위 위임**이며, 그 권위의 정당성은 어디에도 정의돼 있지 않다.

> ※ 교정 기록: 초판은 "자동 검증이 가능하면 그 지식을 살 이유가 없다"는 논리를 썼으나
> 이는 일반적으로 성립하지 않는다 — 발견 비용과 검증 비용은 다를 수 있다(Codex 지적).
> 문제의 본질은 비용 비대칭이 아니라 **정답의 부재**다.

**추가로 놓치기 쉬운 함정**: 우리가 가진 `self_verify.py`의 `SupportCheck`는
**"근거 → 주장"의 함의(entailment)만** 판정한다. 그 근거 자체가 거짓·조작·낡은 것이면
그대로 통과한다. **근거성 검증은 사실성 검증이 아니다.**

## 2. 문제의 이름

**정답(ground truth)이 없는 정보시장의 오라클 문제**.

Validator가 확인할 수 있는 것은 세계의 사실이 아니라 **제출물의 성질**뿐이다:
정합성(제시된 근거와 답변이 맞물리는가) · 재현성(출처를 다시 열어 확인 가능한가) ·
중복성(이미 아는 것인가).

## 3. 설계 원칙 전환

> **"진실을 검증한다" → "근거성·절차를 검증하고, 확인 가능한 위반에 경제적 비용을 붙인다"**

주의: "거짓을 손해로 만든다"가 아니다. 억제 대상은 객관적으로 확인 가능한 부정행위
(위조 인용·미확인 출처·중복)이며, **근거가 갖춰진 그럴듯한 허위는 통과한다.**

이 전환은 본 프로젝트의 기존 철학(근거 없으면 생성하지 않는 abstention, 무폴백,
한계의 정직한 기록)과 정확히 같은 계열이다.

## 4. 4계층 검증 모델

### L0 — 바운티 등급화 (사전 게이트)
바운티 생성 시 **검증 조건과 허용 출처를 미리 명시**한다. 그리고 등급을 나눈다.

| 등급 | 정의 | 정산 방식 |
|---|---|---|
| `verifiable` | 명시된 출처로 재현 확인이 가능한 주장 | L1~L3 적용, 사실성 아닌 **근거성** 기준 정산 |
| `outcome-linked` | 사후 관측 가능한 결과가 있음(반품률·고장률 등) | L4 결과연동 정산 |
| `opinion` | 객관 검증 불가(취향·추천·전망) | **사실성 정산 대상에서 제외**, 참고 정보로만 |

객관 검증이 불가능한 질문을 검증 가능한 척 정산하지 않는다 — 이것이 첫 번째 방어선이다.

### L1 — 기계 검증 (통과 못 하면 정산 대상 아님)
| 검사 | 방법 | 기존 자산 |
|---|---|---|
| 근거 제시 여부 | 출처 없는 제출은 즉시 반려 | RAG 인용 규약 |
| 근거↔주장 정합성 | 함의 판정 | `app/application/self_verify.py` SupportCheck |
| 출처 재현성 | 증거 해시·locator로 원문 재조회 | GraphRAG provenance, 인덱스 |
| 중복성 | 임베딩 유사도 임계 초과 시 중복 처리 | FAISS / pgvector |

**L1은 "맞다"를 증명하지 않는다.** "근거가 있고, 그 근거가 주장을 지지하며, 새롭다"만 확인한다.

### L2 — 경제적 억제 (escrow + 제한적 slash)
- 포인트는 즉시 지급하지 않고 **escrow**에 묶는다.
- **이의제기 기간**을 둔다. 기간 경과 후 정산.
- Provider는 소액을 **stake**한다. 다만 **몰수(slash)는 객관적 위반에만** 적용한다:
  출처 위조 / 재현 실패 / 명백한 중복.
  → **"틀린 것 같다"는 이유로는 몰수하지 않는다.** 진실 판정을 몰수 근거로 삼는 순간
  L1의 한계를 넘어서는 권위 주장을 하게 된다.

### L3 — 표본 감사 (전수 검증 포기)
- **고액·고위험 건만** 무작위 표본으로 감사한다. 2인 독립 검토.
- 목적은 전수 검증이 아니라 **기대이익 역전**이다: 감사 확률 p, 벌칙 P일 때
  `p × P > 거짓으로 얻는 이익`이면 거짓 제출이 손해가 된다.
- 감사 결과는 평판에 반영하되, 평판은 **검증 가능한 부분집합에서의 성적**임을 명시한다.

### L4 — 결과연동 (가능한 것만)
반품률·고장률·재문의율처럼 **사후에 관측되는 신호**가 있는 주장만 결과와 연동해 정산한다.
검증 불가능한 지식을 억지로 정산하는 대신, **정산 가능한 형태의 질문을 늘리는** 방향이다.

### 채택하지 않은 것 — peer prediction
집단 합의로 진실을 추정하는 기법(peer prediction / BTS)은 **이 규모에 과하다.**
참여자가 적으면 공모와 상관오류(여러 Provider가 같은 LLM 편향으로 똑같이 틀림)에 취약해
오히려 잘못된 합의를 보상할 수 있다.

## 5. 구매자 만족도 취급 (중요)

**만족도를 정산 기준으로 쓰지 않는다.** 쓰면 다음이 보상된다:

- 정답보다 **구매자가 듣고 싶은 답**
- **과도한 확신** (모른다고 하면 평점이 깎이므로)
- **불확실성 은폐**

즉 **그럴듯한 날조를 적극적으로 장려**하게 된다. 부수적으로 Provider–구매자 공모,
Sybil 계정, 저평점 협박, 검증 쉬운 질문만 고르는 역선택도 열린다.

→ 만족도는 **서비스 품질 신호로만 분리 수집**하고, 포인트 정산식에서 제외한다.

## 6. 개정 요구사항

| ID | 개정 내용 | 검증 방법 |
|---|---|---|
| REQ-BNT-01 | 근거 부족(abstention) 시 바운티를 생성한다 | 지식갭 → 바운티 생성 경로 테스트 |
| REQ-BNT-02 | Provider별 데이터 접근 범위를 격리한다 | 권한 밖 문서 조회 0건 |
| REQ-BNT-03 | **(개정)** Validator는 **근거성·재현성·중복성**을 평가한다. **사실성은 판정하지 않는다** | 각 검사의 통과/반려 케이스 테스트 + 사실성 판정 코드 부재의 정적 확인 |
| REQ-BNT-04 | 비현금 내부 포인트 원장(이중지급·음수잔액 방지) | 멱등·원장 테스트 |
| **REQ-BNT-05** | **(신설)** 바운티는 생성 시 등급(verifiable/outcome-linked/opinion)과 허용 출처를 명시한다 | 등급 없는 바운티 생성 거부 |
| **REQ-BNT-06** | **(신설)** 포인트는 escrow→이의제기 기간→정산 상태를 거친다 | 상태 전이 테스트, 기간 내 정산 시도 거부 |
| **REQ-BNT-07** | **(신설)** slash는 객관적 위반(출처 위조·재현 실패·중복)에만 적용한다 | "부정확 의심" 사유로는 slash 불가 테스트 |
| **REQ-BNT-08** | **(신설)** 구매자 만족도는 수집하되 정산식에 포함하지 않는다 | 정산 계산에 만족도 입력이 없음을 정적 확인 |

## 7. 상태 머신 (바운티 수명주기)

```
draft → open(등급·허용출처·보상 확정, stake 예치)
      → submitted(답변+출처+증거해시)
      → L1 기계검증 ─실패→ rejected(사유 기록, stake 반환 또는 객관위반 시 slash)
                    └성공→ escrowed
      → dispute_window(이의제기 기간)
          ├ 이의 없음 → settled(포인트 정산)
          ├ 이의 제기 → under_review(고액·고위험이면 L3 표본감사·2인 검토)
          └ 결과연동 건 → awaiting_outcome → settled/partial
```

무폴백 원칙: 각 전이 실패는 조용히 다음 단계로 넘어가지 않고 사유와 함께 정지한다.

## 8. 명시적 비주장 (문서·UI에서 금지)

- ❌ "Validator가 진실을 판정한다"
- ❌ "포인트가 사실성을 보증한다"
- ❌ "검증된 지식입니다"(무한정 표현)
- ✅ 대신: "제시된 근거로 재현 확인된 답변입니다", "근거성·중복성 검사를 통과했습니다"

우리가 주장할 수 있는 것은 **근거성 · 재현성 · 절차적 신뢰도**까지다.

## 9. 기존 자산 매핑 (당장 쓸 수 있는 것)

| 계층 | 이미 있는 것 |
|---|---|
| 바운티 트리거 | abstention → `KnowledgeGap` 큐(PII 마스킹) |
| L1 정합성 | `self_verify.py` SupportCheck |
| L1 중복 | FAISS / pgvector 임베딩 |
| L1 재현성 | GraphRAG provenance(원천+locator) |
| L2 원장 | 멱등 주문/원장 패턴(`OrderIdempotency`) 재사용 |
| L3 감사 | `run_events` append-only + 관리자 대시보드 |

## 10. 한계 (정직 기록)

- 이 모델은 **사실성을 보장하지 않는다.** 근거가 거짓이면 L1을 통과한다.
- L3 표본감사의 억제력은 감사 확률·벌칙 크기에 달려 있고, 그 값은 실 운영 데이터 없이
  정할 수 없다. 초기값은 추정치이며 튜닝 대상이다.
- 평판 점수는 **검증 가능한 부분집합에서의 성적**이지 Provider의 전반적 정확도가 아니다.
- 본 문서는 설계 교정이며 **구현은 아직 없다**(v3.1에서 바운티는 범위 밖).
