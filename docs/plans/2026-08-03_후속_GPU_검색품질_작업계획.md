# S7 후속 GPU 검색 품질 작업계획

작성일: 2026-08-03 KST

## 목표

OCR·축 바인딩으로 확정한 S7 코퍼스를 대상으로 임베딩 모델과 리랭커를 다시 평가하고, 통과한 조합만 운영 후보로 승격한다. 외부 RunPod에는 DB 자격증명을 전달하지 않고 재현 가능한 벡터·점수 artifact만 생성한다.

## 핵심 원칙

- `dragonkue/snowflake-arctic-embed-l-v2.0-ko`는 잠정 1순위이며 운영 확정 모델이 아니다.
- S7 코퍼스, 구어체 질의, 보험사·상품·문서 버전 분리 holdout에서 다시 평가한다.
- 리랭커 도입 여부는 bi-encoder의 `Hit@10`을 먼저 본 뒤 결정한다.
- 정답이 top 10에 없으면 리랭커로 복구할 수 없으므로 청킹·임베딩·hybrid retrieval을 먼저 고친다.
- 외부 GPU는 artifact-only로 사용하고, pgvector 적재와 accepted release 변경은 로컬에서 승인 후 수행한다.

## GPU 배치안

OCR 종료 직후에는 청킹을 기존 권고값으로 고정하고 Arctic-ko 하나만 처리한다.

| GPU | S7 Arctic-ko 생성 |
|---|---|
| x600 | 신규·변경 chunk shard 및 지연시간 기준선 |
| RunPod 1 | 신규·변경 chunk shard |
| RunPod 2 | 신규·변경 chunk shard |
| RunPod 3 | 신규·변경 chunk shard |
| RunPod 4 | 신규·변경 chunk shard |
| RunPod 5 | 신규·변경 chunk shard 또는 OCR 실패 재시도 |

동일 chunk 벡터를 재사용한 뒤 신규·변경분만 6대에 분산한다. 리랭커는 Arctic-ko top-10/20 후보가 고정된 다음 실행한다.

## 외부 RunPod 보안·재현성

- DB 자격증명과 accepted manifest는 전송하지 않는다.
- 입력은 필요한 공개 약관 chunk만 `sha12` 이름으로 평탄화하며 개인·계약자 데이터는 보내지 않는다.
- 원격 실행 환경은 lockfile, 모델 commit revision, CUDA/PyTorch/Transformers 버전을 시작 전에 확인하고 다르면 중단한다.
- 원격 산출물은 벡터·opaque ID·provenance로 제한하고 SHA-256 sidecar와 함께 회수한다.
- 로컬 검증·적재가 끝난 뒤 원격 임시 입력과 산출물의 정리 여부를 별도로 기록한다.

## 예상시간

- S7 평가셋 재매핑·holdout 동결: 30~90분, 주로 CPU
- 2~3개 임베딩 모델 평가·성능 계측: 30~90분
- 승자 전량 shadow embedding artifact: 20~60분
- 2개 리랭커 top-10/20 평가: 30~90분
- 로컬 적재·무결성·회귀 검증·리포트: 45~90분

OCR 이후 추가 소요는 스크립트 호환 문제가 없으면 약 2.5~5시간이다. 파인튜닝은 이 시간에 포함하지 않는다.

## 이번 시간창에서 하지 않는 작업

- 라벨 없는 synthetic pair만으로 리랭커를 파인튜닝하지 않는다.
- 일반 LLM을 보험 판정 모델로 파인튜닝하지 않는다.
- S7 검증 전에 accepted 운영 인덱스를 덮어쓰지 않는다.
- 외부 RunPod에서 운영 DB로 직접 쓰지 않는다.
- 모든 페이지에 두 번째 OCR을 다시 돌리지 않는다. `review_required`와 모델 불일치 표본만 대상으로 한다.

## 후순위 GPU 작업

- 운영 질의 로그가 쌓인 뒤 hard-negative mining과 LoRA 리랭커 학습
- FP16/BF16 대 INT8 리랭커 지연시간·품질 비교
- 변경 chunk만 재임베딩하는 incremental index 검증
- OCR/binder disagreement 사례의 선택적 두 번째 VLM 판독
- 설명 생성 모델은 근거 인용 이후의 표현 계층에만 사용하고 판정 엔진은 규칙·검증 fact를 유지
