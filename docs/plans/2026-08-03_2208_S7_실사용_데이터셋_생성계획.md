## 1. S7 데이터 계약

### 1.1 두 층을 섞지 않는다

| 층 | 뜻 | serving/citation |
|---|---|---|
| `accepted_evidence` | s6에서 이미 검증 게이트를 통과한 조항·선 기반 표 | 기존 자격 유지 |
| `candidate_facts` | MinerU/무테두리/다축 표에서 새로 결합한 사실 후보 | 사람 승인 전 항상 차단 |

S7을 만들었다는 이유만으로 `config/accepted_extraction.json`은 바꾸지 않는다. S7은 완성된
**candidate release artifact**로 내고, 사람 승인 뒤 별도 릴리스 전환을 한다.

### 1.2 페이지 선택 모드

- `native_layout`: PyMuPDF `find_tables()` 결과가 존재
- `verified_line_grid`: 좌표 복원 `method=선`이고 `is_table is not False`
- `ocr_candidate`: 업무 키워드 페이지에 SHA가 맞는 MinerU 결과가 존재
- `text_only`: 위 구조가 없고 본문만 존재
- `failed`: 명시적 실패. 빈 결과로 조용히 대체하지 않음

한 페이지에 복수 근거가 있어도 `selected_mode`는 우선순위 규칙으로 하나를 고르고,
나머지는 `available_modes`와 계보에 보존한다. OCR은 승인 상태를 바꾸지 않는다.

### 1.3 candidate fact 최소 필드

- 결정적 `fact_id`, `fact_type`, `value`
- `axes` (`plan`, `service`, `institution`, `coverage`, 필요 시 generation/product)
- 문서 SHA·쪽·표 번호·행/셀 원점·이미지 SHA·모델 revision
- `evidence_granularity`, `confidence_signals`, `review_reasons`
- `approval=candidate`, `serving_eligible=false`, `citation_eligible=false`

- 로컬: s5/s6 스트리밍 변환, schema/lineage 검증, 최종 manifest
- RunPod: 선별 렌더 PNG의 MinerU 추론만 수행

- DB 자격증명·운영 승인 포인터는 전송하지 않는다.
- 원격 결과는 이미지 SHA, 모델 revision, 설정이 일치해야만 병합한다.
- 30GB 디스크 한도를 넘기지 않도록 배치별 전송·회수·삭제한다.

- S7 핵심 지표가 s6보다 열화: accepted 포인터 전환 금지
