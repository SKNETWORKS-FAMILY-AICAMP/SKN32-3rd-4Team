## 0. 왜 지금 v5 인가

`_3rd_project_4`(팀 다른 갈래의 전처리 코드)와 **같은 PDF 244건**을 정면 대조하다가
우리 쪽 결함이 드러났다.

```
조항 수 중앙값   우리 v4  94   /   3rd  121
문서별 승패      우리 35건 / 3rd 197건
번호 체계 판정   244건 중 242건 일치  ← 근본 오판은 양쪽 다 없다
```

차이는 전부 **우리가 본문 페이지를 목차로 오판해 버린 것**에서 나왔다.

| 항목 | 실측 |
|---|---:|
| v4 전체 | 1,367문서 · 162,678쪽 |
| 목차로 제외한 쪽 | 29,221 (**18.0%**) |
| └ 그중 **비율 규칙만**으로 제외 | 25,736 (**전체의 15.8%**) |

가장 나쁜 사례: NH농협생명 176쪽 문서의 「보상하지 않는 사항」이 목차상 **3개**인데
산출물엔 **1개**뿐이고, 그 1개조차 p39·40·41·44 가 빠진 채 조립됐다.
**면책 조항이 없는 것처럼 보인다** — CLAUDE.md 0장 위반 중 가장 나쁜 형태다.

> v4 중간리포트 §6 에 *"고정 임계값으로 판단했다 — 구조를 보는 규칙으로 바꿔야 했다"* 라고
> 적어 놓고 임계 200 을 그대로 뒀다. 반성문만 쓰고 코드를 안 고친 것이다.

## 1. 범위 — 4단계, 순서가 중요하다

**항·호 청킹을 먼저 얹으면 빠진 페이지 위에 정밀한 인용을 다는 꼴이다.** 순서를 지킨다.

| # | 단계 | 근거 | 상태 |
|---|---|---|---|
| **1** | 목차 판정을 구조 기반으로 교체 | 위 §0 | 착수 |
| **2** | 항(①)·호 단위 청킹 = **팀 11단계의 9단계** | `2026-07-31_전처리_파이프라인_현황.md:24` **❌ 없음** | 대기 |
| **3** | 추출 2모드 자동 선택 | 계획에도 없던 것. 3rd 에서 가져옴 | 대기 |
| **4** | 용어 정의 분해 | `terms.py`·`/v1/terms/explain`·평가셋 용어 5문항의 **선행 조건** | 대기 |

각 단계마다 **4개사(DB손보·삼성화재·NH농협생명·동양생명) 재실행 → 3rd 와 대조 → 통과 후 다음**.
4개사가 다 통과하면 나머지 8개사로 확대한다.

### 범위 밖 (이번에 안 한다)

- 표 의미 부착(보장 한도·자기부담금) — 원칙 충돌이 미결(점검 리포트 §4)
- 별표 귀속 · 준용 해소 — v4 리포트 §7 의 남은 한계 그대로
- 3rd 가 처리한 18건(비의료실손 풍수해보험) — **우리가 의도적으로 격리한 것**이다. 편입하지 않는다

## 2. 단계별 완료 기준 (DoD)

> `2026-07-31_전처리_파이프라인_현황.md` §175 가 *"11단계 각각의 완료 기준(DoD)을 정하지 않았다.
> '됐다'의 판단이 사람마다 다를 수 있다"* 고 지적했다. 여기서 정한다.

### 1단계 — 목차 판정

| 항목 | 기준 |
|---|---|
| 정답셋 | 사람이 눈으로 확인한 페이지 **최소 40쪽**(목차 20 / 본문 20), 4개사 층화 |
| 정확도 | 정답셋에서 **본문을 목차로 오판 0건**. 목차를 본문으로 놓치는 것은 허용(덜 위험) |
| 회귀 | NH `42ce81976809` 의 「보상하지 않는 사항」이 **3개** 나온다 |
| 규모 | 4개사 재실행 후 목차 제외율이 18.0% → **한 자릿수** |
| 대조 | 3rd 와 같은 PDF 기준 조항 수에서 **우리가 지지 않는다** |

### 2단계 — 항·호 청킹

| 항목 | 기준 |
|---|---|
| 산출 | 조항마다 `paragraphs[]`, 각 항에 `paragraph_no`·`items[]`·`text`·`citation` |
| 인용 | `citation` 이 `제4조(보상하지 않는 사항) 제1항 제3호` 형태로 조립된다 |
| 정직성 | 항 번호를 **특정 못 하면 `paragraph_no=null`** 로 두고 세어 보고한다. 추정 금지 |
| 회귀 | 조 단위 `text`·`content_hash` 는 **바뀌지 않는다**(하위호환) |

### 3단계 — 추출 2모드

| 항목 | 기준 |
|---|---|
| 선택 근거 | 모드별 점수를 `stats.extract_mode`·`stats.mode_scores` 에 **남긴다** |
| 회귀 | 4개사에서 조항 수가 **감소하는 문서 0건** |

### 4단계 — 용어 분해

| 항목 | 기준 |
|---|---|
| 산출 | `data/terms/{보험사}/s5_*/{sha12}.terms.json` |
| 정직성 | 용어 추출 실패를 **세어 보고**한다. 빈 결과를 성공으로 내보내지 않는다 |

## 3. 지켜야 할 것 (RULE.md 발췌 — 이번 작업에 특히 걸리는 것)

- **3.2 폴백 금지** — 목차 판정이 애매하면 조용히 한쪽으로 넘기지 말고 `parse_warnings` 에 남긴다
- **3.1 하드코딩 금지** — 임계값은 상수 모듈에 이름 붙여 선언하고 근거를 주석에 남긴다
- **2-4 legacy 보존** — `to_clauses.py` 를 고치기 전에 현행본을 `legacy/` 에 남긴다
- **1.2 검증 우선** — 실행 로그 원문을 리포트에 남긴다. "아마 될 것이다" 금지
- **버전 공존** — 산출 경로를 `s5_*` 로 올린다. **s4 를 덮어쓰지 않는다**
  (s3 를 남겨 뒀기에 v3 의 35% 손상을 찾을 수 있었다)
- **CLAUDE.md 4장** — 중요한 판단은 **코덱스와 교차검증**. 반박당하면 실측으로 가린다
