## 0. 무엇이 문제인가 — 세대를 정하는 곳이 **셋**이고 어긋난다

| # | 위치 | 값 | 쓰는 곳 |
|---|---|---|---|
| 1 | `config/accepted_extraction.json` `tag` | **`s5_pymupdf-1.28.0`** | `file_clause_store` — **기본 serving** |
| 2 | `scripts/index/build_clause_index.py` `_CLAUSE_TAG` | `s6_` | 적재 |
| 3 | `app/adapters/pgvector_clause_index.py` `CURRENT_GENERATION` | `s6` | 검색 |

**판정이 읽는 파일 저장소는 `s5`**(부록 분리 전 · 제목 흡수 6,575건 · 참조머리 8,005개 남은 판)이고,
**벡터 경로는 `s6`**(미승인)이다. 서로 **반대 방향**을 본다.

여기에 더해 페이지 스키마가 `s4 → s5` 로 올라
accepted 의 `s5_pymupdf-1.28.0` 이 **페이지 태그와 글자가 같아졌다.**
사람이 보면 어느 층 이야기인지 알 수 없다.

### 지금 무엇이 깨지나

- 판정 근거로 **부록을 삼킨 조항**이 나갈 수 있다 — `제27조(준용규정)에 따르면 분만은 O80~O84`
- 벡터 검색은 s6 를 보는데 파일 저장소는 s5 를 본다 → **같은 질문에 두 경로가 다른 조항을 준다**
- s6 는 **사람의 승인 절차를 안 거쳤다.** 그런데 벡터 경로는 이미 그걸 쓰고 있다

## 1. 설계 — 승인 포인터 하나 + 불변 릴리스 명세

코덱스 표현 그대로: **"승인 포인터 하나 + 불변 릴리스 명세 + 모든 경로에 명시적 주입"**

### 1-1. `config/accepted_extraction.json` 을 단일 진실원으로

```jsonc
{
  "release_id": "r2026-08-02-s5clause",   // ★페이지 s5 와 조항 s5 의 이름 충돌을 끊는다
  "page_tag":   "s4_pymupdf-1.28.0",
  "clause_tag": "s5_pymupdf-1.28.0",
  "document_count": 1367,                  // 일부만 있는 상태를 막는다
  "artifact_manifest_sha256": "…",         // 산출물 목록 해시
  "embed_profile": {
    "model": "", "revision": "", "dim": 0,
    "max_seq_length": 0, "chunk_budget": 0, "overlap": 0
  },
  "accepted_at": "…", "accepted_by": "…", "reason": [...], "measured": {...}
}
```

- ★`index_generation` 은 **저장하지 않는다.** `clause_tag` 에서 엄격히 파생한다.
  중복 필드를 두면 **다시 어긋난다**(코덱스).
- `embed_profile` 은 모델 이름만이 아니라 **차원·토크나이저·청킹 예산까지** 고정한다.
  이름만 같고 설정이 다르면 벡터 공간이 달라진다.

### 1-2. 모든 경로가 이 파일을 읽는다

```
app/core/release.py           AcceptedRelease 로더 (불변 dataclass)
  ├─ file_clause_store        clause_tag
  ├─ build_clause_index       clause_tag → 읽을 s6/s5 폴더
  ├─ pgvector_clause_index    index_generation(파생) · embed_profile
  └─ pg_clause_store          같은 조건
```

**코드에 문자열 상수를 두지 않는다.** 지금 세 곳에 박혀 있는 것이 정확히 이 문제의 원인이다.

### 1-3. 승인 전에는 s6 를 서빙하지 않는다

코덱스 판단: **B 가 맞다.** 가용성을 위해 미승인 s6 를 올리면 안 된다.

- 후보 s6 인덱스는 **미리 적재해도 된다**(shadow)
- **serving 포인터는 승인 후에만** 바꾼다
- 승인 조건: 구조 감사 · 검색 회귀평가 · 인용 정확도 · 문서 완전성 · 사람 표본검수가
  **s5 대비 기준을 통과**할 때

> ★그러면 지금 벡터 검색은 **0건**이 된다(s5 벡터가 없으므로).
> **그게 정직한 상태다.** 빈 결과가 틀린 근거보다 낫다(CLAUDE.md §0).

## 2. 체크리스트

### 지금 할 것

- [ ] **P1** `app/core/release.py` — `AcceptedRelease` 불변 dataclass + 로더.
      `clause_tag` → `index_generation` 파생. 설정 없으면 **실패**(폴백 금지)
- [ ] **P2** `file_clause_store` 가 `AcceptedRelease` 를 쓰도록. ★**캐시 키에 `clause_tag` 포함** —
      지금은 승인을 바꿔도 같은 프로세스가 옛 문서를 돌려준다(코덱스)

      **import 시점 기본값**을 없앤다
- [ ] **P4** `build_clause_index._CLAUSE_TAG` 제거 → 릴리스의 `clause_tag`.
      ★단 적재는 **shadow 세대**로도 가능해야 한다(`--generation` 명시)

      임포트 시점 I/O 는 테스트·CLI 를 깨뜨린다(코덱스)
- [ ] **P6** `CLAUSE_STORE` 의 **알 수 없는 값도 fail-closed**. 지금은 조용히 file 로 떨어진다

## 4. 코덱스가 지적한 것 중 이 계획에 안 들어간 것

- `artifact_manifest_sha256` — 산출물 목록 해시. **P7 에서 `document_count` 만 먼저 한다.**
  해시는 재생성이 끝난 뒤에 넣는다(지금 파일이 계속 바뀐다)
- `release_id` 는 넣되, 기존 필드를 지우지 않는다 — 다른 세션이 `tag` 를 읽고 있을 수 있다.
  **`tag` 는 당분간 `clause_tag` 의 별칭으로 남긴다**
