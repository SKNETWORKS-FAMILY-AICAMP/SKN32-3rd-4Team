# 0. 왜 v3.2인가 (방향 전환)

v3.1은 "기존 SQLite+FAISS 재사용 + YAGNI + 하드웨어 제약"으로 최적화하며 **PostgreSQL·pgvector·Hybrid·
Rerank를 후속으로 강등**했다. 그러나 사용자의 **진짜 목표는 이 스택들을 연습·구현하는 것**(포트폴리오, 넓게)이다.
→ **연습 대상은 YAGNI로 자르지 않는다(연습 자체가 산출물).** v3.1의 해당 절삭을 의도적으로 되돌린다.

사용자 확정 방향(2026-07-19):
1. 관계형/벡터: **SQLite/FAISS 기준선 유지 + PostgreSQL/pgvector 학습 트랙 병행**(포트 뒤에서 교체·비교).
2. 그래프DB: **GraphRAG 용도부터 설계** 후 DB 결정(Apache AGE=pg내장 vs Neo4j=표준, 미정).
3. 우선순위: **기술 연습·포트폴리오(넓게)**. 단 닫힌 루프도 완성.

**유지되는 것(v3.1에서 승계)**: RULE(무하드코딩·무폴백·검증우선·리포트), 개념적 Clean Architecture +
포트/수직 strangler, 모델 registry(모델ID 하드코딩 금지), phased+Codex gate, 승인 주문·멱등·trace.
**여전히 후속(사용자 관심 밖)**: 음성/화상, WebAuthn/Passkey, 풀 바운티 경제·포인트 원장, 4모델 실시간 라우터.

> 포트/Clean Architecture는 학습에 **유리**하다: 동일 `RetrieverPort` 뒤에서 FAISS↔pgvector↔Hybrid↔GraphRAG를
> 교체하며 **같은 평가셋으로 비교**하는 것이 이 프로젝트의 핵심 학습 활동이다.

# 2. 아키텍처 결정 개정

## ADR-005' (개정) 관계형·벡터 = 병행 학습 트랙, 포트로 교체 가능
- 기준선 **SQLite + FAISS 유지**(회귀 보존). 동시에 **PostgreSQL + pgvector 어댑터**를 추가한다.
- `RetrieverPort`(dense 검색)·`Repository`(관계형) 뒤에서 두 백엔드를 **런타임 설정으로 선택**·비교한다.
- **RetrieverPort 중립성(Phase 1 계약, 교체·비교의 전제)**: 포트는 백엔드 세부에 의존하지 않는다.
  `search(query, k, filters) -> list[Evidence]`, `Evidence = {content, source, locator(page 등), score, backend}`.
  점수는 **정규화**(거리↔유사도를 [0,1] 동일 방향으로)해 FAISS/pgvector/hybrid/graph 결과를 **같은 척도로 비교** 가능하게 한다.
  포트 반환에 백엔드 전용 필드(FAISS distance 원값 등)를 노출하지 않는다 → 어댑터가 정규화 책임.
- 비교는 산출물이다: 동일 RAG 평가셋(30문항)에서 FAISS vs pgvector의 Recall@3·지연·인덱싱 비용을 리포트.
- 인프라: PostgreSQL은 **Docker Compose**로 로컬 구동(약 5GB RAM 고려해 경량 설정·필요 시만 기동).
- RULE 무폴백 유지: 선택된 백엔드가 미준비면 명시 오류(자동 다른 백엔드 전환 없음).

## ADR-007 (신규) GraphRAG = 설계 우선, DB는 설계 후 결정
- 먼저 **지식그래프 용도·스키마**를 설계한다(후보: 상품↔호환성↔스펙 그래프, 정책↔조항↔예외 관계,
  주문↔상품↔카테고리). "무엇을 그래프로 두면 벡터/관계형보다 나은가"를 명시.
- **GraphRAG 검색 흐름**: 엔티티 링크 → 그래프 순회(k-hop) → 서브그래프 근거 + 벡터 근거 결합 → 답변.
- 설계 확정 후 **DB 결정 게이트**: Apache AGE(PostgreSQL 확장 — pg 한 곳에서 관계형+벡터+그래프 통합) vs
  Neo4j(표준 그래프DB·Cypher·GraphRAG 생태계). 트레이드오프를 리포트에 기록하고 사용자 합의로 확정.
- 포트 `GraphStorePort`·`GraphRetrieverPort`로 추상화(선택한 DB 어댑터가 구현).
- **그래프 근거 provenance(출처인용 유지)**: 그래프에서 나온 근거도 `Evidence` 계약을 따르며, 각 노드/엣지는
  **원천 문서(source doc/locator)로 역추적** 가능해야 한다(그래프는 문서 근거의 색인이지 근거의 대체가 아님).
  답변의 출처인용은 그래프 경로가 아니라 그 경로가 가리키는 **원천 문서**를 인용한다.

## ADR-008 (신규) CoT·Planning 활성화
- CoT: RAG 답변 생성에 **자기검증(self-verify)** 단계(근거-답변 정합 확인) 또는 복잡 질의 추론에 적용.
  `should_use_cot` 휴리스틱으로 단순 질의엔 끔(토큰 절약). 프롬프트 버전을 model_run에 기록.
- Planning: 다단계 상담(예: "예산 내 호환 부품 찾아 비교")에 plan-execute 적용(에이전트 경로 내).
- **자기검증 실패 시 동작(무폴백 정합)**: self-verify가 "답변이 근거에 의해 지지되지 않음"으로 판정하면,
  **무근거 답변을 그대로 반환하지 않는다.** 명시적으로 (a) abstention("근거 부족") 또는 (b) 1회 재검색 후 재검증한다.
  조용히 통과시키거나 임의 기본답으로 대체하지 않는다. 재검증도 실패하면 abstention. (TEST-COT-001이 이 경로 검증.)
- 무근거 생성 금지·승인 경계는 그대로(LLM은 제안자).

## 승계 유지 ADR
- ADR-001 모듈러 모놀리스 / ADR-002 개념적 Clean Arch + 수직 strangler / ADR-003 REST 기준계약 /
  ADR-004 LLM 제안자 / ADR-006 자동 fallback 금지 — 모두 v3.1대로 유지.
