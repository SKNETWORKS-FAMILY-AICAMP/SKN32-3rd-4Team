# Phase 9 계획서 — USER/ADMIN 역할 · 관리자 · 지식보강 큐

- 작성일시: 2026-07-20 10:10
- 상위 계획: `plans/2026-07-19_1600_v3.2_학습중심_개정.md` (Phase 9 행)
- REQ/TEST: REQ-AUTH-01, REQ-ADMIN-01/02, TEST-RBAC-*

## 1. 목표 / DoD
DoD(계획서 원문): **RBAC 401/403/200, 인덱스/주문/trace(관리자 조회), abstention 질의 큐(SHOULD).**

## 2. 현황
- `User`: id/username/hashed_password/created_at — **role 없음**.
- JWT payload: `{sub, exp}` — 역할 없음. `get_current_user`가 **이미 DB에서 User를 조회**한다.
- `RunEvent`(append-only 관측 이벤트) 존재. 관리자 라우터·지식 큐 없음.

## 3. 설계
### (a) 역할 모델 — 토큰이 아니라 DB에서 읽는다
- `User.role`(String, 기본 `"USER"`), 허용값 `USER`/`ADMIN`.
- **JWT에 role을 넣지 않는다.** 토큰에 박으면 권한 강등·회수가 만료 전까지 반영되지 않아
  **stale privilege**가 생긴다. `get_current_user`가 어차피 DB에서 User를 읽으므로
  **DB 값을 신뢰**하면 추가 비용 없이 항상 최신이다.
- 의존성: `require_admin` — 미인증 **401**, 인증했으나 USER면 **403**, ADMIN이면 통과(200).
- **알 수 없는 role 문자열은 USER로 폴백하지 않는다**(Codex (a)) — 명시적 오류로 거부.
  DB가 오염돼도 조용히 권한을 부여하거나 강등하지 않는다.

### (b) 마이그레이션 — `create_all`은 컬럼을 추가하지 않는다(중요)
`Base.metadata.create_all`은 **없는 테이블만** 만든다. 기존 DB에는 `role` 컬럼이 생기지 않아
운영/개발 DB가 조용히 깨진다. → `scripts/manage.py migrate`에 **명시적·멱등 컬럼 추가**를 넣는다
(`PRAGMA table_info`로 존재 확인 후 `ALTER TABLE ... ADD COLUMN role ... DEFAULT 'USER'`).
기존 사용자는 전부 `USER`로 채운다(관리자 자동 승격 금지).

### (c) 관리자 부트스트랩 — 조용한 승격 금지
- 최초 ADMIN은 **명시적 CLI**로만: `python -m scripts.manage promote <username>`.
  대상이 없으면 `NotFoundErr`, 이미 ADMIN이면 그대로(멱등).
- 환경변수·가입 시 자동 승격 같은 **암묵 경로는 두지 않는다**(권한 상승 사고 방지).
- **마지막 ADMIN 강등 금지**(Codex (d)): demote가 ADMIN을 0명으로 만들면 거부 —
  잠금(lockout) 방지. 승격/강등은 `run_events`에 **감사 기록**을 남긴다.

### (d) 관리자 API (`/api/admin`, 전부 ADMIN 전용)
- **fail-closed는 라우터 전역**(Codex (d)): 엔드포인트마다 수동으로 붙이면 새 엔드포인트에서
  누락된다 → `APIRouter(dependencies=[Depends(require_admin)])`로 **라우터 단위 강제**하고,
  `/api/admin/*` 모든 라우트가 이 의존성을 갖는지 **가드레일 테스트**로 고정한다.
- `GET /api/admin/orders` — 전체 주문 요약(사용자 무관). 일반 사용자 경로와 분리.
- `GET /api/admin/events` — `run_events` 조회(trace_id/kind 필터, 최신순, limit).
- `GET /api/admin/index` — RAG 인덱스 상태(존재·문서수 등 읽기 전용).
- `GET /api/admin/knowledge-gaps` — 지식보강 큐 조회.

### (e) 지식보강 큐 (SHOULD)
- `KnowledgeGap` 테이블: `question`, `trace_id`, `created_at`, `resolved`(기본 False).
- **abstention이 일어난 질문**을 큐에 적재 → "문서에 없어서 답 못한 질문" 목록이 곧
  지식 보강 대상이 된다.
- 적재 지점: RAG QA 경로에서 답이 `NO_ANSWER`일 때. 유스케이스(순수)는 DB를 모르므로
  **인터페이스 계층(라우터)에서 기록**한다(Clean Arch 경계 유지).
- **개인정보(Codex (c) 반영)**: 질문 원문에는 이메일·전화·주문번호·카드형 숫자가 섞일 수 있다.
  → **저장 전 마스킹**을 기본으로 한다(이메일/전화/카드형/주문번호 패턴 치환). 관리자 전용 접근 +
  **보존기간 파기 CLI**(`purge-gaps --days N`)를 제공한다.
  `run_events`의 "원문 저장 금지" 관례와 다른 이유(큐의 목적이 질문 자체)를 문서화하되,
  **마스킹된 형태**로만 남긴다. 암호화·관리자 세부권한·조회 감사로그는 §6 후속.

## 4. DoD ↔ 테스트 매핑
- **TEST-RBAC-401**: 토큰 없이 관리자 API → 401.
- **TEST-RBAC-403**: USER 토큰으로 관리자 API → 403.
- **TEST-RBAC-200**: ADMIN 토큰으로 관리자 API → 200.
- **TEST-RBAC-STALE-001**: 토큰 발급 후 DB에서 강등하면 **같은 토큰으로도 즉시 403**
  (토큰에 role을 넣지 않은 설계의 핵심 이점을 고정).
- **TEST-ADMIN-BOOTSTRAP-001**: `promote` CLI가 명시적으로만 승격, 없는 사용자는 NotFoundErr, 멱등.
- **TEST-MIGRATE-ROLE-001**: role 컬럼이 없는 기존 테이블에 migrate가 멱등으로 컬럼을 추가하고
  기존 행이 `USER`가 되는지.
- **TEST-KGAP-001**: abstention 발생 시 큐에 1건 적재, 정상 답변 시 적재 0건.
- 회귀: 기존 인증·주문 테스트 유지(기본 role USER로 동작 불변).

## 5. Codex 설계 리뷰 결과 (반영 완료)
판정 **FIX** → 전부 반영:
- (a) 토큰에서 role 제외 = **맞는 선택**(강등 즉시 반영·무폴백 부합). 단 **알 수 없는 role을
  USER로 폴백 금지** → 명시적 거부로 반영.
- (b) `ALTER TABLE ADD COLUMN`은 이 규모에선 가능하나 **사후 스키마 검증**을 갖출 것 →
  migrate 후 컬럼 존재를 검증하도록 반영. Alembic은 인스턴스가 늘거나 제약 변경이 필요해지는
  시점의 후속 과제로 명시(§6).
- (c) 질문 원문 PII 위험 → **저장 전 마스킹 + 보존기간 파기 CLI + 관리자 전용**으로 반영.
- (d) 라우터마다 수동 권한검사는 누락된다 → **라우터 전역 fail-closed + 가드레일 테스트**.
  promote/demote는 **마지막 ADMIN 강등 금지 + 감사 기록**으로 반영.

## 6. 범위 밖(YAGNI, 후속) / 정직한 한계
- **Alembic 도입**: 인스턴스가 여럿이 되거나 제약조건 변경·롤백이 필요해지면 그때가 도입 시점.
  현재는 멱등 스크립트 + 사후 스키마 검증으로 간다(한계를 리포트에 명시).
- 지식 큐의 **암호화 저장·관리자 세부권한 분리·조회 감사로그**: 인프라/정책 과제로 후속.
  이번엔 마스킹·관리자 전용·보존파기까지.
- 세분화 권한(RBAC→ABAC), 감사 로그 서명, 관리자 UI 화면(시연은 Phase 10).
- 큐 처리 워크플로(담당자 배정·해결 처리)는 조회+resolved 플래그까지만.
