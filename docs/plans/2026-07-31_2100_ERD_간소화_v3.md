## 0. 결론

**테이블 28개는 4주 부트캠프에 과하다. MVP는 21개 + 뷰 1개다.**

| 구분 | 수 | 내용 |
|---|---|---|
| **MVP 필수** | **21** | 없으면 제품이 성립하지 않거나 거짓말을 하게 되는 것 |
| **통합 가능** | 5 | 별도 테이블일 이유가 없다 — 컬럼·JSONB로 충분 |
| **P2 이후** | 6 | 필요하지만 MVP 범위(갱신형 계약·특약·구KCD)를 넘는다 |

### ★왜 이렇게 커졌나 — 자기 진단

두 번의 확장이 있었고 **둘 다 이유는 타당했지만 시점이 틀렸다.**

1. **"원칙을 구조로 강제하자"** → 제약을 걸 자리마다 테이블을 만들었다.
   그런데 **제약은 컬럼 NOT NULL로도 걸린다.** 테이블을 나눠야만 강제되는 건 FK 대상이 될 때뿐이다.
2. **코덱스 독립설계 반영** → 코덱스는 "이 도메인의 올바른 모델"을 설계했지 **"4주에 만들 것"을 설계하지 않았다.**
   나도 그 구분 없이 전부 채택했다.

## 1. 그냥 빼도 되는 것 — 별도 테이블일 이유가 없다

| 테이블 | 왜 만들었나 | 왜 뺄 수 있나 | 대체 |
|---|---|---|---|
| ★`confirmed_policy_document` | "식별 안 된 약관으로 판정 금지"를 FK로 강제 | ★**policy_version과 1:1이고 컬럼이 `source_url`·`fetched_at`·`sha256`뿐이다.** "확정 문서 없으면 버전 못 만든다" = "이 컬럼들이 NOT NULL이면 못 만든다" — **효과가 같다** | `policy_version.source_url/sha256/fetched_at` **NOT NULL** |
| `missing_document` | 4단 판정의 `needs_documents` 목록 | 조회·조인·집계할 일이 없다. 판정과 함께 읽고 끝 | `assessment.missing_documents jsonb` |
| `evidence_consistency` | 정합성 검사를 불변 사실로 | ★**FK 대상이 아니다.** 코호트가 참조하는 건 `evidence_verification`뿐이다. 분리 이득이 없다 | `evidence.consistency_checked_at` + `consistency_result jsonb` |
| `knowledge_gap` | 지식갭 승격 워크플로 | `interaction_log`와 1:1이고 라이프사이클도 같다 | `interaction_log.gap_status` + `promoted_ref` |
| `deletion_request` | 삭제 요청 추적 | `consent.revoked_at` + `subject.deleted_at`이 이미 있다 | 기존 컬럼 |

> ★**핵심 원칙**: 테이블을 나눠야만 얻는 것은 **FK를 걸 수 있다**는 것뿐이다.
> FK 대상이 아니면 컬럼으로 두는 게 맞다. `evidence_verification`이 분리되어야 하는 이유가
> 정확히 이것이다 — **코호트 기여 행이 그것을 FK로 참조**해야 하기 때문이다.

## 2. MVP 뒤로 미룰 것 — 필요하지만 지금은 아니다

| 테이블 | 언제 필요한가 | 왜 지금은 아닌가 |
|---|---|---|
| `insurer` | 보험사별 통계·크롤링 상태 관리 | 16곳 고정이고 `product.insurer_name`으로 충분. robots 판정은 이미 파일로 보관 중 |
| `rider` · `rider_holding` | 특약이 면책 판단에 들어갈 때 | **MVP는 특약 없는 단순 케이스**로 시작한다 |
| `kcd_mapping` | 구·신 KCD 차수 매핑 | MVP는 **한 차수만** 쓴다. 여러 차수를 다루기 시작할 때 |
| `policy_application` | **갱신형 계약·중도 특약변경** | 코덱스가 "가장 먼저 깨질 곳"으로 지적한 부분이 맞지만, MVP 비범위다. `policy_holding.policy_version_id` 컬럼으로 두고 **갱신 지원 시 분리**한다 |
| `assessment_evidence_citation` | 판정이 검증된 증빙을 근거로 인용할 때 | MVP 판정 근거는 **약관 조항뿐**이다 |
| `api_call_log` | 레이트리밋·남용 탐지 | MVP는 메모리 카운터로 충분. 남용 패턴 분석은 후순위 |

## 3. ★절대 빼면 안 되는 것 6개

이걸 빼면 **제품이 거짓말을 하게 된다.**

| # | 테이블/장치 | 빼면 무슨 일이 나나 |
|---|---|---|
| 1 | **DB 물리 분리**(`insurance_real` / `insurance_demo`) | 합성 데이터가 실제 통계로 새어나간다. 쿼리 한 줄 실수면 끝 |
| 2 | **`evidence_verification`** (독립 테이블) | ★코호트가 FK로 참조할 대상이 없어진다 → `consistent`가 통계에 들어간다 |
| 3 | **`assessment_clause_citation`** (FK가 조항 하나뿐) | 상호작용 로그가 판정 근거로 인용되는 길이 열린다 |
| 4 | **`cohort_stats` VIEW** (`WHERE status='verified'`) | 집계 게이트가 애플리케이션 코드로 흩어진다 |
| 5 | **`audit_log`** | 누가 무엇을 `verified`로 바꿨는지 사라진다 |
| 6 | **`kcd_code UNIQUE(version, code)`** | 차수가 다른 같은 코드가 섞여 오판이 난다 |

## 4. MVP 21개 최종 목록

### CORE (6)
`product`(insurer 흡수) · `policy_version`(확정문서 컬럼 흡수) · `policy_clause` · `clause_chunk` ·
`kcd_version` · `kcd_code`

### REAL / DEMO — 동일 DDL, 물리 분리 DB (10 + 뷰 1)
`subject` · `policy_holding` · `case` · `case_diagnosis` · `assessment` ·
`assessment_clause_citation` · `claim` · `outcome` · `evidence` · **`evidence_verification`**
\+ `cohort_stats` (VIEW)

### OPS (5)
`agent_client` · `interaction_log` · `consent` · `admin_user` · **`audit_log`**

> ★`actor_declaration_event`(호출자 자기선언)는 **MVP에 넣되 `interaction_log` 컬럼으로 시작**한다.
> 선언 채널이 여러 개(MCP `_meta`/REST 헤더/웹 폼)가 되면 그때 분리한다.

## 5. 이렇게 줄이면 잃는 것 (정직 기록)

- **`policy_version`에 컬럼 흡수** → 한 PDF에서 여러 버전이 나오는 경우를 표현할 수 없다.
  실무상 1 PDF = 1 버전이라 지금은 문제없지만, **전환용·재개용 같은 변형본이 확인되면 재분리**해야 한다.
  (삼성화재 약관 표지에 이미 `[계약전환용]`·`[전환·재개용]`·`[자녀보험전환용]` 표기가 있었다 — **경계 신호다.**)
- **`policy_application` 보류** → 갱신형 계약이 들어오면 스키마 변경이 필요하다.
  코덱스가 "가장 먼저 깨질 부분"으로 짚었으므로, **미룬 것이지 해결한 것이 아니다.**
- **`evidence_consistency` 통합** → 정합성 검사 이력이 한 벌만 남는다(재검사 이력 없음).
- 위 셋은 전부 **P2에서 되돌릴 수 있는 결정**이다. 되돌릴 수 없는 결정(§3)만 지금 지킨다.
