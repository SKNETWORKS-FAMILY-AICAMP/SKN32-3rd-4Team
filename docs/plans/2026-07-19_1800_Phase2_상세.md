# Phase 2 — RAG 품질 고정 + 관측성(trace) + 기동/데이터 분리

## 목표
RAG의 품질을 **평가셋으로 고정**하고, 요청을 **trace로 추적**하며, 앱 기동 시 자동 seed/index를
제거하고 **명시적 migration/ingest**로 분리한다(Codex가 지적한 자동설정 냄새 제거).

## 범위 · DoD
| 요소 | 산출물 | 검증(TEST) |
|---|---|---|
| RAG 평가셋 | `data/eval/rag_v1.jsonl`(30문항: answerable 20/unanswerable 5/adversarial 3/paraphrase 2), `app/eval/rag_eval.py`(hit@k·abstention·forbidden·인젝션 판정) | 결정론 채점로직 테스트 + ml마커 검색 eval(Hit@3≥0.85, abstention 5/5, 인젝션 3/3) — `TEST-RAG-EVAL-001`,`TEST-RAG-INJECT-001` |
| 관측성 trace | `app/obs/trace.py`(contextvar trace_id + 미들웨어), 응답 `X-Trace-ID` | 응답 헤더 존재·요청 헤더 전파 — `TEST-OBS-001` |
| run_events | `RunEvent` 테이블 + `record_event`, 라우터가 RAG 질의 이벤트 기록(Interface 계층) | 이벤트 기록·trace_id 상관 — `TEST-OBS-002` |
| 기동/데이터 분리 | lifespan에서 create_all/seed/index 제거, `scripts/manage.py`(migrate/seed/ingest), `/api/health/ready`(미준비 시 명시 실패) | readiness 미준비→명시 실패, 준비→ok — `TEST-OPS-READY-001` |

## 원칙
- 무폴백: readiness 미준비는 조용히 진행하지 않고 명시 상태/오류. Application(AnswerQuestion)은 순수 유지
  (trace/run_events 기록은 Interface 계층 라우터에서).
- 평가셋은 실제 corpus(환불교환정책.pdf, loop_safety/react_agent_overview/tool_design_rules.txt) 기반.
- 검색 eval은 임베딩 로드 필요 → ml마커(결정론 CI 제외). 채점 로직 자체는 Fake로 결정론 테스트.

## 주의(회귀 안전)
- 기존 테스트는 conftest가 DB 자체 셋업 + client는 lifespan 미기동 → lifespan 자동설정 제거 안전(확인함).
- run_events 테이블 추가는 create_all 대상에 포함(마이그레이션 명령으로 생성).

## 완료 후
- 리포트 + history + Codex 초점 consult(무폴백·평가채점·trace) → 합의 → Phase 3(pgvector).
