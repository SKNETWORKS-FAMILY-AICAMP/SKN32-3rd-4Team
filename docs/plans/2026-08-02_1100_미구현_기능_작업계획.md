## 1. 순서와 근거

사용자가 제안한 순서를 따른다. 이유가 타당하다.

```
① s5 검증        판정의 새 기준선인데 ok 가 132건 줄어든 이유를 모른다.
                 그 위에 뭘 지으면 v3 의 "35% 손상을 나중에 우연히 발견"이 반복된다.
② 확정 게이트     행이 0개인 지금이 가장 싸다. load_versions() 가 0을 돌려주는 게
                 정답이라, 기능이 죽는 것처럼 보이는 걸 팀이 먼저 알아야 한다.
③ observations   작다. 파일 append 하나. 지금 안 붙이면 데모 보고가 영영 사라진다.
④ headline       5분. 팀이 그걸 보고 구현하기 전에.
⑤~⑧             코호트 → 임베딩 → 용어
⑨                clause_store 통합과 ERD 조항 분리는 같은 결정이라 묶는다.
```

## 2. 항목별 상세

### ① 확정 문서 게이트 (P0)

**무엇이 문제인가** — `manifest_policy_resolver` 가 `data/raw/manifests/` 를 직접 읽고
`identification_status` 를 **보지 않는다**. 확정 문서가 0건인데 `load_versions()` 가
**1,361건을 내준다**.

```
실측: grep 'identification' app/adapters/manifest_policy_resolver.py → 0건
```

ERD 는 `policy_version.confirmed_document_id` 를 **NOT NULL FK** 로 두어
"확인 안 된 약관으로 판정하지 않는다"를 **구조로** 만들었다.
판정 코드가 그 절차를 우회하고 있다.
