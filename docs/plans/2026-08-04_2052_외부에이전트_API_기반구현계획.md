# 외부 에이전트 API 기반 구현 계획

- 작성: 2026-08-04 20:52 KST
- 근거 계약: `docs/handoff/03_에이전트_데이터_축적_설계.md` §6~§7
- 목표: 기존 고객 UI와 합성 트랙을 깨지 않고, 실제 외부 에이전트가 인증된 REST API로
  판정·통계 조회·결과 제출을 할 수 있는 최소 운영 기반을 구현한다.

## 범위

### 이번에 구현

- 에이전트 전용 보호 경로 `/v1/agent/*`
- 클라이언트별 API key 해시 저장과 scope 검사
- PostgreSQL 기반 원자적 분당 rate limit
- 요청 원문의 의료정보를 남기지 않는 해시 기반 감사 이벤트
- 쓰기 요청의 `Idempotency-Key` 필수 계약
- API key 발급·폐기 CLI
- 고객 서버 host/port 설정화(안전 기본값 `127.0.0.1` 유지)
- OpenAPI·`llms.txt` 안내와 회귀 테스트

### 이번에 하지 않음

- 실제 인터넷 배포, DNS, TLS 인증서, reverse proxy 설정
- OAuth 2.1, 원격 MCP, A2A Agent Card, webhook
- 사용자 계정·대화 전문·장기 세션 저장
- 외부 사례의 자동 진위승격 또는 약관 판정 근거 사용
- 기존 공개 고객 UI API 제거·인증 강제

## 구현 결정

1. 기존 고객 UI가 사용하는 `/v1/prechecks`, `/v1/observations`, `/v1/cohorts`는 유지한다.
2. 실제 에이전트는 `/v1/agent/prechecks`, `/v1/agent/observations`,
   `/v1/agent/cohorts`만 사용한다.
3. 에이전트 식별자는 body의 `client_ref`를 믿지 않고 인증된 key의 client id로 덮어쓴다.
4. API key 원문은 발급 시 한 번만 표시하고 DB에는 SHA-256 해시만 저장한다.
5. agent 운영 스키마는 약관 색인·합성 DB와 분리한 `insurance_agent` DB에 둔다.
6. agent DB가 준비되지 않았을 때 파일·무인증 경로로 폴백하지 않고 503으로 실패한다.
7. 감사 로그에는 KCD·가입일·질문 원문을 쓰지 않고 canonical request/response hash와
   판정 메타데이터만 남긴다.

## 완료 기준

- 유효한 key와 scope 없이는 `/v1/agent/*`가 성공하지 않는다.
- 같은 key·같은 idempotency key·같은 payload 재시도는 한 건만 저장된다.
- 같은 idempotency key로 다른 payload를 보내면 409로 실패한다.
- rate limit은 다중 프로세스에서도 DB 기준으로 원자적으로 적용된다.
- 감사 로그와 agent stream에 원문 KCD·가입일이 남지 않는다.
- 기존 고객 UI와 `/v1/demo/*` 동작은 바뀌지 않는다.
