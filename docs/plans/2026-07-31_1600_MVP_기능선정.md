## 0. 먼저 — 4주 뒤 결과물의 **정직한 이름**

> **"보장 사전검토 MVP + 실제 코호트 수집이 가능하도록 준비된 합성 데모"**

**"검증된 실제 청구사례 통계 제품"이 아니다.** 실제 지급·부지급 결과는 케이스 단위 공개 데이터가
**존재하지 않는다**(취득계획 §0). 4주 안에 실제 표본이 쌓일 경로가 없다.

이 이름을 먼저 못박는 이유: 발표에서 "실제 승인률"이라고 말하는 순간 제품 주장이 무너진다.
**MVP가 증명해야 할 것은 통계값이 아니라, 실제 사례가 들어오면 통계가 정직하게 갱신되는 구조다.**

## 1. ★DoD를 두 개로 분리한다

혼동의 근원은 "필수"라는 말이 두 가지를 뜻한다는 것이다.

| | 뜻 | 내용 |
|---|---|---|
| **제품 MVP DoD** | 이게 되면 **제품이라 부를 수 있다** | §2 (8개) |
| **졸업 릴리스 DoD** | 제품 코어는 아니지만 **뺄 수 없는 과목 요건** | §3 |

**둘 다 4주 안에 끝내야 하지만, 섞으면 안 된다.** 섞으면 얼굴인식 디버깅하다가
수직 슬라이스가 미뤄지는 전형적 실패가 난다.

## 2. 제품 MVP — 8개

| # | 기능 | 담당 | 왜 이게 최소인가 |
|---|---|---|---|
| 1 | **지원범위 매니페스트** | ① | 지원 상품·약관버전을 **데이터로 선언**. 범위 밖은 추정하지 않고 `ValidationErr` 또는 "전문가 검토 필요"로 끝낸다. 이게 없으면 모르는 걸 아는 척하게 된다 |
| 2 | **합성/실제 물리 분리 + 혼합 차단 테스트** | ③ | 저장·권한·집계뷰·API(`/v1/cohorts` ↔ `/v1/demo/cohorts`)를 분리. ★**이게 없으면 통계를 화면에 띄울 자격이 없다** |
| 3 | **증빙 상태 전이** `submitted→consistent→verified/rejected` | ① | 수직 슬라이스의 심장. ★**`consistent`만으로는 집계가 안 바뀌는 테스트**가 이 항목의 완료 기준 |
| 4 | **적용 약관 버전 확정** | ①+② | 가입일·사고일·상품·특약으로 결정. **현행 약관을 구계약에 조용히 대입하면 그건 폴백이고 오답의 직접 원인** |
| 5 | **결정적 규칙엔진 → 4단 판정** | ① | 날짜·면책기간·특약·한도는 **코드로 계산**. LLM에 맡기지 않는다. `missing_documents` 동반 |
| 6 | **약관 근거 검색** | ② | 조항 + **면책조건을 함께** 반환, locator 제공, 근거 부족하면 abstain. 원문 재배포 안 함 |
| 7 | **정직한 코호트 API** | ③ | `n`·분포·수집경로·최소표본 게이트·편향 경고 동반. **실제 경로는 `n=0` → 비공개**, 데모 경로만 합성 표시 |
| 8 | **근거 사슬 화면 1개** | ⑤ | §5의 흐름이 **한 화면에서** 이어져야 한다. 이 화면 하나가 제품 설명서다 |

**기능이 아니라 전제(모든 항목에 적용)**
- 타입 오류 계약 — `ConfigError`/`InfraError`/`ValidationErr`를 API까지 전파. 폴백·예외 삼키기 금지
- **골든 케이스 6개**(①작성·③합격판정): 면책 누락 / 구약관 혼합 / `consistent` 집계 시도 /
  근거 없음 / 소표본 / 합성·실제 혼합 → **CI에서 차단**. 정상 케이스만 있는 테스트는 의미가 없다

## 3. 졸업 릴리스 필수 — 코어는 아니지만 뺄 수 없다

**제품 MVP 코어에 넣지 않는다. 대신 후순위로도 미루지 않는다.** 별도 트랙(⑤)에서 병렬로 간다.

| 기능 | 연결 방식 | 저장 정책 |
|---|---|---|
| 음성 | 텍스트 상담 API의 **입출력 어댑터** | 녹음 원본 미보존 |
| 화상 | 상담 세션 표현 어댑터 | 영상 미보존 |
| 얼굴 2FA | 민감자료 접근 게이트. 실패 시 **명시적 대체 인증** | 얼굴 원본 미보존 |
| 관리자 보고서 | 기존 검수·집계 결과의 **읽기 전용** 출력 | 개인 원문 제외 |
| 최소 개인정보 통제 | 동의·최소수집·RBAC·감사로그·보존기간·삭제 경로 | 처방전 원본 미보존 |

★**기능별 시간 상한을 미리 정하고, 넘으면 범위를 줄인다.** 이 트랙은 스택이 5종이라
"조금만 더 하면 될 것 같다"로 4주가 사라지는 자리다.

## 4. 후순위 / 하지 않음

### 후순위 (MVP 이후)
실제 코호트 모집·공개 · 보험사/상품/세대 확대 · 자동 약관 수집 확대(S7) · `Ambiguous` 검수도구 고도화 ·
**MCP 전체 도구셋 parity** · 층화·교란변수 보정 · 분쟁사례 대규모 구조화 · 기여 보상·포인트 ·
다중 RAG 백엔드 비교·파인튜닝 · 음성/화상 UX 고도화

> "시간 남으면"이 아니라 **"MVP가 증명된 뒤에 의미가 생기는 것"** 들이다.
> 특히 **실제 코호트 모집**은 제품의 장기 핵심이지만, 동의·검증·삭제 체계가 먼저다.

### 하지 않음 (명시적 비범위)
보험금 지급 확정·자동 지급 결정 · **개인 예상 지급액 제시**(손해사정 유사행위 소지 — 과거 분포만 표시) ·
완전 자동 청구 · 보험상품 권유·판매 · 의료 진단 · **현행 약관으로 과거 약관 대체** ·
권리 미확인 원문 재배포 · CAPTCHA·robots 우회 · **합성·실제 UNION** ·
**정합성 통과를 "검증"으로 표현** · 실제 의료자료의 모델 학습 이용

## 5. ★데모 — 단 하나의 화면

**"근거 사슬이 보이는 사전검토 결과 화면"**

```
[합성 처방전 → KCD 추출·신뢰도 표시 → 사용자 교정·승인]
        ↓
[가입일·사고일 → 적용 약관 버전 확정]          ← "왜 이 약관인가"가 보인다
        ↓
[관련 조항 + 면책조항 + locator]               ← 유리한 조항만 보여주지 않는다
        ↓
[4단 판정 + 부족 서류]                          ← 이진 판정 안 한다
        ↓
[코호트: DEMO/SYNTHETIC · n · 분포 · 편향 경고 · 수집경로]
        ↓
[consistent 제출 → n 그대로 / verified 처리 → n+1]   ← 이 순간이 제품의 증명
```

- 실제 코호트 영역은 **`n=0 · 미공개`** 로 정직하게 비워둔다.
- 합성 영역은 **화면 최상단부터 `DEMO/SYNTHETIC` 고정 표시**.
- 마지막 두 줄이 핵심이다. **"정합성만으론 통계가 안 움직이고, 검증돼야 움직인다"**를
  관객이 눈으로 본다. 이게 우리가 파는 것이다.

## 6. MCP를 후순위로 미루는 것에 대한 이견

Codex는 "MVP는 REST/OpenAPI로 충분, MCP·A2A는 후순위"라고 했다. **절반만 맞다.**

전체 도구셋 parity는 후순위가 맞다. 그러나 **"AI 에이전트가 화면 없이 직접 쓴다"는 것이
이 프로젝트의 포지셔닝 전체**이고, 그 주장의 **유일한 증거가 에이전트 경로**다.
증거 없는 포지셔닝은 발표에서 그냥 말이 된다.

**절충**: MVP에 **OpenAPI + `llms.txt` + MCP 도구 3종**(사전검토 · 코호트조회 · 증빙제출)만 넣는다.
데모 루프를 정확히 덮는 최소 집합이고, MCP는 REST 위의 얇은 래퍼라 비용이 작다.
10종 parity·A2A 위임은 후순위.

## 7. 흔한 실수 3가지 (Codex, 전면 수용)

1. **데모를 위해 하드코딩하거나 조용히 대체한다** — 약관 미확보 시 현행판 사용, OCR 실패 시 고정 KCD,
   검색 실패 시 샘플 답변. 전부 금지. **못 하면 명시적으로 실패한다.**
2. **정합성·사실성·출처를 섞는다** — `consistent=verified`, 합성=실제, 분쟁사례=지급결과,
   소표본 비율=승인률. 이 중 하나만 해도 제품 주장이 무너진다.
3. **크롤링·RAG·음성·화상부터 만들고 수직 슬라이스를 미룬다** — 첫 통합 대상은
   **증빙 1건이 검수되어 집계를 바꾸는 흐름**이어야 한다.

## 8. 한계 (정직 기록)

- **4주는 가정이다.** 실제 마감을 받으면 §2를 다시 줄여야 할 수 있다. 줄인다면 순서는
  ⑧화면 축소 → ⑥검색 범위 축소 → ①매니페스트 항목 축소이며, **②③은 줄이지 않는다**(정직성 장치).
- 이 문서는 **착수 전 선정**이며 구현 실적이 아니다.
- Codex 원안의 "MVP 필수 13개"를 8개로 줄였다. 줄인 항목(개인정보 통제·과목기능·평가셋)은
  **버린 게 아니라 §3과 §2 전제로 옮겼다.** 다만 **총 작업량은 줄지 않았다** — 분류만 정직해졌다.
