# Phase 1 — RAG 질문 수직 슬라이스 + 포트 + 모델 레지스트리

## 1. 목표
기존 `rag/qa.py`(FAISS+프롬프트+LLM 혼합)를 **개념적 Clean Architecture 경계 뒤로** 첫 수직 슬라이스로 이동한다.
이것이 이후 pgvector/Hybrid/GraphRAG 어댑터를 **같은 포트로 교체·비교**하는 토대다(v3.2 ADR-005').

## 2. 범위(이 Phase만)
- **신규 Application 계층**: `RetrieverPort`·`ModelGateway`(포트), `AnswerQuestion`(유스케이스), `Evidence`(DTO).
- **신규 Adapter**: `FaissRetriever`(기존 `rag/service.search` 래핑+점수 정규화), `LlmGateway`(기존 `llm_clients` 래핑).
- **모델 레지스트리**: `model_registry.yaml` + `core/model_registry.py`(스키마 검증 로더).
- **라우터 전환**: `/api/rag/qa`가 `AnswerQuestion`을 호출.
- **테스트 페이크**: `tests/fakes/`(FakeModelGateway, FakeRetriever).
- **범위 밖**: pgvector·Hybrid·GraphRAG·CoT(후속 Phase). 기존 `rag/qa.py`는 **legacy 경로로 유지**(MCP는 아직 사용;
  Phase 8에서 수렴). 두 경로 공존은 이 Phase 한정 strangler로 허용하고 리포트에 명시.

## 3. 설계

### 3.1 포트·DTO (`app/application/ports.py`)
```python
@dataclass(frozen=True)
class Evidence:
    content: str
    source: str            # 원천 문서 식별자
    locator: str | None    # page 등
    score: float           # 정규화 [0,1], 1=가장 관련(백엔드 중립)
    backend: str           # "faiss" | "pgvector" | ...

class RetrieverPort(Protocol):
    def search(self, query: str, k: int | None = None,
               source: str | None = None) -> list[Evidence]: ...

class ModelGateway(Protocol):
    def complete(self, prompt: str, *, max_tokens: int | None = None,
                 temperature: float = 0.0) -> str: ...
```
- 점수 정규화: FAISS 거리 d(정규화 임베딩·L2²=[0,4]) → `score = 1 - d/4`(단조 감소, [0,1]). 어댑터 책임.
- 포트는 백엔드 전용 필드(원거리값 등)를 노출하지 않는다.

### 3.2 유스케이스 (`app/application/answer_question.py`)
```python
class AnswerQuestion:
    def __init__(self, retriever: RetrieverPort, model: ModelGateway,
                 top_k: int | None = None): ...
    def __call__(self, question: str) -> AnswerResult:
        # 빈 질문 → ValidationErr
        # retriever.search → 근거 없음 → abstention(NO_ANSWER, sources=[])
        # 근거 있음 → 프롬프트(EVIDENCE) → model.complete → 답변 + sources(Evidence→citation)
```
- 무폴백: 빈 입력 ValidationErr, LLM/검색 인프라 실패는 전파. 근거 없으면 생성 안 함(abstention).
- **Application 계층은 FastAPI/LangChain/SQLAlchemy/openai SDK를 import하지 않는다**(TEST-ARCH-001).

### 3.3 어댑터
- `app/adapters/faiss_retriever.py`: `RetrieverPort` 구현. 내부에서 기존 `app.rag.service.search` 호출 후
  결과를 `Evidence`로 매핑+점수 정규화. (기존 거리임계·source필터 테스트는 그대로 회귀.)
- `app/adapters/llm_gateway.py`: `ModelGateway` 구현. 내부에서 기존 `app.core.llm_clients` 사용.
  모델 ID는 소스가 아니라 **레지스트리에서** 해석(REQ-LLM-REG-01).

### 3.4 모델 레지스트리
- `model_registry.yaml`: 프로필 목록. 필수 필드(v3.1 §4): profile_id, provider, provider_model_id, revision,
  artifact_sha256, runtime, quantization, verified_at, supported_tasks, max_tested_context, memory_peak_mb, tool_call_verified.
  초기 프로필: `local_qwen35_4b`(검증됨), `local_gemma4_e4b`(평문 MAY), cloud는 키 있을 때만. **fake는 레지스트리에 없음**(런타임 선택 불가).
- `app/core/model_registry.py`: YAML 로드 + Pydantic 스키마 검증. `latest` alias·미확인 checksum·family-only pin 거부.
- 비밀은 `.env`(레지스트리엔 비밀 없음).

### 3.5 라우터
- `app/routers/rag.py`의 `/api/rag/qa`가 `AnswerQuestion`(FaissRetriever+LlmGateway 조립)을 호출.
  조립은 composition root(예: `app/composition.py` 또는 의존성 함수)에서.

### 3.6 페이크 (`tests/fakes/`)
- `FakeRetriever(evidence_list)`: 고정 Evidence 반환(빈 리스트=무근거).
- `FakeModelGateway(reply | raises)`: 고정 답변 또는 예외.
- 런타임 설정에서 선택 불가(테스트 전용).

## 5. 리스크·주의
- 점수 정규화 공식은 기존 거리임계 필터와 **의미가 일치**해야(무관 결과 여전히 제외). 회귀로 검증.
- `rag/qa.py` legacy 공존은 이 Phase 한정. Phase 8에서 MCP·라우터를 하나의 유스케이스로 수렴.
- TEST-LLM-REG-002의 "하드코딩 모델ID 스캔"은 `app/` 소스에서 알려진 모델ID 문자열 패턴을 검출(레지스트리·테스트·주석 제외).

## 6. 완료 후
- 리포트 + history + Codex 구현 점검(web 없이) → 합의 → Phase 2.
