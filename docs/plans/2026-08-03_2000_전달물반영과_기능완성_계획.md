## 1. 전달물 — 무엇인가

`_3rd_project_4/ai-1/s6_chunks_delivery.zip` (326MB)

```
s6_chunks_arctic-ko.jsonl      234MB   조각 본문 (content_hash · seq · n_chunks · text)
s6_chunks_arctic-ko_vectors.npz 277MB  벡터
s6_chunks_arctic-ko.meta.json     474B  설정
```

```json
{ "model": "dragonkue/snowflake-arctic-embed-l-v2.0-ko",
  "dtype": "float16", "dim": 1024, "normalized": true,
  "doc_prefix": "", "query_prefix": "query: ",
  "chunk_budget": 448, "overlap": 80,
  "clauses": 59951, "chunks": 145220,
  "source": "s6 shadow-s6_pymupdf-1.28.0 · clauses.jsonl has_eligible=true",
  "gpu": "NVIDIA GeForce RTX 4090", "built_at": "2026-08-03" }
```

### ★"우리 조건과 같다"는 **틀렸다** (코덱스 조사 2026-08-03)

숫자는 같지만 **자르는 방법이 다르다.** 나는 메타의 숫자만 보고 같다고 적었다.

| | 모델팀 (`embed_s6_chunks.py`) | 우리 (`pgvector_clause_index.chunk_clause`) |
|---|---|---|
| 기준 | 토크나이저 offset **고정 창**(stride 368) | **문장·문단 경계** 우선 |
| 특수토큰 | `add_special_tokens=False` | `True` |
| 겹침 | 정확히 80토큰 | 문장 단위로 **최대** 80 |

→ **나오는 조각이 다르다.** 벡터 자체는 진짜지만 **경계가 우리와 다르게 잘렸다.**

### ★차원이 안 맞는다 — 적재 자체가 막힌다

```
arctic-ko · 전달물        1024차원
pgvector_clause_index    vector(768) 고정
```

`_EMBED_DIM = 768` 을 1024 로 올리고 **테이블을 다시 만들어야** 한다.

### 아래 표는 **숫자만** 같다는 뜻이다

| 항목 | 전달물 | 우리 |
|---|---|---|
| 모델 | `dragonkue/snowflake-arctic-embed-l-v2.0-ko` | 브리핑 §3-3 **잠정 1순위** |
| 질의 접두어 | `query: ` | `query: ` (브리핑 §5-1) |
| 문서 접두어 | 없음 | 없음 |
| 청크 예산 · 겹침 | 448 · 80 | `MAX_TOKENS=448` · `OVERLAP_TOKENS=80` |
| 정규화 | `true` | `normalize_embeddings=True` |

> ★그래서 **"우리 arctic-ko 와 비교"는 성립하지 않는다.**
> 우리는 arctic-ko 로 **색인을 만든 적이 없다.** 벤치마크만 했다.
> 비교할 수 있는 것은 **"전달물이 정말 그 설정으로 만들어졌는가"** 였고,
> 그건 **통과했다**(코사인 최소 0.999995).

세 가지가 막는다.

1. **스냅샷이 다르다** — 판정대상의 12.2%에 벡터가 없다.

3. **차원이 안 맞는다** — 768 → 1024 스키마 변경이 선행돼야 한다.

**→ 우리 s6 로 다시 임베딩한다**(같은 모델·같은 접두어, **우리 청킹 함수 그대로**).
