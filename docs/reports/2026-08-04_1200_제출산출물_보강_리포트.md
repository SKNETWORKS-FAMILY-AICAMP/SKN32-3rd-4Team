## 4. ★발견한 것 — 제출을 막을 뻔한 문제 3건

### 4-1. 커머스 화면을 제출물이 링크하고 있었다

`docs/screen_walkthrough.html` 은 이 저장소가 쇼핑몰 실습(`_unified_mall`)이던 시절 산출물이다.

```
04_orders_preview.png  05_orders_approve_idempotent.png  08_orders_reject_oversell_and_list.png
15_shop_cart.png       16_mypage_face_login.png          17_video_consult.png   18_facebench.png
```

그런데 `05:161` 과 `06:108` 이 이걸 **"전체 앱 18장 워크스루"** 로 링크해 뒀다.
**심사자가 열면 쇼핑몰이 나온다.**

→ 링크를 전부 뗐고, `scripts/verify/check_submission_links.py` 의 금지 목록에 넣어
**다시 들어오면 CI 가 실패**하게 했다. 파일 자체는 이력이라 남긴다.

### 4-2. 기본 CI 가 1건 실패하고 있었다

`04_테스트_계획_및_결과.md` 는 *"제출 직전 별도로 실행해 기록해야 한다"* 고만 적혀 있었다.
**실제로 돌려 보니** `tests/test_terms_api.py::test_실제_색인이_있으면_동작한다` 가 실패했다.

원인은 제품 결함이 아니라 **테스트 격리 결함**이었다 —
`test_s7_chatbot_release.py` 가 `file_glossary_source._cache`(모듈 전역)를 되돌리지 않아
뒤에 도는 테스트가 실제 색인(구절 2,739개) 대신 tmp 픽스처의 **가짜 1행**을 봤다.

★**단독 실행은 통과하고 전량 실행에서만 깨진다.** 파일 단위로만 돌리면 영원히 안 잡힌다.

### 4-3. 「850」이 두 뜻으로 쓰이고 있었다

| | 무엇 | 어디 |
|---|---|---|
| 확정 문서 **850건** | 이 PDF 가 무슨 약관인지 확정한 문서 수 (1,367의 62.2%) | `config/confirmed_documents.jsonl` 850행 |
| 승인 OCR facts **850건** | 사람이 원문 검수해 승인한 표 사실 수 (24패턴) | S7.1 `approved_facts.jsonl` |

**둘 다 실재하는 별개 수치인데 우연히 같다.** 문서에서 구분 표기가 약했다.
`00`·`05` 에 경고 블록을 넣고 발표에서 **단위를 붙여 말하도록** 명시했다.
