## 2. 문제 — 코드가 팀 결정과 자기 주석을 둘 다 어기고 있었다

`팀MVP6 §2-2` 의 결정:

> **40건으로 비율을 내면 안 된다.** 33/40 = 82.5%로 보이지만 표본 40건의 95% 신뢰구간은
> 대략 ±12%p다. "82.5%"라고 단정하면 거짓이다. 화면 문구는
> **"우리가 검증한 40건 중 33건 승인"** 이어야 한다.

그런데 `DEFAULT_MIN_SAMPLE = 30` 이라 **n=40 은 게이트를 통과**하고, 통과하면 이렇게 나왔다:

```
검증된 40건 중 33건 승인 · 7건 부지급 (82.5%)
                                     ↑ 팀이 쓰지 말자고 정한 바로 그 문자열
```

`_headline()` 의 도크스트링은 *"건수로 말한다"* 였다. **코드가 자기 주석과도 어긋났다.**

★핵심은 이것이다 — **최소표본 게이트만으로는 단정을 막지 못한다.**
게이트는 "언제부터 말해도 되나"만 정하고, **"어떻게 말할 것인가"를 정하지 않는다.**
그래서 넘는 순간 다시 점추정을 단정하게 된다.

---

## 3. 고친 방식 — 방어를 두 겹으로

| 층 | 내용 | 강제력 |
|---|---|---|
| ① 최소표본 게이트 | 미달이면 **비율 자체를 내지 않는다**(기존) | `ValidationErr` |
| ② **구간으로 말한다** | 게이트를 넘겨도 **점추정 대신 95% 신뢰구간**(신규) | `_headline()` |
| ③ **짝 강제** | `approval_rate` 와 `approval_ci` 는 **둘 다 있거나 둘 다 없다**(신규) | `__post_init__` |

③이 있어야 나중에 누가 `approval_ci` 를 빼먹고 점추정만 내보내는 일이 생기지 않는다.
**규칙이 아니라 구조다.**

### 왜 Wilson score interval 인가

정규근사 `p ± z·√(p(1-p)/n)` 는 n 이 작거나 p 가 0·1 에 가까우면
구간이 `[0,1]` 을 벗어나고 실제 포함확률이 95% 에 못 미친다.
**우리 표본은 수십 건 규모라 정확히 그 영역이다.**

부수로 드러난 것 — 33/40 의 실제 구간은 `(0.6805, 0.9125)` 로
관측값 0.825 기준 **-14.5%p / +8.8%p 비대칭**이다.
팀 문서의 **"±12%p"라는 대칭 표현 자체가 정규근사의 흔적**이었다.

## 5. 검증

### 실제 출력 (전부 실행 결과 원문)

```
n=  40 approved=  33 | rate=0.825 ci=(0.6805, 0.9125)
   검증된 40건 중 33건 승인 · 7건 부지급 (승인 비율 68%~91%, 95% 신뢰구간)
n=  29 approved=  24 | rate=None  ci=None
   검증된 29건 중 24건 승인 · 5건 부지급 (표본이 적어 비율은 표시하지 않습니다)
n=   0 approved=   0 | rate=None  ci=None
   검증된 사례가 없습니다
n= 400 approved= 330 | rate=0.825 ci=(0.7847, 0.8591)
   검증된 400건 중 330건 승인 · 70건 부지급 (승인 비율 78%~86%, 95% 신뢰구간)
n=  30 approved=  30 | rate=1.0   ci=(0.8865, 1.0)
   검증된 30건 중 30건 승인 · 0건 부지급 (승인 비율 89%~100%, 95% 신뢰구간)
```

★마지막 두 줄이 이 변경의 값어치다.

- **n=400 과 n=40 의 관측값은 똑같이 82.5%인데 구간이 다르다**(78~86% vs 68~91%).
  표본 크기가 **경고 문구가 아니라 숫자 자체로** 드러난다.
- **30건 전부 승인이어도 "100%"라고 하지 않는다** — "89%~100%"다.
  완벽한 표본도 확신을 주지 않는다는 것을 숫자가 말한다.

## 6. 남은 것

1. **임계값 30 은 여전히 잠정치다.** 구간을 도입해 "단정" 문제는 풀렸지만,
   *"몇 건부터 보여줄 것인가"* 는 실제 데이터를 보기 전에는 정할 수 없다(코드 주석 그대로).
2. **`/v1/cohorts` API 스키마에 `approval_ci` 반영 필요.** 지금은 유스케이스까지만 있고
   라우터·응답 스키마가 아직 없다.
3. **용어** — 우리 "코호트"는 종단 추적이 아니라 단면 집계이고 단위가 사람이 아니라 청구 사건이다.
   내부 식별자(`cohort_stats` · `/v1/cohorts`)는 유지하되
   **사용자·발표 문구에서는 "비슷한 사례"** 로 쓴다. 스토리보드 ⑧ 화면 문구는 이미 그렇다.
4. 커머스 제거 완료 후 전체 회귀 재실행.
