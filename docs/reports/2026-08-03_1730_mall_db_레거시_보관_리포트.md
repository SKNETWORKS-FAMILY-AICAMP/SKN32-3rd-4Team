# `mall.db` 레거시 보관 리포트

- 작업 시각: 2026-08-03 17:30 KST
- 작업 목적: 사용하지 않는 `data/mall.db`를 현행 경로에서 제거하되 문제 발생 시 원래 위치로 복구할 수 있게 압축 보관

## 수행 내용

1. 원본 `data/mall.db`의 크기와 상태를 확인했다.
2. 파일을 점유하던 로컬 Uvicorn 개발 서버(PID `10752`, 명령 `python -m uvicorn app.main:app --port 8099 --app-dir _unified_mall_3`)를 종료했다.
3. 원래 저장소 상대 경로를 유지해 `legacy/v8_mall_db.zip`에 `data/mall.db`를 저장했다.
4. 원본과 ZIP 엔트리의 크기 및 SHA-256이 같은지 검증한 뒤 원본을 제거했다.
5. 애플리케이션 코드와 `DATABASE_URL` 기본값은 변경하지 않았다.

## 복원 방법

현재 앱 또는 테스트가 `data/mall.db`를 사용 중이면 먼저 종료한다. 저장소 루트에서 다음 명령을 실행한다.

```powershell
Expand-Archive -LiteralPath legacy\v8_mall_db.zip -DestinationPath . -Force
```

복원 후 확인:

```powershell
Get-Item -LiteralPath data\mall.db
Get-FileHash -Algorithm SHA256 -LiteralPath data\mall.db
```

예상 해시는 `E3B0C44298FC1C149AFBF4C8996FB92427AE41E4649B934CA495991B7852B855`다.

## 주의사항과 후속 결정

- `app/core/config.py`의 기본 `DATABASE_URL`과 `.env.example`은 여전히 `data/mall.db`를 가리킨다.
- 따라서 앱이 기본 SQLite 설정으로 다시 실행되거나 DB 연결을 수행하면 `data/mall.db`가 새로 생성될 수 있다.
- 파일의 영구 폐기가 확정되면 후속 작업에서 기본 DB 경로, `.env.example`, `.gitignore`, 데이터 매니페스트를 함께 정리해야 한다.
- 이번 작업에서는 향후 DB 명칭과 위치가 아직 확정되지 않았으므로 설정 변경까지 확대하지 않았다.
