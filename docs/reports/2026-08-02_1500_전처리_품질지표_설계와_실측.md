# 전처리 구조화 품질을 정직하게 재는 지표 — 설계와 실측

2026-08-02 15:00 · 웹 조사(2026년 기준) + 코덱스 교차검증

## 0. 왜 필요했나

두 파이프라인이 같은 이름의 "커버리지"를 쓰는데 **재는 대상이 다르다.**

| | 무엇을 재나 | 값 |
|---|---|---|
| `_3rd_project_4` `coverage_pct` | 첫 재매칭 헤더 이후 정제텍스트의 **내부 재수록률** | 중앙 100.0% |
| 우리 v5 (내가 "커버리지"라 부른 것) | PDF 페이지 중 **목차로 안 뺀 비율** | 97.1% |

**둘 다 "제대로 나눴나"를 못 잰다.**
3rd 는 구조가 망가져도 100%가 나오고(§3 반례), 우리 것은 목차를 덜 뺄수록 올라간다.

## 1. 2026년 기준 연구가 어디까지 와 있나

| 출처 | 쓸 것 |
|---|---|
| [OmniDocBench](https://github.com/opendatalab/OmniDocBench) (CVPR'25 · v1.6 2026-04) | 레이아웃=검출지표, 읽기순서=edit distance. ★**MGAM** — 정답은 고정하고 **예측 쪽 granularity 만 맞춘다** |
| [HiCoBERT](https://www.nature.com/articles/s41598-026-45259-w) (2026) | 계층적 법률 문서 분할에 **Boundary F1 / Span F1** |
| [DOCR-Inspector](https://arxiv.org/html/2512.10619) | 정답 없이 **오류 유형별로 센다**(단일 점수 대신 good/bad + 유형) |
| [청킹 전략 평가](https://arxiv.org/html/2607.01852v1) (2026) | ★**경계 정확도를 독립적으로 재지 않는다.** 검색 성능으로만 잰다 |
| [CoFE-RAG](https://arxiv.org/abs/2410.12248) | golden chunk 없이 다중 granularity 키워드로 대체 |

**결론: 전처리 단독 품질 지표는 표준이 없다.** 우리가 정의해야 한다.
다만 MGAM 의 발상은 그대로 쓴다 — **단위가 다른 두 산출물을 문자 집합으로 환원**해 비교한다.
(v5 는 조 단위, 3rd 는 항 단위 1,500자라 그대로는 비교 자체가 성립하지 않는다.)

## 2. 설계 — 무참조 3축

정답셋 없이 오늘 계산되고, **양쪽에 똑같이 적용**된다.

### T. 원문 보존 (`coverage_pct` 를 대체하는 정직한 버전)

원문(페이지 JSON)과 산출물을 각각 **공백 제거 후 문자 8-gram 집합**으로 만든다.

```
T1 재현율  = |원문 ∩ 산출물| / |원문|     ← 본문 소실을 잡는다
T2 정밀도  = |원문 ∩ 산출물| / |산출물|   ← 겹침·헤더 접두 인플레를 잡는다
```

★페이지가 아니라 **문자**로 잰다. 빈 페이지와 면책 조항 페이지를 같은 1쪽으로 세지 않는다.
★중복은 1회만 센다. 같은 조항을 여러 번 담아도 재현율이 오르지 않는다.

### B. 경계 건전성

| | 내용 |
|---|---|
| B1 | 조항/청크가 **문장 종결 없이** 끝나는 비율 |
| B2 | 인접 조 번호가 **리셋이 아닌데 역행**하는 비율 |
| B3 | 초대형(>30,000자) · 초미세(<50자) 비율 |

### C. 인용 건전성

| | 내용 |
|---|---|
| C1 | 같은 인용 문자열이 **한 문서에서 여러 곳**을 가리키는 비율 |
| C3 | 조 번호 100 이상인데 **법령으로 표시되지 않은** 비율 |

## 3. 실측 — 같은 PDF, 무작위 80문서

3rd 코드를 우리 PDF 589건에 재실행(`out3rd/`)한 뒤 같은 문서로 비교했다. 중앙값이다.

| 지표 | **v5** | 3rd | 판정 |
|---|---:|---:|---|
| **T1 원문 재현율** | **0.835** | 0.726 | v5 +11%p |
| **T2 정밀도** | **1.000** | 0.978 | 3rd 는 2.2%가 원문에 없는 문자(겹침·헤더 접두) |
| B1 문장중간 절단 | 0.381 | 0.379 | **둘 다 38% — 차이 없음** |
| B2 번호 역행 | **0.000** | 0.008 | |
| B3 초미세(<50자) | **0.011** | 0.125 | 3rd 12.5%가 조각 |
| **C1 인용 중복** | **0.035** | **0.541** | 3rd 는 **54%**가 같은 인용을 가리킨다 |
| C3 법령 미분리 | 0.000 | 0.000 | ★아래 주의 |

### ★T1 이 진짜 커버리지다 — 우리도 83.5%지 97.1%가 아니다

페이지 기준 97.1%는 **너무 후한 값**이었다. 문자 기준으로는 **원문의 16.5%가 조항에 안 들어간다**
(목차 2.9% + 첫 조 이전 머리말 + 조항 사이 빈틈). 이게 정직한 숫자다.

### ★C3 = 0 은 지표가 속인 것이다

3rd 도 0 이 나왔는데 **잘 처리해서가 아니다.** `_filter_sequence` 가 조 번호 150 초과 또는
직전 대비 +15 초과 점프를 **인용 오탐으로 보고 버린다.** 그래서 상법 제651조 같은 헤더가
아예 안 생기고, **그 법령 본문은 앞 조항에 흡수된다.**
코덱스가 찾은 `제27조(준용규정) 제2항 제7호` 안의 질병분류표가 정확히 그 결과다.

→ **지표만 보면 반대로 읽힌다.** C3 는 "법령을 분리했나"가 아니라
   "법령 헤더를 만들었나"를 재도록 고쳐야 한다.

### ★B1 38%는 지표의 한계다

둘 다 38%인데, 이건 두 파이프라인이 똑같이 나쁜 게 아니라 **내 판정식이 거칠기 때문**이다.
한국어 종결(`~다` `~음` `~함` + 마침표)만 보는데, 조항이 **표·목록으로 끝나는 경우가 많다.**
이 지표는 지금 상태로는 쓸 수 없다. 문장 분할기를 붙이거나 표 구간을 빼야 한다.

## 4. 최소 정답셋 설계 (다음 단계)

무참조 지표로는 **"경계가 옳은가"를 끝까지 못 잰다.** 30~50건 정답셋이 필요하다.

### 라벨링 단위

문서 하나에서 **조항마다** 다음을 기록한다.

```
원문 범위(page_from, char_from) ~ (page_to, char_to)
조 번호 · 제목 · 부(部)
종류: 약관조항 | 인용법령 | 별표 | 목차 | 안내문
```

### 층화 (`docs/handoff/10_계약_모델_평가.md` §3-3 규칙 준수)

| 축 | 값 |
|---|---|
| 보험사 | 12개사에서 최소 2건씩 |
| 조판 | `제N조` 형 / `N.` 형 / 혼합 |
| 위험군 | 별표·법령 부록이 있는 문서 · 분권 문서 · `suspect` 문서 |

★30건에서 오류 0건이어도 **실제 오류율 95% 상한은 약 10%** 다(rule of three).
같은 문서의 §3-2 가 이미 지적한 내용이다. **표본이 작으면 작다고 말한다.**

### 채점

예측 조항과 정답 조항을 **원문 범위로 일대일 매칭**하고, 아래를 모두 만족할 때만 TP.

- 범위 겹침이 충분(예: IoU ≥ 0.8)
- 조 번호와 제목이 일치
- 종류가 일치 (약관조항을 법령으로 부르면 오답)

```
Precision = TP / 예측 조항 수      Recall = TP / 정답 조항 수
```

항·호가 대상이면 매칭된 조항 안에서 `paragraph_no` · `item_no` 정확도를 따로 낸다.

## 5. 이 지표가 검색 품질을 보장하나 — 아니다

전처리 지표가 좋아지면 검색이 좋아진다고 **말할 수 없다.** 2026년 논문들이
경계 정확도를 독립적으로 안 재는 이유이기도 하다.

함께 재야 하는 것:

| 층 | 지표 |
|---|---|
| 전처리 | 위 T/B/C + 정답셋 기반 조항-span P/R |
| 검색 | hit@k · MRR — **단, 정답 청크 ID 가 산출물 버전에 묶인다.** s5 로 바뀌면 정답셋을 다시 만들어야 한다 |
| 판정 | **인용 검증** — 답이 든 조항이 실제 근거에 있는가. 여기가 서비스 안전선이다 |

★모델팀의 e5-large 선정(80문항)은 **s2 또는 3rd 청크 위**에서 나온 값이다.
s5 로 재색인하면 조항 경계가 달라져 **정답 청크 ID 가 깨진다.** 재평가가 필요하다.

★**3rd 는 `collapse_glyph_dup()` 로 이 글리프 중복을 정제하고 횟수를 보고한다. 우리는 안 한다.**

### 5.5-4. 코덱스의 운영 정책 제안 (채택 권고)

- **A-B-A · 내부 타 조 헤더 · 부록 흡수** → `parse_status=suspect` + `citation_eligible=false`
- 번호 비연속 · 항·호 이상 · 오염률 → **검수 우선순위 신호**(자동 실패 아님)
- **단일 종합 점수는 만들지 않는다.** 정답셋이 없어 가중치를 정당화할 수 없다

### 5.5-5. 정답셋은 "문서 48건"이 아니라 **48개 평가 패킷**

각 패킷 = 서로 다른 문서의 **원문 3페이지 창**(경계 페이지 앞뒤 1쪽 포함) ≈ 144페이지.
계약(`10_계약_모델_평가.md:177`)의 20+5+5+위험군 규칙을 그대로 지킨다.

| n | 오류 0건일 때 실제 오류율 95% 상한 | p=0.5 Wilson 반폭 |
|---:|---:|---:|
| 30 | 9.50% | ±16.85%p |
| 48 | **6.05%** | ±13.61%p |
| 50 | 5.82% | ±13.36%p |

★48건 전부 무오류여도 **"오류율 6% 미만"** 까지만 말할 수 있다.
★span 수가 많다고 CI 를 좁히지 말고 **문서 단위 cluster bootstrap** 을 쓴다.

★1차 지표는 span F1 이 아니라 **위험 오인용률**과 **안전 인용 precision** 이다.
  (텍스트는 실재하는데 다른 조·항·호를 붙인 예측 / 인용 가능한 전체 예측)
