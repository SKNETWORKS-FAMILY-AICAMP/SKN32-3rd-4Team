# SQLite 기본 명칭·위치 정리 리포트

- 작업 시각: 2026-08-03 17:43 KST
- 작업 목적: 쇼핑몰 레거시 이름인 `mall.db`를 제거하고 보험 프로젝트에 맞으면서도 용도가 과도하게 좁지 않은 기본 SQLite 명칭과 위치를 정한다.

## 결정

기본 SQLite 경로를 다음과 같이 정했다.

```text
data/db/insurance.sqlite3
```

- `insurance`: 현재 프로젝트의 보험 도메인을 나타내되 특정 기능이나 화면 이름에는 종속되지 않는다.
- `.sqlite3`: 모호한 `.db` 대신 실제 파일 형식을 드러낸다.
- `data/db/`: 런타임 데이터를 소스 코드 `app/db/` 및 DDL·마이그레이션 `scripts/db/`와 분리한다.

## 변경 내용

| 파일 | 변경 |
|---|---|
| `app/core/config.py` | `DB_DIR` 추가, 기본 `DATABASE_URL`을 새 경로로 변경 |
| `.env.example` | 기본 경로 설명과 SQLite URL 예시 변경 |
| `.gitignore` | `data/db/*.sqlite3` 및 SQLite 사이드카 파일 제외 |
| `data/db/README.md` | 런타임 DB 디렉터리의 역할과 관리 기준 기록 |
| `docs/data_manifest.md` | 기본 로컬 SQLite 생성물 경로 변경 |
| `docs/asset_manifest.md` | 복제 제외 생성물 경로 변경 |
| `tests/test_config.py` | 기본 DB 경로와 `DB_DIR` 회귀 검증 추가 |
| `tests/conftest.py` | 임시 DB 이름을 `insurance_test_*.sqlite3`로 변경 |
| `legacy/README.md` | 과거 `mall.db` 복원 시 명시적 URL 지정이 필요함을 반영 |

`legacy/v8_mall_db.zip`에 보관한 0바이트 스냅샷은 그대로 유지했다. 그 엔트리를 새 위치에 `insurance.sqlite3`라는 이름으로 배치했으며, 파일 내용과 해시는 바뀌지 않았다.

## 검증

### 설정 직접 검증

환경의 `DATABASE_URL`을 제거하고 `Settings(_env_file=None)`을 생성해 다음을 확인했다.

```text
DATABASE_URL = sqlite:///C:/Users/playdata2/Documents/llm_workspace/_unified_mall_3/data/db/insurance.sqlite3
DB_DIR       = C:\Users\playdata2\Documents\llm_workspace\_unified_mall_3\data\db
```

- `DB_DIR == DATA_DIR / "db"`: 성공
- 기본 URL이 `/data/db/insurance.sqlite3`로 끝남: 성공
- 현행 코드·설정·현재 매니페스트의 `mall.db` 참조: 0건

## 주의사항

- 현재 파일은 이름과 위치를 옮긴 빈 스냅샷이므로 실제 스키마나 데이터가 없다.
- 애플리케이션이 기본 설정으로 DB 초기화를 수행하면 이 파일에 SQLite 스키마가 생성될 수 있다.
- 운영 또는 공유 환경에서는 파일명을 다시 바꾸지 않고 `DATABASE_URL`로 PostgreSQL 등 외부 DB를 지정할 수 있다.
- `legacy/v8_mall_db.zip`과 이전 작업 리포트의 `data/mall.db` 표기는 과거 상태를 증명하므로 유지한다.
