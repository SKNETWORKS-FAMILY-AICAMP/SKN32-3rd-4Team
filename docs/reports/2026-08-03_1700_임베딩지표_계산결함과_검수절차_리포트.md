## 2. 실제 수행 내용

### 2-1. ★「벡터무변화」 계산이 틀렸다 — 측정 21건 전부 무효였다

코덱스가 저장값 `proviso_delta_min = −0.00417` 을 짚었다. 코사인 거리는 음수가
될 수 없다. 파고 보니 두 군데가 어긋나 있었다.

```
옛 계산:  d = 1 − (h·w)          ,  세는 조건 d < 1e-6
```

- **① 벡터가 단위 노름이 아니다.** 재측정에서 잰 노름이 fp16 **0.999579~1.000488**,
  4bit **0.998076~1.003902**. 곱이 1을 넘으면 거리가 **음수**가 되어 문턱을 통과하고,
  1보다 작으면 **같은 벡터라도** 거리가 양수로 남아 문턱을 못 넘는다.
- **② 문턱 `1e-6` 은 잴 수 없는 값이었다.** fp16 내적의 1 근처 분해능은 2⁻¹¹≈4.9e-4 다.
  저장된 `proviso_delta_min` 17개가 **2⁻¹¹ 배수를 6자리로 반올림한 값**과 일치했다.

**고침** — float64 에서 노름을 직접 나눠 계산하고 문턱을 `1e-9` 로 내렸다.
결과에 `probe_norm_min/max`·`blind_eps`·`probes_gpu`·`probes_dtype` 를 남긴다.

### 2-2. 전량 재측정 (21건)

`--probes-only` 를 만들어 **탐침만** 다시 쟀다. 순위 지표(`ranks` 포함)는 유효하므로
덮어쓰지 않고 합친다 — 통째로 갈면 §3-1 짝비교를 다시 못 만든다.

| | 어디서 | 결과 |
|---|---|---|
| fp16 17건 | 랩 박스 RTX 4070 SUPER | 전부 성공 |
| 4bit 4건 | **같은 랩 박스** | 전부 성공(`comsat` 은 1회 실패 후 재시도) |

★4bit 원 측정 기계(RunPod RTX 2000 Ada)는 반납돼 접속이 끊겼다(`Connection refused`).
GPU 가 다르므로 `probes_gpu_matches_original=false` 로 남긴다.

**바뀐 값** — 지표가 잘림에만 반응하게 됐다.

```
128토큰    45~46/60  (2개)      옛 34·30
512토큰     6/60     (5개 전부)  옛 4·7
8192 이상   0/60     (14개 전부) 옛 1·2·11·13·15·18
```

★**§5-6 「4bit 13/60 은 양자화 조건에 귀속된다」를 철회했다.** 재측정에서 4bit 넷이
전부 0/60 이다. 다만 공식과 GPU 가 **함께** 바뀌었으므로 어느 쪽 때문인지 가르지 않는다.

### 2-4. ★내가 만든 결함 둘

**① `readiness` 가 PG 세션을 안 닫아 3시간 락을 걸었다.**
`index_state()` 를 연 연결이 `idle in transaction` 으로 3시간 9분 남아
`policy_clause_chunk` 읽기 락을 쥐었다. 그 뒤로 **병행 트랙의 `ALTER TABLE` 이 막히고**
같은 조회 12개가 밀렸다. 테스트가 64%에서 15분간 멈춘 원인이었다.
→ `lock_timeout 2s` · `statement_timeout 5s` · `finally: rollback+close`.

**② 병합 스크립트에서 `dtype` 버그를 고치고 `gpu` 에서 똑같이 되풀이했다.**
`new["gpu"]` 를 쓰면 재측정 GPU 가 원본으로 되돌아가고 일치 판정이 `true` 가 된다.
→ `new.get("probes_gpu") or new.get("gpu")`. [회귀 시험 6건](../../tests/test_probe_merge.py) 추가.

### 2-5. 검수가 14라운드를 돌고도 수렴하지 않아 절차를 바꿨다

코덱스에 **왜 수렴하지 않는지**를 물었다. 답:

> 문서가 205 → 882줄로 커지는 동안 **고정된 대상을 전수 검수한 적이 없었다.**
> 14라운드는 "부분검수와 수정이 서로 새 표면적을 만든 기록"이다.

그리고 내 습관 셋을 짚었다 — 결론을 먼저 쓰고 한계를 뒤에서 수습한다,
`확인됐다`·`때문이다`·`전부` 를 증거보다 한 단계 세게 쓴다,
**정정 이력을 공유 문서에 계속 붙인다**(투명성이 아니라 복제 결함 발생기).

**바꾼 것**

- **동결 검수** — 문서·스크립트·결과 21건의 SHA-256 을 기록하고, 검수 중 하나라도
  바뀌면 결과를 폐기한다. 코덱스가 시작·종료 해시가 같음을 확인했다.
- **감사 도구** [`scripts/eval/audit_brief.py`](../../scripts/eval/audit_brief.py)
- **생성 영역** — 표·접두어·재현 명령을 `<!-- BEGIN GENERATED -->` 로 감싸
  실제 출력과 대조한다. 손으로 고치면 잡힌다.
- **증거 태그** — `(통제 비교)` `(관찰)` `(해석)` `(정책)` `(원인 미상)`

## 6. 이 작업이 알려준 것

- **틀린 숫자가 그럴듯한 방향으로 틀리면 아무도 의심하지 않는다.**
  "양자화하면 정보가 준다"는 상식과 맞아떨어져 14라운드째에야 잡혔다.
- **표를 손으로 만들면 반드시 어긋난다.** 생성 영역 + 바이트 대조로 바꿔야 한다.
- **검수 대상이 움직이면 전수 검수가 성립하지 않는다.** 동결이 먼저다.
- **정정 이력을 공유 문서에 계속 붙이면 결함이 복제된다.**
  공유용 · 실험 부록 · 정정 기록을 분리해야 한다(다음 작업).
- 규칙을 **작업 전에** 읽는다. 내가 만든 문제로 생긴 규칙을 내가 어겼다(§0).
