# s6 manifest가 승인 포인터를 전처리 입력으로 해시함

- 발견 시각: 2026-08-03 16:02 KST
- 심각도: P0 — s6 승인 행위가 s6 기준선 검증을 스스로 깨뜨림
- 상태: **수정 완료** — mutable 포인터 제외·과거 manifest 호환·회귀 테스트 통과

## 위치

`scripts/extract/build_manifest.py:config_state()`가 `config/*.json`을 전부 해시한다.
현재 대상은 다음 두 파일이다.

- `generation_profiles.json`
- `accepted_extraction.json`

## 재현과 실측

`data/manifests/preprocess/manifest_s6.json`의 `config`에는
`accepted_extraction.json=26966e…`가 기록돼 있다. `--verify`는 현재 파일의 해시가 이 값과
다르면 실패한다.

하지만 `accepted_extraction.json`은 전처리 입력이 아니라 **어느 산출물을 서빙할지 정하는 mutable 운영 포인터**다.
s6를 승인해 이 포인터를 s5에서 s6로 바꾸는 순간 s6 manifest 검증이 실패하는 순환 의존이 생긴다.

## 위험

- 정상적인 s6 승인 작업이 “전처리 산출물 변조”로 오인된다.
- 반대로 승인 포인터를 못 바꾸는 이유가 품질 결함인지 manifest 설계 결함인지 구분되지 않는다.
- 전처리 재현성과 serving 상태가 한 지문에 섞여 단일 진실원 경계가 무너진다.

## 정정 계획

1. `accepted_extraction.json`을 전처리 config snapshot에서 명시적으로 제외한다.
2. 과거 manifest에 해당 키가 있어도 `--verify`는 검증에서 제외하고 NOTE를 남긴다.
3. 제외 규칙을 회귀 테스트로 고정한다.
4. 임의의 config 전체가 아니라 실제 전처리 입력 설정 allowlist로 좁히는 후속 검토를 남긴다.

## 수정·검증 결과

- `RUNTIME_ONLY_CONFIGS={"accepted_extraction.json"}`를 추가했다.
- 새 manifest의 config snapshot에서는 해당 포인터를 제외한다.
- 과거 manifest에 기록된 키는 `--verify`가 NOTE를 남기고 전처리 무결성 검사에서 제외한다.
- 제외/과거 호환 회귀 테스트를 추가했고 `tests/test_preprocess_manifest.py` **6 passed**.
- 실제 s6 verify는 NOTE와 함께 문서 1,367건·어긋남 0·exit 0.

후속 과제: `generation_profiles.json`도 실제 extraction 입력인지 확인하고 config snapshot을
명시적 allowlist로 좁힌다.
