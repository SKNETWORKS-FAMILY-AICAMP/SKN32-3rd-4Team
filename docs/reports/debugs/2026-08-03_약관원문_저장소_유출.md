## 무엇을 어겼나

`CLAUDE.md` §2:

> **약관 원문은 저작물이다.** `data/raw/` 에만 두고 **커밋하지 않는다.**

이 규칙을 지키려고 이미 여러 장치를 만들어 두었다 —
`.gitignore` 에 `data/extracted/`·`data/structured/`·`data/glossary/` 를 넣었고,
푸시할 때마다 유출 점검 명령을 돌렸다.

**그런데 `data/exports/` 는 그 목록에 없었다.**

---

## 원인

전처리 트랙(병행 세션)이 시각화용으로 `data/exports/` 를 새로 만들었다.
서버 트랙(나)이 커밋할 때 `git add -A` 로 **전부 쓸어 담았다.**

```
f5a1354  _unified_mall_3: 용어 챗봇 — 보장 여부는 답하지 않는다
         ← 이 커밋에 parquet 이 섞였다
```

★**파일을 보지 않고 커밋한 것**이 원인이다.
푸시 직전 유출 점검도 돌렸지만, 점검 패턴이
`data/(extracted|structured|glossary|external|cohort)/` 였고
**`exports/` 가 빠져 있었다.** 새 폴더가 생기면 점검이 자동으로 따라가지 않는다.

> 트랙이 둘로 나뉘어 돌면 **한쪽이 만든 산출물의 성격을 다른 쪽이 모른다.**
> 이건 그 구조가 만든 사고다.

## 조치

### 한 것

```
git rm --cached data/exports/s5_clauses.parquet
.gitignore  +  data/exports/*_clauses.parquet
```

두 저장소(로컬 · 팀) 모두 적용하고 푸시했다(`7066a0b` · `de5dbf6`).

같은 폴더의 나머지 9개는 **parquet 열을 전수 확인**해 원문이 없음을 확인하고 남겼다 —
추측으로 지우거나 남기지 않았다.

| 파일 | 판정 |
|---|---|
| `s5_clauses.parquet` | ★`text` 열 = 원문 → **제거** |
| `s5_documents` · `s5_clause_lengths` · `kcd_chapter_kind` · `ref_matrix_top` | 메타만 → 유지 |
| `views/v1~v5` | `sha12`·`insurer`·`page` 등 메타만 → 유지 |

### ★안 한 것 — 그리고 왜

**이력에서는 지워지지 않았다.** 커밋 객체가 남아 있어
해당 커밋 해시를 알면 지금도 내려받을 수 있다.

지우려면 `git filter-repo` + 강제 푸시가 필요한데,
**팀원 전원이 클론을 다시 받아야 한다.** 팀이 결정할 사안이라
임의로 하지 않았다.

## 재발 방지

### 넣은 것

```gitignore
# ★약관 원문이 든 산출물은 커밋하지 않는다(CLAUDE.md §2 — 저작물).
data/exports/*_clauses.parquet
data/exports/**/*_clauses.parquet
```

### ★부족한 것 (정직 기록)

위 규칙은 **이름이 `_clauses` 로 끝나는 것만** 막는다.
다음에 누가 `data/exports/clause_dump.parquet` 을 만들면 또 새어 나간다.

**이름이 아니라 내용을 보는 검사**가 필요하다 —
커밋 대상 중 텍스트 열(`text`/`body`/`content`)을 가진 데이터 파일을 찾아
막는 훅. 아직 없다. 다음 작업으로 남긴다.

## 이 사고가 알려준 것

- `git add -A` 는 **다른 트랙이 만든 것까지 가져온다.** 커밋 전에 목록을 봐야 한다.
- 유출 점검을 **폴더 이름 목록**으로 하면, 새 폴더가 생길 때마다 구멍이 생긴다.
- 대용량 경고(`GH001: Large files detected`)가 떴을 때 **그냥 넘기지 않은 것**이
  이 사고를 발견한 계기였다. 경고를 읽는 것이 값을 했다.
