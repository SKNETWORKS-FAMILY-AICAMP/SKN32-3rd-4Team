## 1. 확인된 결함

### 1-1. 외부 에이전트 경로가 무인증이다

- `app/routers/precheck.py:253`의 `/v1/prechecks`
- `app/routers/precheck.py:431`의 `/v1/observations`
- `app/routers/cohort.py:95`의 `/v1/cohorts`

세 경로에 agent API key, OAuth client, scope dependency가 없다. `client_ref`는 body의 자기신고
문자열이어서 다른 에이전트 이름을 적어도 그대로 저장된다. 실행 중인 고객 앱의 OpenAPI에서도
세 operation의 `security`가 비어 있음을 확인했다.

### 1-2. 명시적 멱등키가 HTTP 스키마에서 조용히 사라진다

`app/adapters/external_submission_store.py:85`는 payload의 `idempotency_key`를 읽지만,
`app/schemas/precheck.py:137`의 `ExternalCaseSubmission`에는 해당 필드가 없다. Pydantic 기본
extra 처리로 HTTP body에 넣은 키가 model dump 전에 제거된다.

재현:

```powershell
@'
from app.schemas.precheck import ExternalCaseSubmission
x = ExternalCaseSubmission(
    client_ref="agent-a", insurer="DB손해보험", kcd_codes=["F32"],
    outcome="denied", idempotency_key="client-event-1"
)
print(x.model_dump())
'@ | python -
```

출력에 `idempotency_key`가 없다. 현재 중복 방지는 payload 전체 해시의 우연한 동일성에 기대며,
클라이언트가 재시도 키를 명시적으로 통제할 수 없다.

### 1-3. 민감정보를 남기지 않는다는 관측 계약과 실제 코드가 다르다

`app/obs/agent_stream.py:20`은 민감정보를 담지 않는다고 선언하지만,
`app/routers/precheck.py:324`는 `detail.codes`에 KCD 원문을 기록한다. 현재
`data/obs/agent_events.jsonl`은 append-only 파일이고 감사 저장소도 아니므로, 원문 KCD를
남길 필요가 없다.

### 1-4. DDL만 있고 런타임 연결이 없다

`scripts/db/004_app_ops.sql:116`에는 `ops.agent_client`, 인증 로그,
`ops.interaction_log`가 있으나 앱 코드에서 이 테이블을 조회·기록하는 repository가 없다.
또한 handoff가 요구하는 scope 필드와 영속 rate-limit 이벤트가 DDL에 없다.

### 1-5. 원격 운영 진입점이 없다

`scripts/run_customer_server.py:24`는 `127.0.0.1:8080`에 고정돼 있다. 안전한 개발 기본값으로는
맞지만 환경설정으로 바꿀 수 없어 reverse proxy나 컨테이너 뒤에 배치할 때 소스 수정이 필요하다.

## 2. 실측

- 고객 API readiness: `true`
- `/v1/prechecks`, `/v1/observations`, `/v1/demo/observations`, `/v1/cohorts` OpenAPI security: 없음
- 합성 agent DB: 제출 77·승격 40·대기 37
- 관련 기존 회귀시험: 39 passed

합성 시뮬레이터는 실제 HTTP를 사용하지만 `/v1/demo/*`와 `insurance_demo`에 격리돼 있어 이 결함의
직접 원인은 아니다.

## 3. 영향

1. 외부 공개 시 아무 클라이언트나 판정·제출 API를 호출하고 다른 `client_ref`를 사칭할 수 있다.
2. 호출량을 클라이언트별로 제한하거나 폐기한 key를 차단할 수 없다.
3. 같은 이벤트의 안전한 재시도와 같은 키·다른 payload 충돌을 구분할 수 없다.
4. KCD 원문이 관측 파일에 누적돼 최소수집 원칙을 어긴다.
5. DDL이 존재한다는 사실만으로 운영 인증이 구현된 것으로 오인할 수 있다.

## 4. 정정 방향

1. 기존 고객 UI 경로는 유지하고 `/v1/agent/*` 보호 경로를 별도로 둔다.
2. 별도 agent DB에 key hash·scope·상태·auth log·rate event·API audit를 저장한다.
3. 인증된 client id만 사용하고 body의 `client_ref`는 신뢰하지 않는다.
4. agent 쓰기 경로는 `Idempotency-Key` 헤더를 필수로 하고 payload 충돌을 409로 거절한다.
5. 감사·관측에는 canonical hash와 비민감 판정 메타데이터만 남긴다.
6. host/port는 설정화하되 기본값은 loopback으로 유지한다.
