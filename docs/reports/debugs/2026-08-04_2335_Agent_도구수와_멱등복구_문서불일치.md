# Agent 도구 수·멱등 복구 문서 불일치

- 발견 시각: 2026-08-04 23:35 KST
- 대상: `docs/handoff/03_에이전트_데이터_축적_설계.md`,
  `docs/handoff/06_계약_Agent.md`, `app/adapters/external_submission_store.py` 문서화 문자열
- 상태: 구현 완료 후 계약 대조에서 확인, 수정 전 기록

## 현상

1. Agent 계약의 제목은 “도구 3개”라고 쓰지만 바로 아래 표에는
   `precheck`, `explain_term`, `cohort_stats`, `submit_observation` 4개가 있다.
2. 외부 사례 저장소의 경로 설명은 공개 접수 경로만 보여 주며, 등록 에이전트 원본이
   `submissions/registered_agent/` 아래에 격리된 구현을 드러내지 않는다.
3. 설계 문서는 5분 stale 재개까지만 설명하고, 늦게 끝난 이전 worker가 새 worker의 완료 결과를
   덮지 못하도록 `lease_token` compare-and-set을 적용한 보강을 적지 않았다.

## 영향

- 팀원이 외부 인터페이스 수를 잘못 이해할 수 있다.
- 공개·등록 채널의 원본 격리 경계를 파일 구조에서 확인하기 어렵다.
- 멱등 복구가 단순 시간 만료인지, 소유권 토큰까지 검증하는지 계약만 보고 판단할 수 없다.

## 수정 방향

도구 수를 4개로 정정하고, 등록 채널 원본 경로와 lease token CAS를 구현 계약에 명시한다.
