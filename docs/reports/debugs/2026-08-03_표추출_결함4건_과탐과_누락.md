## D-1. 2열짝짓기가 본문을 표로 오인 — **과탐 99.8%**

**위치** `scripts/extract/table_coords.py` `find_two_col()` / `pair_two_col()`

**재현**
```bash
python -m scripts.eval.table_signal_fit
```

**실측** (s6 전량, 게이트 전)
```
좌표 표 405,845개
  2열짝짓기 404,929 (99.8%)
  선          916 (0.2%)
```
산출물 표본에서 그대로 뽑은 것:
```
'6.' | '응급환자의 이송 등…'          ← 6·7·8행에 같은 값
'보험금 ④ 회사는' | '늦어지는 경우 보험수익자…'
'실손의료비보험은 에 한정합니다)를' | '보험회사가 피보험자의 질병 또는…'
```
마지막 것은 **한 문장을 두 열로 쪼개며 어절이 뒤섞인 것**이다.
원문: "실손의료비보험은 보험회사가 피보험자의 질병 또는 상해로 인한 손해(의료비에
한정합니다)를 보상하는 상품입니다."

**위험도 — 높음.** 없는 표를 근거로 든다. 어절이 뒤섞이면 **뜻이 반대로 남을 수 있고**,
면책 조항에서 그러면 "보상됩니다"라고 잘못 말한다(CLAUDE.md §0).

**정정** — 직전 보고에서 "표 405,845개 · 레코드 2,549,729개"라고 적고
정답셋 1.000 과 나란히 놓았다. **그 1.000 은 `선` 경로 0.2% 를 잰 값**이고
나머지 99.8% 는 미검증이었다. 두 수치를 함께 놓아 전체가 정확한 것처럼 읽히게 만들었다.

**수정**
- 조항 단계 게이트 — `선` 또는 판별 신호 통과(`is_table`)만 싣는다
- 보류 수를 `stats.tables_withheld_unverified` 에 남긴다(조용한 스킵 금지, §3)
- 판별 신호 `scripts/extract/table_signals.py` 신설

## D-2. `pair_two_col()` 이 **오른쪽 덩어리를 재사용**한다

**위치** `scripts/extract/table_coords.py:313` (수정 전)

**원인** 왼쪽 덩어리마다 y 가 겹치는 오른쪽 덩어리를 **전부** 붙였다.
한 덩어리가 여러 왼쪽에 중복 배정된다.

```python
for t in lb:
    m = [b for b in rb if y겹침]      # ← 이미 쓴 것을 빼지 않는다
    pairs.append((join(t), join(모든 m 의 단어)))
```

**실측** `'6.'|X, '7.'|X, '8.'|X` 의 직접 원인.
그리고 **점수를 부풀린다** — 붙기만 하면 `matched` 가 오르므로
본문이 표처럼 높은 점수를 받는다(코덱스 지적).

**위험도 — 높음.** rowspan 오연결로 **질병명↔KCD 코드 오짝**을 만든다.

**수정** 겹침이 가장 큰 왼쪽에만 배정하고 쓴 것은 뺀다. `n_right_unused` 를 함께 남긴다.

**★부수 효과 — 판별 신호가 사라졌다.** 고치기 전에는
`T2 연속중복셀`·`T4 좌셀문장비율` 이 참/거짓을 깨끗이 갈랐는데,
고친 뒤 **참·거짓 모두 0** 이 됐다. 그 둘은 표의 성질이 아니라 **이 버그의 지문**이었다.
남은 판별자는 `T1 통로` 하나뿐이고 간격도 좁다(참 0.039 / 거짓 0.064).
**게이트가 얇아졌다는 사실을 계획서 L1 에 적었다.**

## D-3. `line_cols()` 가 `re`(사각형) 괘선을 못 본다 — **4개사 표 0개**

**위치** `scripts/extract/table_coords.py:119` `line_cols()`

**원인** `it[0] != "l"` 로 선분만 봤다. 조판기에 따라 표 괘선을 **얇은 사각형**으로 그린다.

**실측**
```
KB손보 1d87934060bb p8:  drawings 29 · item {'l': 27, 're': 2} · line_cols 0
```
`선` 경로 표가 **0개**인 보험사 4곳: `kbinsure` · `meritzfire` · `myangel` · `nhlife`

**위험도 — 중.** 그 회사 문서는 표가 아예 판정에 도달하지 않는다.
"표가 없는 약관"이 아니라 **우리가 못 본 것**인데, 산출물만 보면 구분이 안 된다.

**수정** `_rules()` 신설 — `l` 과 **얇은 `re`(두께 ≤ 2.0pt)** 를 함께 모은다.
두꺼운 `re` 는 음영 상자라 제외한다.

**결과** kbinsure·meritzfire·myangel 에서 `선` 표가 검출됐다(표 있는 6쪽 중 3~5개).

## D-4. `line_cols()` 길이 조건이 **페이지 높이의 30%**

**위치** 같은 함수 `min_frac: float = 0.3`

**원인** 세로 괘선이 `(clip 높이) × 0.3` 을 넘어야 열 경계로 인정했다.
`clip` 은 **페이지 전체 텍스트 영역**이라, 쪽 일부만 차지하는 작은 표는
**원리적으로 못 잡는다.**

**실측** nhlife 표본에서 최장 세로 괘선 56.8pt / clip 높이 498 → 11.4%. 전부 탈락.

**위험도 — 중.** D-3 과 같다. 작은 표(자기부담금 요약 등)가 통째로 누락된다.

**수정** 절대 길이 `min_abs = 24.0pt`(본문 3줄 남짓)을 두고 **둘 중 작은 쪽**을 문턱으로.
그보다 짧은 세로선은 밑줄·구분자이지 표 괘선이 아니다.

**회귀 확인** 정답셋 `table_gold_check` **1.000 유지**.
