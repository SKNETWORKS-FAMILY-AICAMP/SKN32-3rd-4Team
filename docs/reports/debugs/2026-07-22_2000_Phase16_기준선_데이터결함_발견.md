# Phase 16 중간 리포트 — 기준선 구축 중 **학습 데이터 결함 발견**

- 일자: 2026-07-22
- 계획: [`docs/plans/2026-07-22_1900_Phase16_CS분류_SLM_QLoRA.md`](../plans/2026-07-22_1900_Phase16_CS분류_SLM_QLoRA.md) §9 첫 단계(저렴한 기준선)
- 결론: **계획의 데이터 전제가 사실과 다르다. 착수 조건 미충족 → 진행 중단하고 방향 재결정 필요.**

## 1. 무엇을 하려 했나

계획서대로 SLM 파인튜닝에 앞서 "SLM 없이 나오는 성능선"을 확보하려 했다.
TF-IDF(char n-gram) + 선형 분류기 3종 + 다수클래스 하한선을,
원본 60건에 대한 반복 stratified 5-fold CV로 평가.

## 2. 1차 결과와 그것을 의심한 이유

| 모델 | Macro-F1 (평균±95%CI) |
|---|---|
| TF-IDF(char)+LogReg | 0.992 ± 0.015 |
| TF-IDF(char)+LinearSVC | 0.992 ± 0.015 |
| TF-IDF(char)+ComplementNB | 0.992 ± 0.015 |
| 다수클래스(하한선) | 0.051 ± 0.003 |

7클래스·60건에서 Macro-F1 0.992는 **비정상적으로 높다.** 그대로 보고하지 않고 검증했다.

## 3. 검증 결과 — 두 가지 결함

**(1) 내 평가 코드의 누수 (내 실수)**
- 분할 무결성(train∩test) 자체는 문제 없었다(0건).
- 그러나 **동일 본문이 여러 행에 존재**하는데 이를 같은 계보로 묶지 않아,
  같은 문장이 train과 test 양쪽에 들어갔다. → 0.992는 **암기 점수**다.

**(2) 원본 데이터 자체의 결함 (더 중대)**

`data/cs_inquiries.csv`는 60행이지만 **고유 본문은 15개뿐**이다.
같은 문장이 2~7회 반복되고 `inquiry_id`·고객ID·채널·일시만 다르다.

```
같은 본문 → ids: ['Q0001', 'Q0023', 'Q0025', 'Q0028', 'Q0044']
반복 횟수 분포: 7회×1, 6회×1, 5회×4, 4회×3, 3회×3, 2회×3
```

| 클래스 | 원본 행 | **고유 문장** |
|---|---|---|
| 상품문의 | 13 | 3 |
| 배송 | 7 | 3 |
| 결제 | 8 | 2 |
| 환불 | 10 | 2 |
| 교환 | 9 | 2 |
| 불만 | 8 | 2 |
| **칭찬** | 5 | **1** |
| 합계 | 60 | **15** |

부가 확인: 고유 15건 중 **라벨 단어가 본문에 그대로 등장**하는 경우가 상당수라
태스크 자체도 어휘 매칭으로 풀리는 쉬운 문제다.

## 4. 이것이 의미하는 것

- **0.992는 철회한다.** 누수된 수치이며 어떤 비교의 기준으로도 쓸 수 없다.
- 계획서 §2의 전제 "라벨 데이터 60건 보유 → 즉시 학습 가능"은 **사실이 아니다.**
  실제로는 **15문장**이고, 한 클래스는 **1문장**이다.
- 고유 15건으로는 stratified 5-fold조차 불가능하다(최소 클래스 1건 → 최대 1-fold).
  실제로 sklearn이 `n_splits=5 cannot be greater than the number of members in each class`로 실패했다.
- 즉 **이 데이터만으로는 파인튜닝도, 그 평가도 성립하지 않는다.**

## 5. 선택지 (재결정 필요)

| # | 방향 | 내용 | 현실성 |
|---|---|---|---|
| A | 외부 데이터를 **주력**으로 | AI Hub 민원상담/한국어 대화를 본 데이터로 삼고, 사내 15문장은 도메인 예시로만 사용 | AI Hub 가입·승인 필요(지연 위험) |
| B | **태스크 변경** | 공개 데이터가 충분한 과제로 전환 — 근거기반 QA(KorQuAD) 또는 근거지지 판정(KorNLI). 둘 다 즉시 다운로드 가능 | **즉시 착수 가능** |
| C | 데이터 직접 제작 | 7클래스 × 30건 이상을 직접 작성/수집 | 시간 소요, 품질은 통제 가능 |
| D | 강행 | 15문장으로 파인튜닝 | **비권장** — 결과에 의미 없음 |

## 6. 배운 것 (프로세스)

- "행 수"를 데이터 규모로 신뢰하면 안 된다. **고유값 기준으로 먼저 세야 한다.**
- 비정상적으로 좋은 첫 수치는 성과가 아니라 **점검 신호**다. 0.992를 그대로 보고했다면
  이후 모든 비교가 무의미해졌을 것이다.
- 계획서 작성 시 데이터 "존재"만 확인하고 **품질·중복·고유성**을 확인하지 않은 것이
  이번 착오의 원인이다. 다음 계획서부터 데이터 검증을 착수 전 필수 항목으로 넣는다.
