## 1. 한화손해보험 — robots 가 약관 파일을 금지한다

### robots.txt 의 구조

파일이 **BOM(`﻿`)으로 시작**한다. 그래서 파이썬 `RobotFileParser` 는 첫 줄
`User-Agent: *` 를 인식하지 못하고, 그 아래 규칙 365개가 전부 주인 없는 규칙이 되어
**"규칙 없음 = 전부 허용"** 으로 오독한다.

실제 내용을 `utf-8-sig` 로 읽으면:

```
Allow 364개  +  Disallow: /   ← 화이트리스트 방식
```

### 확인한 것

| 항목 | 결과 |
|---|---|
| 상품소개 페이지 `/product/catalog/product-info.do?insGdcd=…` | **Allow (30개)** |
| 그 페이지에 약관 PDF 링크 | **있다** |
| 실손 상품 | **1건** — `한화실손의료보험(갱신형)Ⅴ 무배당` |
| 그 PDF 경로 `/upload/product/…_약관.pdf` | ★**Allow 목록에 없다** |
| `/upload` 로 시작하는 Allow | 2개뿐, 둘 다 `/upload/etc/notice/ir/…` |

→ `Disallow: /` 가 적용되어 **약관 PDF 는 금지**다.
   "페이지는 봐도 되지만 파일은 받지 말라"가 robots 에 적힌 그대로다.

### 판단

목록에 넣는 것을 잊었을 수도 있다. 그러나 **우리가 "의도는 허용일 것"이라고 해석하면 안 된다.**
게다가 실손이 1건뿐이라 실익도 작다. **수집 대상에서 제외한다.**
사람이 사업적으로 판단해 문의할 사안으로 남긴다.

## 2. 롯데손해보험 — 경로는 전부 찾았다. 마지막 한 걸음이 남았다

### ★"방화벽 차단"은 오판이었다

처음에 브라우저로 열었을 때 WAF 차단 화면이 나와 "불가"로 접었는데, **그건 브라우저 자동화에만
걸린 것**이고 내가 시도한 URL(`/web/C/D/A/cda_intro.jsp`)도 404 였다.
파이썬 직접 요청은 정상 200 이고 robots 도 관대하다:

```
User-agent: *
Disallow: /web/C/D/H/cdh_center_intro.jsp
Disallow: /mobile/
```

공시실은 **허용**이다.

### 찾은 경로

```
/index2.jsp  →  <frameset>  →  /web/main.jsp   ← 실제 메뉴가 여기 있다
   /web/main.jsp 안에서:
     공시실       /web/C/D/H/cdh700.jsp
     상품공시      /web/C/D/H/cdh170.jsp
     ★보험상품약관  /web/C/D/H/cdh190.jsp      ← 우리가 쓸 화면
```

### 조회 연쇄 (4단계)

`POST /CChannelSvl` · `ops_tc=dfi.c.d.g.cmd.Cdg079Cmd` · `rtnUri=/web/C/D/H/cdh190_result.jsp`

| 단계 | task | 파라미터 |
|---|---|---|
| 2 대분류 | — | `step2(lcode, mcode, val, gubun)` (화면 탭) |
| 3 소분류 | `gostep3issale` / `gostep3isnotsale` | `lcode, mcode, scode, issale` |
| 4 판매기간 | `gostep4issale` / `gostep4isnotsale` | + `startdate` |
| 5 약관 | (미확인) | 응답에 `alt='약관'` 버튼이 있다 |

**대분류 코드(실측)**

| lcode | mcode | 이름 |
|---|---|---|
| 01 | 01~11 | 자동차(개인용/업무용/영업용/이륜차/운전자/…) |
| 02 | 01 | 일반 |
| **03** | **01** | **상해,질병** ← 실손이 여기 |
| 03 | 02~06 | 저축 / 운전자 / 재물 / 연금보험 / 제도성특약 |
| 04 | 01 | 공통 |

`lcode=03, mcode=01, issale=Y` 로 3단계를 부르면 `step4('03','01','','20250401')` 이 돌아온다
— 판매개시일이 나온다는 뜻이다.

### ★막힌 지점

4단계(`gostep4issale`)를 직접 POST 하면 **응답이 0바이트**다.
원인은 `step4()` 안의 `frm.target = "common"` — **응답이 `common` 이라는 프레임으로 가는 구조**라
프레임 없이 POST 하면 빈 응답이 온다.

시도했으나 실패한 것:
- `myform` 의 히든 필드 9개를 전부 실어 보냄 → 여전히 0바이트
- 3단계를 먼저 호출해 세션 상태를 만든 뒤 4단계 호출 → 여전히 0바이트

### 남은 방법

**브라우저로 프레임을 실제로 띄워야 한다.** 다만 롯데는 브라우저 자동화가 WAF 에 걸린다.
- 헤드리스 탐지를 우회하는 것은 **하지 않는다**(사이트가 막은 것을 뚫는 것이 된다)
- `rtnUri` 가 가리키는 `cdh190_result.jsp` 를 **GET 으로 직접** 열어 보는 것은 아직 안 해 봤다

## 3. 흥국생명 — 공시실 URL 을 못 찾았다

차단이 아니다. **찾지 못한 것**이다.

확인한 것:

| 시도 | 결과 |
|---|---|
| `/index.do` (53KB) | '공시' 단어가 **아예 없다** |
| `/front/public/personProduct.do` | 보호금융상품등록부(상품명 목록). 약관 공시 아님 |
| `/front/help/sitemap.do`, `/front/main/sitemap.do`, `/front/public/publicMain.do` | 전부 같은 34,925B 기본 페이지 |
| `/front/public/productDisclosure.do` | 같은 34,925B |
| `pdcs.heungkuklife.co.kr`, `gongsi.heungkuklife.co.kr` | DNS 없음 |
| `online.heungkuklife.co.kr` | 1,543B 껍데기 |

홈페이지에서 발견한 외부 도메인 중 `buy.` / `online.` 만 자사 서브도메인이다.

### 추가로 확인한 것 (2차 조사)

| 시도 | 결과 |
|---|---|
| 홈페이지 링크 `/front/*.do` **35개 전수 조회** | 공시·실손 포함 페이지 **0개** |
| `sitemap.xml` (239개 URL) | 공시실 URL **없음**. 상품 관련 39개는 전부 상품 소개 |
| `/front/product/productInfo.do?cd_prt=…` (상품 상세) | **34,925B 셸**. 약관 0회 |
| `/front/pdcs/`, `/front/gongsi/`, `/front/disclosure/` 등 8개 추측 경로 | 전부 같은 34,925B 셸 |
| `/jsps/…` 경로 75개 | **실제 콘텐츠를 준다**(86KB~786KB). 다만 약관은 없다 |
| `robots.txt` | ★**Fasoo DRM 으로 암호화**되어 있다(내용을 읽을 수 없다) |

★**`/front/*.do` 가 무엇을 요청하든 34,925B 같은 페이지를 돌려준다.**
  서버가 봇에게는 SPA 셸만 주는 구조로 보인다. `/jsps/` 는 실제 파일을 주므로
  **공시실도 `/jsps/` 아래 어딘가**일 가능성이 있다.

### 다음에 해볼 것
- 브라우저로 전체메뉴를 펼쳐 공시실 링크 확인(아직 안 해 봄 — 가장 유력)
- `/jsps/front/` 하위를 탐색
- 생명보험협회 통합공시에서 흥국생명 링크 역추적

★robots.txt 가 DRM 암호화되어 **읽을 수 없다**. 규칙을 확인할 수 없으므로
  **본격 수집 전에 사람이 사이트 운영자에게 확인해야 한다.**

## 4. 메리츠화재 — 경로는 전부 확인했으나 WAF 가 막는다

### 확인한 것 (전부 실측)

AngularJS SPA. 기본 화면은 **자동차보험 분류형**이라 실손이 없다(401건 전부 자동차).
`goSch()`(검색형)로 바꾸고 상품명 `실손` 으로 검색하면 **157건**이 나온다.
검색 입력창은 `name` 이 아니라 **`id="i_keyword"`** 다.

각 행의 스코프(`sal`)에 든 것:

```
ttlNm         상품명
putupStDdTm   판매개시일   putupEdDdTm  판매종료일
file1         /cu/ctl/202607200943045350509U.pdf   ← 약관 실제 경로
file1#[E]     azL/bSZyDdMz8wLjHv1fMN+...           ← 암호화 토큰
```

`pdfDown(item, fileCnt, ttlNm)` 함수가 알려주는 슬롯:
**file1=약관 / file2=사업방법서 / file3=요약서 / file4=상품설명서**

다운로드 호출(함수 본문에서 확인):

```js
fileUtil.download('/hp/fileDownload.do', {
  path:        item['file1#[E]'],      // 암호화 토큰
  id:          item['file1#[E]'],
  orgFileName: ttlNm + "약관.pdf"
})
```

브라우저가 실제로 보내는 요청을 폼 submit 을 가로채 확인:
**method=GET**, 필드에 **`check: "N"`** 이 추가로 붙고, 괄호는 `%28`/`%29` 로 미리 인코딩된다.

### ★막힌 지점

| 시도 | 결과 |
|---|---|
| 파이썬 POST `/hp/fileDownload.do` (path/id/orgFileName) | **WAF 차단** (338B "Web firewall security policies have been blocked") |
| 파이썬 GET + `check=N` + 사전 인코딩 | **WAF 차단** (동일) |
| 브라우저에서 실제 클릭 | `200 OK` → **`net::ERR_ABORTED`** (다운로드 전환으로 보이나 수집기가 못 잡음) |

암호화 토큰의 `/`·`+` 문자가 WAF 규칙에 걸리는 것으로 보인다.
브라우저에서는 되는데 우리 요청만 막힌다.

### 남은 방법
- Playwright 의 `page.expect_download()` 로 감싸 클릭(현재는 `ctx.on("download")` 만 쓴다).
  폼 target 으로 시작되는 다운로드는 컨텍스트 이벤트로 안 잡힐 수 있다.
- **헤드리스 탐지·WAF 우회는 하지 않는다.**
