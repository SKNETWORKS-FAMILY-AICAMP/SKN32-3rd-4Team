# 외부 사례 원본·정규화 이벤트 부분 기록 결함

- 발견일: 2026-08-04
- 대상: `app/adapters/external_submission_store.py`
- 상태: 수정 전 기록

## 현상

파일 저장 순서는 원본 JSON 작성 후 일별 JSONL 이벤트 append다. 두 번째 쓰기에서 프로세스가
죽거나 I/O 오류가 나면 원본만 남는다. 같은 요청을 재시도하면 기존 원본을 발견한 즉시
`duplicate=True`를 반환하므로 빠진 정규화 이벤트는 다시 만들어지지 않는다.

## 영향

- 원본 제출 수와 event/cohort 검수 입력 수가 영구히 달라질 수 있다.
- 등록 에이전트 PostgreSQL 멱등 예약이 재시도를 안전하게 만들더라도 파일 저장소 내부의
  부분 기록까지 자동으로 고치지는 못한다.
- 호출자는 성공적인 중복 응답을 받아 누락을 알아차릴 수 없다.

## 수정 방향

같은 client/key/payload 원본을 발견했을 때 대응 이벤트 존재 여부도 확인한다. 이벤트가 없으면
기존 원본의 수신 시각과 payload로 append를 복구한 뒤 중복 receipt를 반환한다. 검사·복구는
프로세스 lock 안에서 수행하고 회귀 테스트로 원본-only 상태를 고정한다.
