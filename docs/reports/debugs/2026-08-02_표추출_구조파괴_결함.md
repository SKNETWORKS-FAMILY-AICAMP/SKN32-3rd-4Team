# 표 추출이 구조를 파괴한다 — 결함 5건

발견 2026-08-02 · 코덱스 교차검증 · 원본 PDF 실측

> 보장한도·자기부담금·질병분류표(KCD)가 **전부 표에 있다.**
> 표의 **글자**는 조항 본문에 평문으로 들어가지만 **행·열 관계가 없다.**
> "자기부담금 20%"는 검색되는데 **그 20%가 표준형 입원인지 선택형 통원인지 모른다.**
> KCD 표는 더 위험하다 — 질병명과 코드가 잘못 짝지어지면 **오판정**이 된다.

---

## D-1 ★`None` 을 `""` 로 바꿔 **병합 정보를 지운다**

**위치** `scripts/extract/to_page_json.py:172`

```python
"" if c is None else str(c)
```

`Table.extract()` 의 `None` 은 **rowspan/colspan 의 연속 자리**다. 오류가 아니다.
그걸 빈 문자열로 바꾸면 **진짜 빈 셀과 병합 연속 셀을 영원히 구분할 수 없다.**

실측(코덱스, 원본 PDF 직접 확인):

| 문서 | 현상 |
|---|---|
| DB손보 `28db2dc7edb4` p21 | `표준형` 셀 bbox 가 **5개 논리행 전체를 세로로 가로지른다.** 아래 `None` 들은 그 rowspan 의 연속 자리 |
| 메리츠 `e60978d0aad7` p132 | `심장질환` 셀이 `I00`~`I52` **약 40행을 한 번에 span** |

★**파급**: 내가 "빈 셀 54.2%"를 품질 지표로 보고했는데 **틀렸다.**
  그 54.2% 에는 **정상적인 병합 셀이 대량 포함**돼 있다. 지표로 쓸 수 없다.

---

## D-2 표·셀 **bbox 를 통째로 버린다**

같은 파일이 셀 문자열만 남기고 다음을 전부 버린다.

```
table.bbox · table.rows[].cells 의 개별 bbox · header · 추출 전략 · 신뢰도
page.rotation · mediabox/cropbox · 좌표계
```

**파급**: 실패 원인을 **사후에 분석할 증거 자체가 s4 에 없다.**
rowspan 복원·중첩 표 판별·조항 귀속이 전부 막힌다.

---

## D-3 `find_tables()` **기본 전략만** 쓴다

PyMuPDF 는 `lines` · `lines_strict` · `text` · `explicit` 와 축별 혼합, `clip`, `add_lines` 를 제공하는데
코드는 인자 없이 호출한다. 표마다 맞는 전략이 다르다.

코덱스 실측:

| PDF·쪽 | `lines` | `lines_strict` | `text` | 적합 |
|---|---|---|---|---|
| 삼성생명 `f8f2…` p31 | 정상 3×2 | 중복 후보 | 72×7·빈칸 63% | `lines` |
| 삼성생명 `203260…` p28 | 7×2·11×4 빈칸多 | **3×2·5×4 개선** | 64×7 | `lines_strict` |
| DB `02aa…` p53 용어표 | **0** | **0** | 63×10 가짜격자 | crop+좌표 |
| 흥국화재 `ff052…` p109 KCD | **2×3 (22행 붕괴)** | 동일 | 77×6·빈칸 71% | 좌표 `explicit` |

## D-4 ★선이 있는데도 표를 놓친다 — **`get_drawings()` 에 남아 있다**

`find_tables()` 는 선을 **격자로 엮지 못하면** 표를 통째로 놓친다.
그런데 **선 자체는 `page.get_drawings()` 에 그대로 있다.**

실측(내가 재현, 흥국화재 `ff0521a99902` p109):

```
find_tables()          2행 × 3열          ← 22행 표가 붕괴
get_drawings() 세로선   66.13 | 86.49 | 165.44 | 445.88
그 선을 열 경계로 쓰면   42행 × 3열 · 단어배정 100% · 첫열 1,2,3… 단조증가 ✓

  1 | 심장질환   | I20~I25, I26~I28
  2 | 뇌혈관질환 | I60~I69 / G45, G46, Q28
  3 | 당 뇨 병   | E10~E14 / O24, H28.0, H36.0
```

**격자 조립에 실패해도 열 경계는 살릴 수 있다.** 지금은 그냥 버린다.

## D-5 조항에 **표 개수만** 남긴다

**위치** `scripts/extract/to_clauses.py` — `tables_on_pages: {"23": 1}`

셀 내용이 조항으로 넘어가지 않는다. 같은 페이지에 조항이 여럿이면 **어느 조항 것인지도 모른다.**

> 이건 의도된 설계다 — 독스트링이 *"표가 어느 조항에 속하는지 **추정하지 않는다**"* 고 선언했다.
> 원칙은 옳다. 다만 **결과적으로 보장한도 표가 판정에 도달하지 못한다.**
> 추정 대신 **문서 흐름상 포함 관계**(조항 구간 안에 완전히 들어오는 표만 귀속)로 풀어야 한다.

## 내가 잘못 보고했던 것 (정정)

| 내가 말한 것 | 실제 |
|---|---|
| "빈 셀 **54.2%**" | D-1 때문에 **정상 병합 셀이 포함된 값.** 품질 지표가 아니다 |
| "500자 이상 행 2개 이하 = **6.5% 실패**" | 코덱스가 57쪽·59표를 원본으로 재검사: **30표(50.8%)에 실제 자식 표가 들어 있었다.** wrapper·중첩이지 실패가 아니다. `행≤2 && 500자` 는 **실패 판정이 아니라 검사 신호** |
| "pdfplumber 로 바꾸면 되나" | PyMuPDF `find_tables()` 가 **pdfplumber 에서 포팅**된 것이라 같은 탐지 모델. 자동 해결 가능성 낮다 |

## 수정 방향 (합의됨)

```
1. clip 자동 검출
2. 선 연결요소 기반 패널 분리
3. 패널별 열 추정
4. 행 / 논리레코드 분리
5. span 추론
```

★**도구 교체가 답이 아니다.** 실측으로 확인:

| 케이스 | `find_tables()` | OpenDataLoader v2.0 | 좌표+선 복원 |
|---|---|---|---|
| 흥국화재 KCD (선 O) | 2×3 붕괴 | 27×3 | **42×3 · 배정 100%** |
| DB 용어정의표 (rot90·무테두리·2패널) | 0표 | **0표** | **패널 2개 분리** |

ODL 은 선 있는 표에, 좌표는 회전·다단에 강하다. **둘 다 후보로 만들고 검증 점수로 고른다.**
