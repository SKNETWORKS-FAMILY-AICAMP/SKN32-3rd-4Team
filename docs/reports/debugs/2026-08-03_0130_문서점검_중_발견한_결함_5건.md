## D1 · `locator` 에 끝 오프셋이 없어 본문을 재구성할 수 없다

**위치** [`scripts/extract/to_clauses.py`](../../../scripts/extract/to_clauses.py) 본문 조립부

```python
b = end_off if p == end_page else len(t)          # 조립에는 end_off 를 쓰고
...
"locator": {"page_from": page, "page_to": end_page, "char_offset": off}
                                                   # ← end_off 를 저장하지 않는다
```

**재현**

```bash
python -c "import json,glob; d=json.load(open(glob.glob('data/structured/*/s6_*/*.clauses.json')[0],encoding='utf-8')); print(d['clauses'][1]['locator'])"
```

**실측** `locator` 키가 `page_from · page_to · char_offset` 3개뿐. `end_off` 는 계산 후 버려진다.

**위험도** — **중.** 판정 자체는 돌아가지만 **검증이 막힌다.**

| 가능 | |
|---|---|
| 시작 앵커 검증 | ✅ |
| 중간 페이지 포함 검증 | ✅ |
| **본문 완전 재구성** | ❌ |
| **조항 끝 경계 기계 검증** | ❌ |

[v5 계획](../../plans/2026-08-02_0812_전처리_v5_개선계획.md)이 *"2단계부터는 인용 정확도로 잰다"* 고
선언했는데 **그 지표를 만들 수 없는 상태**다.

**제안** `locator` 에 `end_offset` 추가(한 줄). 다음 전처리 실행부터 완전 재구성 검증 가능.

## D2 · ~~`page_from` 이 목차 페이지를 가리킬 수 있다~~ → ★**결함 아님. 실측 0건 (2026-08-03 01:45)**

> ★**내가 틀렸다. 아래 원 서술은 기록으로 남기고 결론만 뒤집는다.**
>
> ```
> s5 전량   문서 1,367 · 조항 211,131 · page_from 이 목차 →  0건
> s6 부분   문서   123 · 조항  12,267 · page_from 이 목차 →  0건
> ```
>
> **구조적으로 0이다.** 조 머리 탐지 루프가 목차 페이지를 **먼저 건너뛴다**
> ([`to_clauses.py`](../../../scripts/extract/to_clauses.py) 조 머리 수집부 · `_NUMBERED` 수집부 둘 다):
>
> ```python
> for pg in pages:
>     if pg["page"] in toc_pages:
>         continue          # ← 머리를 아예 안 찾는다
>     for m in _ARTICLE.finditer(t):
> ```
>
> 머리가 목차에서 안 나오므로 `page_from` 이 목차일 수 없다.
> 조립 루프의 `if p in toc_pages: continue` 는 조항이 목차를 **가로지를 때**를 위한 것이지
> 시작점 문제가 아니었다.
>
> ★**원인 — 조립 루프만 보고 상류(머리 탐지)를 안 봤다.**
> 이 세션에서 여섯 번째 오보다. 같은 패턴이다 — **한 곳만 읽고 단정했다.**
>
> **재현**
> ```bash
> python -c "import json,glob; t=b=0
> for f in glob.glob('data/structured/*/s5_*/*.clauses.json'):
>     d=json.load(open(f,encoding='utf-8')); toc=set(d.get('toc_pages') or [])
>     for c in d.get('clauses') or []:
>         t+=1; b+= ((c.get('locator') or {}).get('page_from')) in toc
> print(t,b)"
> ```

<details><summary>원 서술 (틀렸음 — 기록용)</summary>

**위치** 같은 파일. 조립 루프는 목차를 건너뛰는데 `locator` 는 건너뛴 페이지를 그대로 가리킨다.

```python
for p in range(page, end_page + 1):
    if p in toc_pages:
        continue                    # ← 본문에서 빠진다
...
"locator": {"page_from": page, ...} # ← 그런데 여전히 그 페이지를 가리킨다
```

**위험도** — ★**높음.** 인용이 *"12쪽"* 이라고 하는데 본문은 13쪽에서 시작한다.
**인용 쪽수가 틀리면 근거를 못 댄 것과 같다**(CLAUDE.md §0).

**★몇 건인지 아직 세지 않았다.** 세는 것이 다음 작업이다.

**재현(설계)** 각 조항에서 `locator.page_from in doc["toc_pages"]` 인 건수를 센다.

</details>

## D3 · 확정 게이트를 꺼도 **판정 응답에는 경고가 없다**

**위치** [`app/routers/precheck.py`](../../../app/routers/precheck.py) — 경고가
`/v1/support-manifest` 의 `notes` 에만 붙는다. `/v1/prechecks` 의 `warnings` 에는 **없다.**

**재현**

```bash
curl -s localhost:8000/v1/support-manifest | grep -o 'require_confirmed_documents[^,]*'
```

**실측** [`app/core/ports/precheck.py`](../../../app/core/ports/precheck.py)
`REQUIRE_CONFIRMED` 는 기본 켜짐이고 `PRECHECK_ALLOW_UNCONFIRMED=1` 로만 꺼진다. 게이트 자체는 정상.
문제는 **꺼진 상태를 판정 응답만 봐서는 알 수 없다**는 것.

**위험도** — **중.** 시연용으로 껐다가 그대로 두면 미확정 약관으로 답하면서
**응답에는 아무 표시가 없다.** 코드 주석이 *"끄면 응답에 표시한다 — 조용히 미확정 약관으로
답하면 그게 가장 위험하다"* 고 적어놨는데, 그 표시가 **판정 응답에는 없다.**

**제안** `PrecheckResult.warnings` 에도 넣는다.

## D4 · `generation_profiles.json` 내부 모순 + 4세대 종료일이 역산값

**위치** [`config/generation_profiles.json`](../../../config/generation_profiles.json)

**결함 (a) — 자기모순**

```json
"review_status": "unreviewed",          // 파일 헤더
...
{ "generation": 5, "verified": true }   // 개별 항목은 전부 verified
```

헤더는 *"`unreviewed` 인 동안에는 어떤 문서도 CONFIRMED 로 확정할 수 없다"* 고 한다.
**확정 문서 0건의 원인 중 하나일 수 있다.**

**결함 (b) — 4세대 `effective_to` 가 근거 없는 역산값**

```json
{ "generation": 4, "effective_to": "2026-05-05", "verified": true }
```

**실측(1차 출처 확인)** 금융위원회 보도자료(2026-05-04)는
**5세대 판매 개시 2026-05-06 · 16개사(생보 7 · 손보 9)** 만 밝히고
**4세대 판매 종료일은 명시하지 않는다.**

★그리고 역산이 실제로 안 맞는다 — **신한EZ손보는 6월 1일 출시**다.
그 회사는 5/6~5/31 에도 4세대만 팔았다. **4세대 종료일이 회사마다 다르다.**

**위험도** — ★**높음.** 세대가 자기부담금을 정한다(1세대 사실상 전액 ↔ 4세대 급여20%/비급여30%).
회사별 차이를 전역 단일 날짜로 다루면 그 구간 가입자의 세대가 틀린다.

**정정 사항 — 5세대 날짜 자체는 우리가 맞았다.** config 주석의
*"2026-05-06 출시, 손보 9·생보 7 총 16개사"* 가 금융위 발표와 정확히 일치한다.

**제안** ① 금융위 1차 출처 추가 ② `effective_to` 에 "역산값 · 회사별 상이" 표시
③ `verified` / `review_status` 모순 해소

# ★내가 잘못 보고했던 것 5건 — 정정

RULE.md §4.0-5 — *결함 때문에 지표가 틀렸다면 그것도 결함이다.*
아래는 **내 관측 오류**다. 다섯 중 넷은 **낡은 읽기를 그대로 쓴 것**이 원인이다.

| # | 내가 보고한 것 | 사실 | 원인 |
|---|---|---|---|
| 1 | `proviso_delta` 가 전 모델 **None** — "핵심 지표가 안 재졌다" | **재져 있었다.** 키가 `proviso_delta_mean`/`_min`/`blind_count` 다 | 키 이름 착오. 확인 없이 단정 |
| 2 | `/v1/observations` 가 **저장을 안 한다** | `data/external/submissions/` 에 **저장한다** | 세션 초반 읽기를 그대로 씀. 그 사이 구현됨 |
| 3 | 판정 코드가 **확정 절차를 우회한다**(P0) | `REQUIRE_CONFIRMED` **기본 켜짐**. 이미 고쳐져 있었다 | 〃 |
| 4 | LangGraph **미작성** · `app/insurance/` 확인하라 | [`app/workflow/precheck_graph.py`](../../../app/workflow/precheck_graph.py) 에 있다. `app/insurance/` 부재가 정상 | 〃 — ★**팀원이 중복 구현할 뻔했다** |
| 5 | 조항 중복률 **59.7%** | s6 기준 **66.0%**(등장 204,121 / 고유 69,422) | 분모를 s4 로 잰 값을 현행처럼 씀 |

★**4번이 가장 위험했다.** 팀 공유 문서([11_AI_구조_지도](../../handoff/11_AI_구조_지도.md))에
잘못된 경로를 적어놨고, 그대로 뒀으면 `app/insurance/` 에 **중복 구현**이 났다.
2·3·4는 전부 **코덱스가 잡아줬다**(교차검증 2·3라운드).

## 왜 이런 일이 반복됐나 — 원인 하나

**다른 세션이 동시에 코드를 고치는데, 내가 세션 초반의 읽기를 캐시처럼 썼다.**
파일이 20분 만에 생겼다 사라지는 환경에서 **"아까 읽었다"는 근거가 되지 못한다.**

대응으로 [11_AI_구조_지도 §6](../../handoff/11_AI_구조_지도.md) 의 상태표에서
**기능별 ✅/❌ 판정값을 전부 없애고 "확인 명령 + 기대값"만 남겼다.**
