## 3. 원인

`test_s7_chatbot_release.py::_configure` 는 `monkeypatch` 로 `_ACCEPTED_RELEASE` · `_PASSAGES` ·
`_META` · 환경변수 `S7_FACT_ROOT` 를 tmp 경로로 바꾼 뒤 `source._reset_for_tests()` 로 캐시를 비운다.

- `monkeypatch` 가 되돌리는 것 — 속성과 환경변수 ✅
- **되돌리지 않는 것** — `file_glossary_source._cache` (모듈 전역) ❌

그래서 테스트가 끝난 뒤에도 캐시에는 tmp 픽스처가 만든 **가짜 구절 1행**(`content_hash="approved"`)만
남는다. 뒤에 도는 `test_실제_색인이_있으면_동작한다` 는 `_load()` 가 캐시를 그대로 돌려줘
실제 색인(`data/glossary/passages.jsonl` · 16.3MB · 구절 2,739개)을 **보지도 않고** `found=False` 가 된다.

**직접 호출은 정상이다** — 오염이 없는 프로세스에서:

```
도수치료 → found=True total=1207
상해     → found=True total=1115
본인부담금 → found=True total=1070
```

즉 제품 결함이 아니라 **테스트 격리 결함**이다.

## 5. 위험도

**판정·인용에 직접 영향 없음.** 실행 중인 서비스는 프로세스마다 캐시를 한 번만 채우고,
`_reset_for_tests()` 는 테스트에서만 호출된다.

다만 **제출 위험은 컸다.** 심사자가 README 대로 기본 CI 를 돌리면 실패 1건을 본다.
그리고 이 실패는 "용어 검색이 안 된다"처럼 보여서 **제품 결함으로 오해되기 쉽다.**

★단독 실행은 통과하고 전량 실행만 깨지는 종류라, 파일 단위로만 돌려 보면 영원히 안 잡힌다.

## 6. 고침

`tests/test_s7_chatbot_release.py` 에 **끝나고도 비우는** autouse fixture 를 추가했다.

```python
@pytest.fixture(autouse=True)
def _restore_glossary_cache():
    yield
    source._reset_for_tests()
```

★시작 전 비우기(`_configure` 안의 호출)는 그대로 둔다 — 앞선 테스트가 남긴 것을 치우는 역할이고,
이번에 추가한 것은 **내가 남긴 것을 치우는** 역할이라 서로 다른 일을 한다.
