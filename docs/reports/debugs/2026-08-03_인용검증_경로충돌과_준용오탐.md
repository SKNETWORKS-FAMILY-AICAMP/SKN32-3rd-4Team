## 1. 결함 ① — `by_path` dict 충돌

### 위치

```python
def _index(evidence):
    by_handle, by_path = {}, {}
    by_no = defaultdict(list)          # ← v1 버그를 여기서 고쳤다
    for e in evidence:
        if e.handle: by_handle[...] = e
        by_path[_norm_space(e.qualified_no)] = e      # ★여기는 여전히 dict
        ...
```

`_check_one` 의 순서가 ① 손잡이 → ② **`by_path`** → ③ 번호(`by_no`, 모호성 검사 있음) 다.
**②에서 맞으면 ③의 모호성 검사에 아예 도달하지 못한다.**

### 전제가 틀렸다

v2 설계 주석은 이렇게 적고 있다.

> · 핸들이 없으면 **전체 경로**(`보통약관/제9조`)로 맞춘다.

전체 경로가 **문서 안에서 유일하다**는 전제다. 그런데 같은 파일의 다른 곳
(`app/core/usecases/precheck.py` `_dedupe`)에는 이미 반증이 적혀 있다.

> `{sha12}/{qualified_no}` 는 31,085건 충돌한다(문서의 86%) —
> 부 탐지 입도가 특약보다 굵어 다른 특약이 한 라벨에 뭉치기 때문이다.

**같은 저장소 안에서 한쪽은 알고 있고 한쪽은 모른다.**

### 재현 — 실제 s6 문서

```python
# 실행: python - (저장소 루트에서)
import glob, json, collections
from app.core.domain import citation_guard as cg

hit = None
for p in sorted(glob.glob("data/structured/*/s6_*/*.clauses.json")):
    d = json.load(open(p, encoding="utf-8"))
    by = collections.defaultdict(list)
    for c in d.get("clauses") or []:
        qn, t = c.get("qualified_no") or "", (c.get("text") or "")
        if qn and t: by[qn].append(c)
    for qn, cs in by.items():
        if len({c["text"] for c in cs}) > 1:
            hit = (p, qn, cs); break
    if hit: break

p, qn, cs = hit
ev = [cg.EvidenceClause(qualified_no=c["qualified_no"], text=c["text"]) for c in cs]
r = cg.verify(cited_clauses=[qn], evidence=ev, answer_text="")
print(r.ok, r.checks[0].resolution.value, len(r.checks[0].candidates))
print(r.checks[0].matched.text[:44])
```

★**부 이름까지 정확히 썼는데도** 세 조항 중 마지막 것이 앞의 둘을 덮었고,
`ambiguous` 가 아니라 **`exact`** 로 통과했다. `candidates` 도 비어 있어
"어느 것인지 모른다"고 되물을 기회조차 없다.

주제가 **부활**과 **알릴 의무**로 서로 다르다. 인용문 대조(`_with_quote`)를 하더라도
덮어쓴 조항의 본문과 맞추므로, 틀린 근거가 "원문 확인됨"으로 나온다 —
**v1 의 `by_key` dict 붕괴와 같은 실패 방식이다.**

### 규모 (s6 전량 1,367문서 · 204,098조항)

```
내용이 다른데 qualified_no 가 같은 조항을 가진 문서   1,198 / 1,367  (87.6%)
그런 라벨에 속한 조항                                 75,537 / 204,098 (37.0%)
최악: 한 라벨에 서로 다른 내용 25개 — '(비갱신형/갱신형) 특별약관/3.'
```

### 언제 터지나

손잡이(`E001`)로 인용하면 `by_handle` 에서 정확히 갈린다. 문제는 **LLM 이 손잡이를 안 쓸 때**다.
그런데 이 검증기의 존재 이유가 첫 줄에 적혀 있다.

> ★왜 필요한가 — **프롬프트는 방어선이 아니다**

프롬프트를 무시하는 모델을 잡으려고 만든 장치가, 프롬프트를 무시하면 뚫린다.

팀 저장소 쪽은 더 나쁘다 — `precheck_graph.build()._retrieve` 가 `qualified_no` 를
아예 안 채워 `article_no`(`제9조`, 부 이름 없음)로 떨어진다. 충돌이 가장 잘 나는 모양이다.

### 수정 방향

`by_path` 도 **list 로 바꾸고, 후보가 2개 이상이면 `AMBIGUOUS`** 로 낸다.
`by_no` 에 이미 있는 규칙(`uniq = {e.qualified_no for e in cands}`)과 같은 처리인데,
경로 층에서는 **내용이 다른지**로 접어야 한다 — 같은 조항이 청크로 쪼개진 것은 1개로 본다.

```python
by_path: dict[str, list[EvidenceClause]] = defaultdict(list)
...
cands = by_path.get(key, [])
if len({e.text for e in cands}) > 1:
    return CitationCheck(raw, Resolution.AMBIGUOUS,
                         candidates=tuple(sorted({e.qualified_no for e in cands})))
```

★**`qualified_no` 를 유일 키로 만들려 하지 마라.** 그건 전처리의 부 탐지 입도 문제이고,
검증기가 감당할 일이 아니다. 검증기는 **모르면 모른다고** 하면 된다.

**이 수정안을 실제 s6 문서로 돌려 확인했다.**

```
같은 라벨 3개(내용 3종)   현재: exact  →  제안: ambiguous
라벨이 유일할 때          제안: exact                    ← 정상은 계속 통과한다
```

## 2. 결함 ② — 준용 조항에서 미선언 오탐

### 위치

```python
mentioned = {f"제{...}조" for m in _MENTION.finditer(answer_text or "")}
undeclared = sorted(mentioned - declared)
...
ok = ... and not undeclared          # ← fail-closed
```

`declared` 는 인용으로 선언한 것과 **해소된 근거 자신의 번호**만 담는다.
그런데 약관 조항은 서로를 부른다.

### 재현

```python
from app.core.domain import citation_guard as cg
ev = cg.make_handles([cg.EvidenceClause(
    qualified_no="보통약관/제9조",
    text="회사는 제3조(보험금의 지급사유)에서 정한 사유가 발생한 경우 보험금을 지급합니다")])
r = cg.verify(cited_clauses=["E001"], evidence=ev,
              answer_text="제9조에 따라 보상됩니다. 다만 제3조에서 정한 지급사유를 충족해야 합니다.")
print(r.ok, r.undeclared_mentions, r.reason_code)
```

```
ok=False   미선언=['제3조']   reason_code=undeclared_citation
```

근거 조항의 문장을 **그대로 옮겨 적기만 해도** 그 안의 `제3조` 가 미선언으로 잡혀 기권한다.
근거로 준 조항 자신이 부르는 번호인데도 그렇다.

### 규모 (s6 전량)

```
조항 204,098 중 **자기 번호가 아닌 '제N조' 를 본문에 담은 것**  90,428  (44.3%)
```

절반에 가깝다. 이대로 LLM 을 붙이면 **정상 답변의 상당수가 근거를 대고도 폐기**된다.

### 왜 이게 문제인가 — 기권은 안전한데?

CLAUDE.md §0 은 **"근거를 못 대면"** 판정하지 말라고 한다.
이 경우는 근거를 **댔는데** 폐기하는 것이다. 방향이 다르다.

그리고 실무적으로 더 나쁘다 — 오탐이 잦으면 다음 사람이
**"이 검사 꺼 두자"** 로 간다. 그러면 결함 ①까지 함께 풀린다.

### 수정 방향

`declared` 에 **근거로 넘긴 조항들의 본문에 등장하는 번호**를 더한다.

```python
for e in evidence:                       # 우리가 준 근거가 스스로 부르는 번호
    for m in _MENTION.finditer(e.text):
        declared.add(f"제{int(m.group(1))}조" + (f"의{int(m.group(2))}" if m.group(2) else ""))
```

이러면 "근거 안에서 언급된 조항을 답변이 따라 말한 것"은 통과하고,
**근거 어디에도 없는 조항을 답변이 지어낸 것**은 여전히 잡힌다 — 원래 막으려던 게 그것이다.

**이 수정안도 돌려서 확인했다.** 막으려던 것을 계속 막는지가 핵심이다.

| 답변 | 현재 | 제안 |
|---|---|---|
| `제9조에 따라… 다만 **제3조**에서 정한 지급사유를…` (근거가 부르는 조항) | `ok=False` ← 오탐 | **`ok=True`** |
| `제9조에 따라… 또한 **제77조** 특칙에 따라 전액 지급됩니다` (지어냄) | `ok=False` | **`ok=False`** · 미선언 `['제77조']` |

근거 본문 어디에도 없는 `제77조` 는 여전히 잡힌다.

## 3. 두 결함의 공통점

둘 다 **약관의 구조를 검증기가 단순하게 가정**해서 생겼다.

- ① `qualified_no` 가 문서 안에서 유일하다 → **아니다**(87.6% 문서에서 충돌)
- ② 답변에 나온 조 번호는 곧 인용 선언이다 → **아니다**(44.3% 조항이 남을 부른다)

v1→v2 재작성은 v1 의 **증상**(`_clause_key` 가 부를 뗀다)을 고쳤지만,
**같은 가정**(라벨이 조항을 유일하게 가리킨다)은 그대로 남았다.

## 4. 위험도

| 결함 | 위험도 | 이유 |
|---|---|---|
| ① | **높음** | fail-open. 틀린 근거가 "검증됨"으로 나온다. 우리 제1원칙을 정면으로 어긴다 |
| ② | 중 | fail-closed 라 사용자가 손해 보진 않는다. 다만 ①을 풀어 버리는 압력이 된다 |

지금 당장 서비스에 영향은 없다 — `precheck.py:340` 이 밝혀 두었듯 **호출부가 아직 없다**
(`run()` 은 LLM 없이 규칙만으로 판정한다). **LLM 을 붙이기 전에 고쳐야 한다.**
