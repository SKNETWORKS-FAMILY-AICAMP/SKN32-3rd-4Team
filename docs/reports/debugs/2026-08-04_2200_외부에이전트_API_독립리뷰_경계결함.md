# 외부 에이전트 API 독립 리뷰 경계 결함

- 발견일: 2026-08-04
- 방법: 구현자 외 3개 읽기 전용 리뷰 트랙 + 회귀 테스트 대조
- 상태: 수정 전 기록

## 확인된 결함

1. **보호/공개 observation provenance 충돌**
   - 공개 `/v1/observations`가 임의 `client_ref`를 받고 보호 경로와 같은 파일 namespace를 쓴다.
   - 공개 호출자가 등록 client ID와 추측한 key를 먼저 쓰면 보호 제출이 충돌할 수 있고, 저장된
     원본만으로 어느 채널에서 인증돼 들어왔는지 구분할 수 없다.
2. **멱등키·client 경로 변환 충돌**
   - 보호 헤더는 `.`·`~`와 최대 128자를 허용하지만 파일 token은 문자를 제거하고 64자로 자른다.
   - client ID도 경로에서 40자로 잘려 서로 다른 논리 identity가 같은 파일 namespace가 될 수 있다.
3. **배포 전 무키 public 재시도 호환성**
   - schema에 `idempotency_key=None`이 새로 추가되면 내용 기반 hash 입력이 달라져, 기존 payload와
     같은 요청도 새 key로 계산될 수 있다.
4. **보호 precheck의 KCD 원문 knowledge-gap 기록**
   - 공개 라우터 재사용 경로가 `no_evidence`에서 보험사·KCD 원문을 SQLite 지식갭에 쓴다.
   - agent audit 테이블은 안전해도 전체 보호 요청의 “의료정보 원문 로그 금지” 계약은 깨진다.
5. **readiness 필수 테이블 누락**
   - 인증 로그와 멱등 테이블이 없어도 ready=true가 될 수 있다.
6. **MCP invalid outcome 오류 계약 이탈**
   - outcome을 Literal로 강화했지만 MCP DTO 생성이 구조화 오류 wrapper 밖에 있어 Pydantic 예외가
     그대로 누출된다.
7. **보호 API 오류/OpenAPI 계약 불완전**
   - 기존 HTTP 라우터 함수를 직접 부르는 façade 때문에 일부 422/503이 `{detail}` 형태로 나가며,
     support/terms 응답은 strict response schema가 없다.
8. **멱등 lease·마이그레이션·DB 권한 경계**
   - stale 예약 takeover에 lease token이 없어 늦은 worker가 새 worker의 완료 상태를 덮을 수 있다.
   - rate limiter가 client 전체 행을 잠가 서로 다른 subject/operation도 직렬화한다.
   - audit/auth/rate 원장은 runtime `postgres`가 수정·삭제할 수 있어 append-only가 권한으로 강제되지 않는다.
   - 최초 ledger 생성과 DB 생성의 check-then-act가 advisory lock 밖이라 동시 초기화가 실패할 수 있다.
   - 거절 event 무한 증가, allowed partial index·retention/prune 부재가 트래픽 자체를 DB 비용으로 만든다.
   - caller가 정한 Idempotency-Key 원문이 agent DB에 저장돼 PII-free 설명과 충돌한다.

## 수정 방향

- 보호 observation 파일 저장 channel을 `registered_agent` 하위 namespace로 분리하고 서버가
  provenance를 강제한다. 공개 body로 이 channel을 선택할 수 없게 한다.
- 논리 idempotency key/client identity와 파일 token을 분리하고 token에는 전체 입력 hash suffix를
  붙인다. 기존 레코드는 top-level identity 대조로 읽는다.
- 내용 hash에서는 값이 없는 선택 메타필드를 제외해 배포 전 요청과 호환한다.
- 보호 façade가 호출할 때 knowledge-gap 기록을 끄는 명시적 내부 옵션을 두고, 필요한 경우
  비식별 별도 gap만 기록한다.
- readiness, MCP 오류 wrapper, HTTP 충돌/namespace/legacy 재시도 테스트를 보강한다.
- forward `002`에서 lease CAS, HMAC idempotency key, bucket advisory lock, retention/index,
  owner/runtime/admin role 권한을 보강한다. 이미 적용한 `001`은 수정하지 않는다.
- application façade를 HTTP 라우터에서 완전히 분리하고 전 응답 DTO를 닫는 작업은 더 큰 리팩터링이므로
  이번 기반 구현에서는 오류 응답 정규화·response model 보강까지 하고 후속 구조 개선으로 남긴다.
