# 인용 쪽 「80쪽 어긋남」 2건 — **약관이 아니라 채점기가 틀렸다**

- 날짜: 2026-08-03
- 발견: `docs/reports/2026-08-03_검색품질_지표_설계.md` §3.4.1 이 "불일치 2건 = 결함"으로 보고.
  그 세션은 파일 3개 제약으로 결함 리포트를 못 썼고(그 리포트 §5-7 · §6-1), 이 리포트가 그 몫이다
- 상태: **재현·전량 실측 완료 · 코드는 고치지 않음**(지시 범위 밖). 원인만 짚는다
- 규칙: RULE.md §4.0 (위치·재현·실측·위험도·**내 오보 정정**)

## 0. 결론 먼저

**보고된 "동양생명 인용 쪽 80쪽 어긋남"은 실재하지 않는다.**
`page_from` 은 두 건 모두 **맞다.** PDF 원문으로 확인했다.

틀린 것은 채점기다. 조항 앵커(본문 앞 30자)가 **쪽 경계에서 갈라졌는데**,
채점기가 그것을 "검증불가"가 아니라 **"불일치"로 세고**,
같은 문서 안 **다른 조항 등장**에서 같은 문장을 찾아 "실제 쪽은 176쪽"이라고 **지어냈다.**

전량 실측: 조항 195,659개 중 `page_from` **불일치 0건.**
현재 규칙이 불일치로 세는 것은 **7건**이고 **7건 모두 같은 오탐**이다(전부 동양생명 3문서).

## 1. 위치

```
scripts/eval/retrieval_quality.py:561-570   _score_pages() 분류 분기   ← 결함
scripts/eval/retrieval_quality.py:294-309   page_probes 앵커 생성      ← 앵커 유일성 미보장
scripts/eval/retrieval_quality.py:118-124   HEAD_ANCHOR=30 주석        ← 코드와 어긋난 설명
```

문제의 분기(`561-570`) 원문:

```python
if pf in pages and head in pages[pf]:
    hit_f += 1
else:
    where = [pg for pg, t in pages.items() if head in t]
    if where:
        wrong_f += 1                                     # ← 여기
        off_by[min((w - pf for w in where), key=abs)] += 1
    else:
        #: 앵커가 쪽 경계를 넘어갔거나 원문 재현이 다르다 → **못 쟀다.**
        unver_f += 1
```

**빠진 것이 둘이다.**

| # | 빠진 것 | 결과 |
|---|---|---|
| ① | `pt`(=`page_to`)를 **한 번도 안 쓴다.** 조항이 `pf`~`pt` 에 걸쳐 있는데 `pages[pf]` 한 쪽만 본다 | 쪽 경계에서 갈라진 앵커가 전부 `else` 로 떨어진다 |
| ② | 앵커의 **유일성을 확인하지 않는다.** `where` 에 걸린 쪽이 *이 조항의* 등장인지 묻지 않는다 | 같은 문장을 가진 **다른 조항**을 "실제 쪽"으로 보고한다 |

①만 있으면 `unver_f`(검증불가)로 흘러 정직하게 "못 쟀다"가 된다.
①과 ②가 **겹칠 때만** 없는 결함이 있다고 보고된다.
그래서 2,828건의 걸침 중 **7건만** 불일치로 잘못 샜다.

★`118-124` 주석은 *"N 을 늘리면 앵커가 쪽 경계를 넘어가 **검증불가**가 는다"* 라고 적어 놓았다.
설계 의도는 맞았는데 **코드가 그렇게 안 되어 있다.** 주석이 결함을 가렸다.

### 2.4 전량 재측정 (약 3분)

```bash
export PYTHONIOENCODING=utf-8
python - <<'EOF'
import json, re
from collections import Counter
from pathlib import Path
BR = str.maketrans({"[":"(","]":")","【":"(","】":")",
                    "（":"(","）":")","［":"(","］":")"})
npg = lambda s: re.sub(r"\s+", "", (s or "").translate(BR))
c = Counter()
for ins in sorted(Path("data/structured").iterdir()):
    cdir = ins / "s6_pymupdf-1.28.0"
    if not cdir.is_dir():
        continue
    for cf in sorted(cdir.glob("*.clauses.json")):
        pfile = Path("data/extracted") / ins.name / "s5_pymupdf-1.28.0" / f"{cf.name[:12]}.json"
        if not pfile.exists():
            c["쪽파일없음"] += 1          # 조용한 스킵 금지 — 센다
            continue
        d = json.loads(cf.read_text(encoding="utf-8"))
        pages = {p["page"]: npg(p.get("text") or "")
                 for p in json.loads(pfile.read_text(encoding="utf-8")).get("pages", [])}
        for cl in d.get("clauses") or []:
            loc = cl.get("locator") or {}
            pf, pt = loc.get("page_from") or 0, loc.get("page_to") or 0
            body = npg(cl.get("text") or "")
            if len(body) < 30:
                c["본문짧음_제외"] += 1
                continue
            head, c["대상"] = body[:30], c["대상"] + 1
            if pf in pages and head in pages[pf]:
                c["적중"] += 1
                continue
            span = "".join(pages.get(p, "") for p in range(pf, pt + 1))
            where = [g for g, t in pages.items() if head in t]
            if head in span:                      # ★현재 코드에 없는 갈래
                c["쪽경계걸침"] += 1
                if where:
                    c["★현재규칙은_이걸_불일치로_센다"] += 1
                # page_from 이 정말 시작 쪽인가 — pf 쪽 끝이 앵커 앞부분이어야 한다
                if any(pages.get(pf, "").endswith(head[:k]) for k in range(30, 0, -1)):
                    c["pf쪽_끝에서_갈라짐(정상)"] += 1
            elif where:
                c["불일치_교정후"] += 1
            else:
                c["검증불가_진짜"] += 1
print(json.dumps(dict(c), ensure_ascii=False, indent=1))
EOF
```

## 4. 위험도

### 4.1 인용 신뢰성 — **낮음.** 보고된 위험이 실재하지 않는다

이 서비스는 "약관 몇 쪽"을 잘못 대면 사용자가 근거를 못 찾는다.
그래서 §3.4.1 의 "사람이 그 쪽을 펴도 그 조항이 없다"는 **정확히 옳은 위험 인식**이었다.
다행히 **그 일은 일어나지 않는다.** `page_from` 은 전량 195,659건에서 어긋난 사례가 없다.

경미한 잔여 위험은 `page_to` 한 쪽 과다 5,302건(2.71%)뿐이다.
`96–97쪽` 이라고 대야 할 것을 `96–98쪽` 으로 댄다. **시작 쪽은 맞으므로 사람은 조항을 찾는다.**

### 4.2 ★진짜 위험 — **거짓 결함 보고가 오진 위의 수정을 부른다**

- 앞선 리포트가 §3.4.1 을 **"결함이다"** 로 못 박았고, §6 다음작업 **1순위**로
  "동양생명 쪽수 80쪽 어긋남 2건" 결함 리포트를 지목했다.
  다음 사람이 그대로 받으면 **없는 버그를 고치러 조항 조립기(`page_from` 산출)를 건드린다.**
  `CLAUDE.md` §3 — **오진 위에 수정을 쌓지 않는다.** 이 리포트가 그 앞을 막는 것이 목적이다.
- 「80쪽」은 **딱 떨어지는 숫자**다(#1 +80, #2 −80). `CLAUDE.md` §3 은
  *"딱 떨어지는 숫자는 프로토콜을 의심한다"* 고 한다. 실제로 데이터가 아니라
  **동양생명 약관의 특약 반복 주기**가 만든 숫자였다.

### 4.3 반대 방향 — 이 채점기는 **진짜 오류를 놓칠 수 있다**

걸침 2,828건(1.45%)은 현재 규칙에서 `page_from` 이 틀려 있어도
"검증불가"로 흘러 **지표에 안 잡힌다.** 지표 ③ 의 검정력이 그만큼 비어 있다.
지금은 교정 측정으로 0건임을 확인했지만, **전처리가 바뀌면 이 구멍으로 회귀가 샌다.**

## 6. 원인만 짚는다 (코드 수정은 이 세션 범위 밖)

고치려면 `_score_pages()` 에 갈래 **하나를 더** 넣어야 한다. 지금은 세 갈래인데 넷이어야 한다.

| 갈래 | 조건 | 지금 |
|---|---|---|
| 적중 | `head in pages[pf]` | 있다 |
| ★**쪽경계걸침** | `head in "".join(pages[pf..pt])` **이고** `pages[pf]` 끝이 `head` 앞부분 | **없다** → 불일치/검증불가로 흩어진다 |
| 불일치 | 위 둘 다 아닌데 다른 쪽에 있다 | 있다(과대) |
| 검증불가 | 어디에도 없다 | 있다 |

앵커 유일성도 함께 봐야 한다. `where` 가 여럿이면 **"어긋났다"고 단정할 수 없다** —
그 문서에 같은 문장이 여러 번 나온다는 뜻이다. `content_hash` 로 형제 등장을 먼저 걸러야 한다.

★그리고 **`page_to` 한 쪽 과다 5,302건**은 이 결함과 별개다. 별도 조사가 필요하다.
