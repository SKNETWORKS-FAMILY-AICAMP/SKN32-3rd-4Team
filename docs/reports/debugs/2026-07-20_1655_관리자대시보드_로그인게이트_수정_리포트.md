# 관리자 대시보드 — 미인증 상태에서 본문 노출되던 문제 수정

- 작성일시: 2026-07-20 16:55
- 계기: 사용자 지적 "http://localhost:8080/static/admin.html — 여기에 관리자 로그인이
  되어있지 않은데 왜 UI 보여주지? 로그인 완료해서 토큰 받아야 보여줘야 하는 거 아니야?"

## 1. 문제
직전 커밋(`1ca991f`)의 Codex 대시보드는 로그인 전에도 `<header class="app-header">`와
`<main class="dashboard">` 전체(요약 카드 3개·주문 테이블·이벤트 타임라인·지식갭 패널)를 항상
렌더링하고 있었다. `authNotice` 배너 하나만 위에 얹혀 "로그인 필요"라고 알릴 뿐, 그 아래
카드들은 "확인 중"/"–"/"불러오는 중입니다" 같은 플레이스홀더 텍스트로 항상 표시돼 있었다.
실제로 API를 호출하진 않았지만(코드상 `hasToken()`이 false면 `refreshDashboard()`를 아예
안 부름 — 데이터 누출은 없었음), 화면만 보면 "대시보드가 로딩 중"처럼 보여 로그인 없이도
관리자 화면 레이아웃 전체가 그대로 노출되는 것처럼 읽혔다. 정당한 지적이었다.

## 2. 수정
`app/static/admin.html`에 로그인 전용 게이트 `#loggedOutGate`를 추가하고,
`#dashboardHeader`/`#dashboardMain`에 `hidden` 속성 기본값을 줬다(초기 마크업 자체가
"로그인 전 = 대시보드 숨김"을 기본값으로 갖도록 — 무폴백 설계와 같은 방향: 인증 안 된 상태를
스켈레톤 UI로 가리지 않고 명시적으로 보여준다).

`app/static/admin.js`의 `synchronizeAuthentication()`(로그인/로그아웃/초기로드마다 호출되는
단일 진입점)에서 토큰 유무에 따라 세 요소를 함께 토글하도록 확장:
```js
elements.loggedOutGate.hidden = authenticated;
elements.dashboardHeader.hidden = !authenticated;
elements.dashboardMain.hidden = !authenticated;
```
403(로그인은 됐지만 관리자 아님) 상태는 토큰이 있으므로 `authenticated=true`라 대시보드
본문은 그대로 보이고 각 패널이 "불러오기 실패"를 표시한다 — 이건 의도된 동작이라 손대지
않았다(RBAC 사다리 검증 화면으로 이미 확인됨).

  09~12 재촬영.
