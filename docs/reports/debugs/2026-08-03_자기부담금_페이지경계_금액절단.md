# 자기부담금이 **쪽 경계에서 잘려** 15,000원이 5,000원이 된다

- 날짜: 2026-08-03
- 상태: **차단 완료(안 C).** 근본 수정(안 A)은 미착수
- 위험도: **높음 — `parse_status="ok"` 로 나가는 오답이다**
- 규칙: RULE.md §4.0 (위치·재현·실측·위험도·정정)

> ★**이 리포트가 늦었다.** 결함은 L3 1차 리포트(§4.5-①)에서 이미 언급됐는데
> `docs/reports/debugs/` 에 남기지 않고 두 세션을 넘겼다. RULE.md §4.0 이
> 정확히 그걸 막으려고 신설된 조항이다. **세 번째다.**

---

## 1. 위치

```
scripts/extract/coverage_limits.py::_krw_lines   (줄 병합은 있으나 쪽 경계는 못 넘는다)
scripts/extract/coverage_limits.py::parse_page   (계약이 "한 쪽"이다)
```

`_krw_lines` 독스트링에 **줄 경계** 병합은 이미 적혀 있다 —

> ★단위가 줄 끝에 걸린 경우(`1만` / 다음 줄 `5천원`)는 **이어 붙인 뒤** 읽는다.

그런데 **쪽 경계**는 다루지 않는다. `parse_page(pg)` 가 페이지 하나만 받기 때문이다.

## 2. 재현

```bash
export PYTHONIOENCODING=utf-8
python - <<'PY'
import sys, json, glob; sys.path.insert(0, '.')
import fitz
man = {}
for g in glob.glob('data/raw/manifests/*.jsonl'):

d = fitz.open(man['224bd44994c3'])
print('p5 끝:', repr(d[4].get_text()[-120:]))
print('p6 앞:', repr(d[5].get_text()[:120]))
PY
```

## 3. 실측 — 원문이 두 쪽에 걸쳐 있다

**p5 끝**
```
…「의료법」 제3조 제2항 제3호에 따른 종
1만
```

**p6 앞**
```
합병원, 병원, 치과병원, 한방병원, 요양병원
5천원과 보상대상 의료비의 20%중 큰 금액
```

이어 붙이면 원문은 이렇다.

```
「의료법」 … 제3호에 따른 종합병원, 병원, 치과병원, 한방병원, 요양병원
1만 5천원과 보상대상 의료비의 20%중 큰 금액
```

**참값 15,000원.** 파서는 p6 만 보고 `5천원` → **5,000원**으로 읽는다.
기관 이름도 `합병원`(← `종합병원`의 꼬리)으로 시작해 잘린 것이 보인다.

### 범위

| | 값 |
|---|---:|
| `기관종별=병원급 · 공제액=5,000` 인 레코드 (**전량**) | **10건** |
| 그중 `parse_status` | **전부 `ok`** |

> ★★**내 숫자도 두 번 틀렸다.**
> L3 1차 리포트 §4.5-① 은 **4건**, 내가 처음 센 것은 **26건**, 전량 실측은 **10건**이다.
> 26 은 `kbinsure` 만 앞에서 40파일 제한으로 훑으면서 **같은 레코드를 여러 번 센 값**이었다.
> **10 이 전량 기준이다.** 숫자를 말할 때 분모와 범위를 함께 적는다(CLAUDE.md §4).

참고: 정상 기대값은 통원 자기부담금 `의원 1만 · 병원 1.5만 · 상급종합 2만` 이다.
같은 문서 p5 에 `1만원과 … 20%중 큰 금액`(의원급)이 온전히 있고,
p6 에 `2만원`(상급종합)이 있다. **중간 값 하나만 틀린다.**

## 4. 위험도 — **높음**

세 가지가 겹친다.

1. **`parse_status="ok"` 로 나간다.** 판정이 "확실한 값"으로 받는다.
   `unparsed` 였다면 기권했을 텐데 그러지 않는다.
2. **금액이 1/3 로 줄어든다.** 자기부담금 15,000 → 5,000 이면
   보험금 계산이 **가입자에게 유리한 쪽으로 틀린다** — "덜 부담한다"고 답한다.
   그러고 실제 청구에서 뒤집히면 그게 이 서비스가 가장 피해야 할 실패다(CLAUDE.md §0).
3. ★**축 채우기 뒤 더 위험해졌다.** 2026-08-03 작업으로 `입통원=통원`·`상해질병=상해`
   라벨이 **사실로**(`inferred=false`) 붙었다. 값은 여전히 틀린데 **더 그럴듯해 보인다.**

## 5. 왜 안 잡혔나

- `word_coverage`·`parse_status` 어느 것도 쪽 경계 절단을 보지 못한다
- 원문 대조 표본(`--handcheck` 48건, 무작위 43건)이 **파서가 이미 성공한 자리**에서 뽑혔다.
  실패한 자리를 안 봤으니 실패가 안 보였다
- 기관 이름이 `합병원` 으로 잘린 것이 **눈에 보이는 신호**인데 아무도 안 봤다

## 6. 고치는 방법 (미착수)

| 안 | 내용 | 비용 |
|---|---|---|
| **A** | `parse_page` → `parse_pages(prev, cur)` 로 계약 변경. 앞 쪽 꼬리를 이어 붙여 읽는다 | 중. 호출부 전부 손봐야 함 |
| **B** | 값 검증 규칙 — 기관등급별 표준값(`의원 1만 · 병원 1.5만 · 상급종합 2만`)과 **다르면 `partial` 로 내린다.** 표준값을 채우지 않고 **의심 표시만** 한다 | 소. 즉시 가능 |
| **C** | 잘린 신호 탐지 — 기관 이름이 `합병원`·`원,` 처럼 **어절 중간에서 시작**하면 그 행을 `unparsed` | 소 |

★**B 를 표준값으로 "고치는" 것은 금지다.** 그건 지어내는 것이다(CLAUDE.md §1).
의심스러우면 **비워 두고 기권**한다.

권고: **C → B 순으로 즉시 막고, A 는 별도 작업으로.**
지금은 10건이 `ok` 로 나가고 있으므로 **막는 것이 먼저다.**

## 7. 조치 결과 (2026-08-03 추가)

**안 C 를 넣었다** — `_looks_truncated()`. 표준값으로 고치지 않고 **의심 표시만** 한다.

신호 셋 (실측으로 정했다):

| 모양 | 예 | 왜 절단인가 |
|---|---|---|
| 구두점으로 시작 | `, 병원, …` | 앞이 확실히 잘렸다 |
| 사전 말의 **꼬리**로 시작 | `합병원, …` `원, …` | `종합병원` 의 꼬리 |
| **첫 두 토막이 같음** | `병원, 병원, 치과병원, …` | 원문은 `종합병원, 병원, …`. **같은 기관을 두 번 쓰는 약관은 없다** |

세 번째는 처음에 놓쳤다 — `병원` 이 사전에 있는 말이라 통과했다.
**중복 자체가 절단의 지문**이라는 것을 3건을 열어 보고 알았다.

### 효과 (전량 실측)

| | 조치 전 | 조치 후 |
|---|---:|---:|
| `기관종별=병원급 · 공제액=5,000` 중 `ok` | **10** | **0** |
| 같은 조건 `partial` | 0 | **10** |
| 쪽 경계 절단 의심(전체) | — | **29** |
| 전량 상태 | ok 6,956 · partial 2,342 | ok **6,949** · partial **2,349** |
| 정답셋 `table_gold_check` | 1.000 | **1.000 유지** |

★**`ok` 가 7건 줄었다.** 그게 목적이다 — 틀린 값이 "확실한 값"으로 나가던 것을 막았다.

### 아직 안 한 것

- **안 A**(`parse_pages(prev, cur)`) — 근본 수정. **값을 되찾지는 못했다.**
  지금은 막기만 했고 15,000원을 읽지는 못한다
- **안 B**(기관등급 표준값 대조) — 안 넣었다. C 로 이 케이스가 잡혀서인데,
  다른 모양의 절단은 여전히 못 잡는다
