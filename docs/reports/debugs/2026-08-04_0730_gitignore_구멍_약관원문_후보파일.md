## 4. 왜 안 막혀 있었나

`.gitignore` 는 **파생물이 저작물이라는 것을 이미 알고 있었다.** 주석에 이렇게 적혀 있다.

> PDF 는 `data/raw/insurance_terms/` 로 막아 뒀는데, 그것을 텍스트로 뽑은
> 산출물은 안 막고 있었다. 형식만 바뀌었을 뿐 **내용은 약관 원문 그대로**다.

그래서 `data/extracted/` · `data/structured/` 를 막았다. **그 뒤에 생긴 폴더는 안 막혔다.**

★**같은 실수가 이 저장소에서 세 번째다.**

| 시점 | 무엇 |
|---|---|
| 이전 | `data/exports/s5_clauses.parquet` 이 실제로 **팀 저장소에 올라갔다**(조항 211,131행 + `text`) |
| 이전 | `data/extracted/`·`data/structured/` 가 안 막혀 있었다 |
| **이번** | `data/candidates/` 602파일 — 커밋 전에 잡았다 |

**규칙이 "무엇을 막을까"(deny-list) 방식이라 새 폴더가 생길 때마다 뚫린다.**

## 6. 남은 위험 — 고치지 않았다

★**deny-list 그대로다.** 다음에 `data/` 아래 새 폴더가 생기면 또 뚫린다.
allow-list(`data/*` 를 막고 필요한 것만 `!` 로 되살리기)로 뒤집는 것이 옳지만,
지금 추적 중인 73개 파일의 경로를 전부 확인해야 해서 **이번 작업 범위 밖으로 둔다.**

그때까지의 임시 방어: **`git add -A` 하지 말고 스테이징 건수를 세어 본다.**

```bash
git diff --cached --name-only | grep "/data/" | sed 's|.*/data/||' | cut -d/ -f1 | sort | uniq -c
```
