# s6 부록의 file·PG 근거 집합 불일치

- 발견 시각: 2026-08-03 16:02 KST
- 심각도: P0 — 저장소 backend에 따라 검색 가능한 근거가 달라짐
- 상태: 재현 완료, 계약 결정 필요로 수정 보류

## 위치

- `app/adapters/file_clause_store.py`: `doc["clauses"]`만 읽고 `annexes[]`는 읽지 않는다.
- `scripts/index/build_clause_index.py`: `annexes[]`를 별도 루프로 색인한다.
- s6 전량 부록: 9,342개, ok 문서 부록: 9,158개.

## 재현

1. s6 조항 JSON에서 `clauses`와 `annexes` 개수를 센다.
2. file store의 로딩 루프가 `clauses`만 순회하는지 확인한다.
3. index builder가 `annexes`를 별도로 적재하는지 확인한다.

## 실측과 위험

같은 승인 릴리스라도 file backend는 부록 9,342개를 근거 후보에서 제외하고, PG/index 경로는 포함한다.
더구나 부록에는 조항과 동일한 `citation_eligible`·`statute` 계약이 명확히 적용되지 않는다.

따라서 backend에 따라 같은 질문의 검색 후보와 인용 결과가 달라질 수 있다. 부록을 무조건 살리거나 버리는
수정은 둘 다 위험하다. 별표·부록은 KCD와 한도 표의 핵심 근거일 수 있지만 약관 조항과 locator/번호 계약이 다르다.

## 정정 계획

1. 부록이 판정 근거가 될 수 있는 조건과 인용 locator 형식을 계약으로 먼저 정한다.
2. 조항과 부록을 함께 다루는 공통 eligibility 함수를 만든다.
3. file store·PG store·index builder가 같은 fixture에서 같은 ID 집합을 내는 parity 테스트를 만든다.
4. 계약 전에는 s6 serving 승인과 PG 전환을 보류한다.
