## 2. 재현과 실측

수정 전 실제 명령의 실측 결과:

```powershell
python -m scripts.eval.bench_embedders --report --md
python -m scripts.eval.bench_embedders --report --md --dtype 4bit
python -m scripts.eval.bench_embedders --prefixes --md
python -m scripts.eval.bench_embedders --repro --md
```

- 앞의 세 명령: stdout을 만든 뒤 종료 코드 **2**, `--model 이 필요합니다` stderr
- `--repro`: 종료 코드 **0**
- 기존 감사 시험: **27 passed**였지만 위 결함을 놓침
- 기존 전체 감사: 통과 21 · 확인필요 2 · 실패 **18**

## 3. 원인

1. 출력 전용 분기 두 곳에 `return 0`이 빠졌다.
2. 필수 키의 **존재**와 값의 **유효성**을 같은 것으로 보았다.
3. 생성 영역 부재를 “검사 불가” 경고로만 처리해 감사 성공 가능성을 열어 뒀다.
4. 줄 단위 태그 검사를 문장 단위로 바꿨지만 Markdown 셀과 HTML 줄바꿈 경계를 빠뜨렸다.
5. 동결 대상의 내용을 해시하면서 정체성인 파일명을 넣지 않았다.
6. 감사기의 subprocess mock이 감사 판정은 검사했지만 실제 생성기 디스패처를 실행하지 않았다.

## 4. 위험도

- 생성 명령이 실패해도 stdout이 맞아 보이므로 문서 생성 계약이 정상이라고 오인할 수 있다.
- 생성 블록 삭제·결과 파일 rename·`blind_eps=None`을 동결/감사가 통과시킬 수 있다.
- 제목 표의 값과 ranks 기반 검산 값이 갈라져도 각각 별도 정상으로 보일 수 있다.
- 증거 태그 하나가 같은 표 행의 다른 단정까지 가려 사람 검토 후보가 줄어든다.

브리핑의 모델 선택 근거를 잘못 승인할 수 있으므로 감사 도구 신뢰성 기준에서 **높음**이다.

## 5. 수정과 정정

- 출력 전용 세 모드가 명시적으로 `return 0` 하도록 수정했다.
- `blind_eps`의 정확한 값, 생성 마커 존재, top-level/title 정합을 검사한다.
- Markdown 셀·`<br>` 경계를 분리하되 구두점 없는 일반 한국어 문장을 추측해 자르지 않는다.
- 결과 동결 해시에 파일명·파일명 길이·내용 길이를 포함한다.
- 실제 CLI와 정상/단일 변조본 시험을 추가했다.
