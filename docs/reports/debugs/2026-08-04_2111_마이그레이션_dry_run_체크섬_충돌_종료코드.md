# 마이그레이션 dry-run 체크섬 충돌 종료코드 오류

- 발견 시각: 2026-08-04 21:11 KST
- 대상: `scripts/db/apply.py`
- 상태: 수정 전 재현·원인 기록

## 현상

이미 적용된 마이그레이션 파일의 내용과 현재 파일의 체크섬이 다르면 `--dry-run` 출력에는
`STOP`이 표시되지만 프로세스는 항상 종료코드 `0`을 반환한다.

## 재현 근거

`scripts/db/apply.py`의 dry-run 분기는 각 파일에 대해 다음 표시를 계산한다.

```text
skip  : 적용 이력과 현재 체크섬이 같음
STOP  : 같은 이력 키가 있으나 체크섬이 다름
would : 아직 적용되지 않음
```

그러나 모든 파일을 출력한 뒤 충돌 여부와 무관하게 `return 0`으로 끝난다. 따라서 CI나 운영
점검 스크립트가 표준출력을 별도로 파싱하지 않으면 적용본 변조를 정상 상태로 오인한다.

## 영향

- 신규 `agent` 마이그레이션 트랙을 포함한 모든 트랙에서 체크섬 충돌이 자동 점검을 통과할 수 있다.
- 사람은 `STOP` 문구를 보더라도 호출 프로세스는 성공으로 판단한다.
- 변경 불가 마이그레이션 원칙을 도구가 강제하지 못한다.

## 수정 방향

dry-run 중 체크섬 충돌을 하나라도 발견하면 끝까지 전체 상태를 출력한 뒤 비정상 종료코드를
반환한다. 신규 테스트에서는 정상 `skip/would`와 충돌 `STOP`의 종료코드를 각각 고정한다.
