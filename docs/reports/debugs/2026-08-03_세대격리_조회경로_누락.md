# 세대 격리를 벡터 검색에만 걸고 **PG 조회 경로를 빠뜨렸다**

- 날짜: 2026-08-03
- 발견: 팀원 지적 → 코덱스 3라운드 검토로 확정
- 상태: **수정 완료 · 회귀 테스트 추가**
- 규칙: RULE.md §4.0

---

## 1. 위치

```
app/adapters/pg_clause_store.py   load_clauses() · stats() · search()
```

세 함수 모두 `policy_clause_occurrence` 를 읽으면서 `index_generation` 을 보지 않았다.

## 2. 재현

```bash
python -m pytest -q tests/test_pg_clause_store.py::test_세대_필터가_모든_조회_경로에_걸려_있다
```

수정 전에는 실패한다 — `FROM policy_clause_occurrence` 3곳 중 세대 필터 0곳.

## 3. 실측

DB `mall_vec`, 2026-08-03:

| 세대/종류 | 발생 | 문서 |
|---|---:|---:|
| `s5-mixed/clause` | 158,186 | 1,110 |
| `s6/clause` | 186,615 | 1,288 |
| `s6/annex` | 9,002 | 1,118 |

**한 테이블에 구·신 세대가 함께 있다.** 벡터 `search()` 는 막았는데
PG 조회 경로는 옛 세대를 그대로 돌려줬다.

## 4. 위험도 — 높음 (단, 기본 경로는 아니었다)

`s5-mixed` 조항은 **부록을 본문에 삼킨 상태**다. 그걸 인용하면
`제27조(준용규정)에 따르면 분만은 O80~O84` 처럼 **출처가 틀린 근거**가 나온다. KCD 오인용이다.

완화 요인: `CLAUDE_STORE` 기본값이 `file` 이라 실제 서비스 경로는 아니었다.
**그러나 환경변수 하나 차이다.** 막는 곳이 하나 빠지면 막은 게 아니다.

## 5. 정정

앞서 "s5-mixed 를 격리했다"고 보고했다. **벡터 검색만 격리했고 전부는 아니었다.**
코덱스 최종 판정은 "황색이 아니라 **적색**에 가깝다 — 격리 완료로 선언해서는 안 된다"였다.

## 6. 수정

- `load_clauses()` · `stats()` · `search()` 세 경로에 `index_generation` + `embed_model` 필터
- 회귀 테스트 2건 — SQL 문자열에서 `FROM policy_clause_occurrence` 조회 수와
  `index_generation` 등장 수를 비교한다. **빠진 경로가 생기면 실패한다**
  (DB 없이 도는 테스트다. DB 를 띄워야만 도는 테스트는 CI 에서 조용히 건너뛰어진다)
- 기존 PG 테스트 2건은 이제 **사유를 밝히고 skip** 한다 —
  `현재 프로필(세대 s6 × 모델 jhgan/ko-sroberta-multitask)로 색인된 문서가 없습니다`

## 7. ★기본키에도 넣어야 했다

`upsert_occurrences` 는 `ON CONFLICT DO NOTHING` 이다.
세대가 PK 밖이면 `(hash, sha, no, page)` 가 같은 옛 행 때문에
**새 세대 행이 버려지고** 그 자리는 계속 `s5-mixed` 로 남는다.
검색은 현재 세대만 보므로 **그 조항은 영원히 안 나온다.**
로그에는 "이미 있음"으로 찍혀 정상처럼 보인다 — 가장 위험한 실패다.

현재 PK(확인함):
```
policy_clause_occurrence : content_hash, sha256, qualified_no, page_from, index_generation
policy_clause_chunk      : content_hash, chunk_ix, embed_model
```
