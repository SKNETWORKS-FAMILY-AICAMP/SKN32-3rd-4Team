## 3. 원인과 영향

커머스 CSV는 `legacy/v3_commerce.zip`으로 격리됐지만, 활성 관리 CLI와 공식 README에서
커머스 시더 호출을 제거하지 않았다. 즉 데이터 격리와 호출자 격리가 한 작업으로 끝나지 않아
설치 계약이 갈라졌다. 보험 DB migration 자체에는 커머스 CSV가 필요하지 않는데도 팀원이
애플리케이션 장애로 오해하게 만들었다.

## 4. 수정

- 활성 `seed` 명령·dispatch·`app.db.seed` import 제거
- `app/db/seed.py` 활성 트리에서 제거
- 제거 전 소스와 CLI를 `legacy/v9_commerce_seed_cli.zip`에 보존
- README와 현행 프로젝트 개요의 `seed` 실행 안내 제거
- 데이터 매니페스트에서 커머스 CSV를 역사 자료로 명시
- 임시 SQLite migration, CLI 도움말, 문서, ZIP 내용 해시 회귀 테스트 추가
