# 표 개수를 **부착 횟수**로 보고했다 — 2.1배 부풀림

- 날짜: 2026-08-03
- 발견: D1 정합검사 에이전트가 디스크를 세다가 상태표와 어긋나는 것을 잡음
- 상태: **수치 정정. 세는 코드에 단위 구분 추가**
- 규칙: RULE.md §4.0 (위치·재현·실측·위험도·**내 오보 정정**)

---

## 1. 위치

내가 세던 방식(대화·리포트·`CLAUDE.md` 상태표):

```python
for k in ("clauses", "annexes"):
    for x in doc[k]:
        for t in x.get("tables") or []:
            T += 1                       # ← 부착 횟수를 세고 있었다
```

한 표가 **조항과 부록에 둘 다** 붙으면 2로 센다. 페이지 하나에 걸친 조항이 여럿이면 더 센다.

## 2. 재현


## 3. 실측 — 정정표

| 조항에 실린 표 | 1,313 | **613** | 2.14배 |

앞선 보고에서 "916개"라고 적은 것도 같은 단위였다(그때의 고유 수는 더 작다).

## 4. 위험도 — 중

판정을 직접 틀리게 하지는 않는다. `table_id` 중복 제거는 이미 들어가 있어
`clause_table_check` 는 정답 22에 **22 레코드**를 본다.

그런데 **커버리지를 실제보다 2배 좋아 보이게** 만든다.
"표 1,313개가 실렸다"는 말은 팀에 "충분히 실렸다"로 읽히고,
실제로는 613개다 — 12개사 1,367문서에 613개다.

## 5. 왜 못 봤나

코덱스가 라운드에서 **정확히 이걸 경고했다**:

> 수량 단위를 분리해야 합니다.
> `unique_page_tables` / `attached_table_occurrences` / `withheld_unique_tables`

읽고 `table_id` 는 넣었지만 **세는 쪽은 안 고쳤다.** 중복 제거는 채점기(`clause_table_check`)에만
넣고, 상태 보고용 집계는 그대로 두었다. 지적을 절반만 반영한 것이다.

## 6. 수정

- `scripts/eval/table_counts.py` 신설 — 단위를 **이름으로 구분**해 함께 낸다.
  `unique_tables` · `attached_occurrences` · `unique_records` · `attached_records` · `withheld`
- 앞으로 표 수를 말할 때는 **어느 단위인지 함께** 적는다.
