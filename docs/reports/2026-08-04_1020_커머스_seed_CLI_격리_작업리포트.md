## 4. 검증 방법과 결과

### 집중 회귀

```powershell
python -m pytest tests\test_manage_cli.py tests\test_arch.py `
  tests\test_health.py tests\test_static_ui.py -q -p no:randomly
```

결과: `22 passed`.

이 중 임시 디렉터리의 새 SQLite DB에 `migrate`를 실제 실행했다. 활성 `data/`에
`products.csv`와 `inventory.csv`가 없는 상태에서도 DB 파일과 스키마가 생성됐다.
health/static 테스트로 애플리케이션 import와 기본 라우트 회귀도 확인했다.

### 전체 CI 필터 회귀

```powershell
python -m pytest -q `
  -m "not llm and not ml and not mcp and not pg and not legacy_data" `
  -p no:randomly
```

결과: `660 passed, 1 skipped, 52 deselected`.

처음에는 위 조건에서 `not legacy_data`를 빠뜨려 `test_load_cs_dataset` 1건이 실패했다.
이는 격리된 `cs_inquiries.csv`를 요구하는 명시적 레거시 테스트였고, 저장소 CI의 실제 조건에는
이미 `not legacy_data`가 있다. CI와 같은 조건으로 다시 실행해 전부 통과했다.

## 5. 동작 계약

보험 프로젝트의 로컬 DB 준비 명령은 다음과 같다.

```powershell
python -m scripts.manage migrate
```

커머스 `seed`는 성공하는 빈 동작으로 남기지 않았다. 그런 폴백은 잘못된 설치법을 계속 살려 두므로,
호출하면 argparse가 제거된 명령으로 명시적으로 거부한다.
