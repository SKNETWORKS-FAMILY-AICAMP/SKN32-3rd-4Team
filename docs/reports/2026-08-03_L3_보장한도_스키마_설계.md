# L3 — 보장한도·자기부담금 표 스키마 설계와 파서

- 날짜: 2026-08-03
- 계획서: [`docs/plans/2026-08-03_1200_표추출_한계5종_해결계획.md`](../plans/2026-08-03_1200_표추출_한계5종_해결계획.md) **§4 L3**
- 대상 단계: L3-1(스키마 설계) · L3-2(헤더 계층 파싱) · L3-3(값 정규화)
- **범위 밖**: L3-4(판정 경로 연결). 손대지 않았다.

> ★**개정 이력**
> - 초판(설계·부분실측) 뒤에 **전량 1,367문서를 실행**하고 **원문 PDF 10개를 열어 대조**했다.
>   그 결과 §4.3 의 `병원급 5,000원` 판단이 **틀렸다는 것을 확인했다.**

## 1. 작업 목표

계획서 §4 의 진단은 이랬다.

> 이 표는 2차원이 아니라 **유형 × (입원/통원) × 기관종별** 3축이다.
> 평평한 `records` 로는 "상급종합병원 통원 자기부담금"을 못 집는다.

이 진단은 **맞았지만 축을 적게 셌다.** 실측한 축은 다섯이다(§3.3).
그리고 진단이 전제한 입력(`tables_coords`)이 **틀렸다**(§2).

★그리고 실행해 보니 **계획서가 예로 든 바로 그 질문("상급종합병원 *통원* 자기부담금")은
아직 답할 수 없다.** `입통원` 축이 사실로 채워진 레코드가 0.5%뿐이기 때문이다 — §4.6.

## 2. ★가장 먼저 확인한 것 — **입력을 틀리게 잡고 있었다**

계획서는 입력을 `tables_coords` 로 잡았다. 전량 1,367문서를 훑어 확인했다.

### 2.1 `tables_coords` 에는 자기부담금 표가 없다

| 측정 | 값 |
|---|---:|
| 자기부담금 키워드(`자기부담금\|본인부담금\|상급종합병원\|보상한도\|보장한도`)를 가진 `tables_coords` 표 | **13,263** |
| 그중 `선`(괘선 격자 — 조항에 실리는 **유일한** 경로) | **3** |
| 나머지(`2열짝짓기`, 보류 중이라 조항에 안 실림) | 13,260 |

그 `선` 3개를 열어 봤다 — 현대해상 `09db07e32346`·`4e39dccf59ce`·`b3b339438e49` p3.
**자기부담금 표가 아니라 임신·출산 보험금 계산 예시 표**였다. `본인부담금` 이라는
낱말 때문에 걸린 것이다.

> **`tables_coords` 만 입력으로 삼으면 이 파서는 영원히 0건을 낸다.**

### 2.2 표는 `pages[].tables` 에 있었다

같은 페이지 JSON 의 **다른 키**(PyMuPDF `find_tables()` 산출물)에 격자가 들어 있다.

| 측정 | 값 |
|---|---:|
| `상급종합병원` + (`공제`\|`자기부담`) + 금액 토큰 4개 이상인 쪽 | **1,958** |
| 그중 `pages[].tables` 에 3열·3행 이상 격자가 있는 쪽 | **1,279 (65.3%)** |

회사별: 삼성화재 374/415 · 흥국화재 195/434 · 롯데손보 172/173 · 삼성생명 259/367 ·
현대해상 122/248 · 나은생명 53/70 · KB손보 51/74 · 동양생명 34/34 · DB손보 15/118 ·
흥국생명 4/20 · 메리츠화재 0/2 · NH손보 0/3.

> ★**표본이 작은 회사의 0/N 을 "실패율 100%"라고 읽지 않는다.**
> 메리츠화재는 후보가 2쪽, NH손보는 3쪽뿐이다.

### 2.3 그래서 파서는 **두 모양을 다 받는다**

- (가) `tables_coords` 표 dict — 계획서가 정한 계약. 유지한다
- (나) `pages[].tables` 원소(`list[list[str]]`) — **실제로 값이 여기 있다**

`근거_locator.source` 에 어느 쪽에서 나왔는지 남긴다.

### 2.4 ★★그런데 (나)는 **아직 조항에 실리지 않는 경로다**

전량 실행에서 값 있는 레코드 **5,618개**의 출처 —

| 출처 | 값 있는 레코드 |
|---|---:|
| `pages[].tables` | **5,414 (96.4%)** |
| `tables_coords` | 204 (3.6%) |

그리고 그 204개는 **전부** `method="2열짝짓기"` · `is_table=False` 였다.
즉 판별 게이트가 **버린** 표에서 나온 것이다(계획서 L4 참조).

> **승인된 경로(`선`)만 놓고 보면 자기부담금 레코드는 0개다.**
> `pages[].tables` 는 `to_clauses.py` 가 개수(`tables_on_pages`)만 세고 내용을 싣지 않는다.
> 이 파서의 산출물을 판정이 쓰려면 **적재 경로를 새로 뚫어야 한다**(§6).

### 3.3 스키마

계획서 예시는 `{급여구분, 입통원, 기관종별, 자기부담률, 한도금액, 통화, 단위, 근거_locator}`
8필드였다. **실측한 축이 더 많고, 값이 하나의 수가 아닌 경우가 있어** 아래로 바꿨다.

```
── 축 (다섯) ────────────────────────────────────────────────
가입형        표준형 | 선택형 | 선택형Ⅱ | 기본형 | 특약형 | None
상해질병      상해 | 질병 | None
급여구분      급여 | 비급여 | 3대비급여 | None      ← 4세대에만 있다
입통원        입원 | 통원 | None            (셀에 적혀 있을 때만)
입통원_추론   통원 | None                   (항목이 외래/처방조제비일 때. inferred)
항목          외래 | 처방조제비 | 입원의료비 | 상급병실료차액 | … | None
항목_후보     list  ← 한 칸이 여러 항목을 가리킬 때 전부 남긴다
기관종별      의원급 | 병원급 | 상급종합병원 | 약국 | None
기관종별_후보 list
기관종별_원문 str   ← 원문은 항상 남긴다

── 값 ──────────────────────────────────────────────────────
공제액          int|None   정액 공제(원)
자기부담률      float|None 단일 비율
자기부담률_급여     float|None ┐ 선택형Ⅱ 는 급여 10% + 비급여 20% 합산이라
자기부담률_비급여   float|None ┘ **하나의 수로 뭉갤 수 없다**
결합규칙        max | 정액 | 정률 | None
한도금액 한도단위 통화 단위
금액_원문       str

── 출처·정직성 ─────────────────────────────────────────────
근거_locator  {page_from, page_to, table_id, row, source}
축_원문       list
inferred      bool
추론근거      list[str]
parse_status  ok | partial | unparsed
미파싱_사유   list[str]
```

계획서 예시에서 **바꾼 이유**:

1. `가입형`·`상해질병`·`항목` 을 추가했다 — 실측에서 실제로 갈리는 축이다.
   `표준형` 과 `선택형Ⅱ` 는 같은 기관·같은 금액이라도 **비율 계산식이 다르다.**
2. `자기부담률` 하나로는 선택형Ⅱ 를 담을 수 없어 `_급여`/`_비급여` 를 나눴다.
3. `결합규칙` 을 추가했다. `20%` 와 `max(2만원, 20%)` 는 **다른 금액**이다.
4. `단위` 는 셀에 적혀 있을 때만 채운다. "아마 방문 1회당"으로 채우지 않는다.
5. `입통원_추론` 을 사실 칸과 **분리**했다(CLAUDE.md §0).

### 3.4 파싱 실패를 다루는 방식

- **못 읽은 값은 `None`.** 0 으로 채우지 않는다.
- **값을 못 읽은 행도 레코드로 남긴다**(`parse_status="unparsed"`).
  조용히 버리면 분모가 줄어 커버리지가 좋아 보인다(CLAUDE.md §3).
- 버린 행·표도 `stats` 에 센다: `표_역할못찾음` `행_기관없음` `행_본문덩어리`.
- `미파싱_사유` 에 **왜 못 읽었는지**를 문장으로 남긴다.

### 4.3 교차표 — 오연결이 있으면 여기서 튄다

#### ① 페이지 넘김에서 금액의 앞자리가 잘려 나간다 — **미해결 · 4건**

### 4.6 ★축 채움률 — **"통원 자기부담금"은 아직 못 집는다**

계획서가 든 예는 *"상급종합병원 **통원** 자기부담금"* 이었다.
`ok` 레코드 **4,471개**를 기준으로 각 축이 **사실로** 채워진 비율은 —

|---|---:|---:|
| `기관종별` | 4,471 | **100.0%** |
| `결합규칙` | 4,471 | **100.0%** |
| `공제액` | 4,432 | 99.1% |
| `가입형` | 3,301 | 73.8% |
| `항목` | 3,243 | 72.5% |
| `자기부담률` | 2,559 | 57.2% |

읽는 법:

1. **`기관종별` 축은 됐다.** 4축 중 계획서가 가장 중요하게 본 것이다.
2. **`입통원` 축은 안 됐다(0.5%).** 상해통원/질병입원 구분은 표의 **맨 왼쪽 `담보종목` 열**에
   있는데, `find_tables` 격자가 그 열을 대개 포함하지 않는다(§4.4 에서 8쪽 전부 확인).

   `inferred=true` 로 분리돼 있다. **사실로 승격하지 않았다.**
3. **`급여구분` 은 0%다.** 급여/비급여로 갈리는 것은 4세대인데,
   4세대는 금액 열을 통째로 잃어 값 있는 레코드가 아예 안 나온다(§5-1).
4. **`한도금액` 은 `unparsed`·`partial` 까지 다 세어도 0건이다.**
   `단위` 도 전체에서 14건(`unparsed` 13 · `partial` 1)뿐이다.
   ★즉 계획서 스키마의 `한도금액`·`통화`·`단위` 필드는 **정의만 있고 한 번도 채워진 적이 없다.**
   `_CAP`·`_UNIT_RULES` 정규식이 실제 셀을 하나도 못 잡는다는 뜻이므로 **검증이 필요하다** —
   `1일 평균금액 10만원 한도` 같은 원문이 있는데도 `한도금액` 이 아니라 `공제액` 으로
   들어간 사례를 §4.3 에서 1건 확인했다.

> ★**결론을 흐리지 않는다.** 지금 파서가 확실히 답할 수 있는 질문은
> **"이 상품(가입형)의 이 기관등급에서 공제액·자기부담률이 얼마인가"** 까지다.

## 5. ★못 한 것 (숨기지 않는다)

1. **흥국화재 4세대(급여/비급여 축)를 하나도 못 읽는다.**
   `find_tables` 가 **금액 열을 통째로 잃는다.** `0e5af513f7d6` p10 의 격자는 5열인데
   마지막 열에 `의료기관①②③` 라벨만 있고 `본인부담금의 20%` 같은 값이 없다.
   축은 정확히 읽히는데 **값이 없다.** → 4세대 자기부담금은 **판정에 쓸 수 없다.**
   `급여구분` 채움률 0%(§4.6)의 원인이 이것이다.

2. **★페이지 넘김에서 잘린 금액 4건이 틀린 채 `ok` 로 남아 있다**(§4.5-①).
   이번 세션에서 **못 고쳤다.** 값 있는 레코드 5,618건 중 4건(0.07%)이지만
   **판정 가능 상태의 오답**이라 비율보다 위험이 크다.

3. **`의료기관①②③` 각주를 못 푼다.** 정의(`주1) 의료기관① : …`)가 표 **밖**에 있다.
   표 dict 하나만 받는 함수 계약으로는 원리적으로 못 푼다. `unparsed` 382건이 여기 걸린다.

4. **현대해상 `공제기준금액주)` 의 비율을 못 읽는다.** 비율이 표 밖 각주에 있다.
   금액(정액)은 읽고 비율은 `None` → `partial`. `partial` 346건의 주된 원인이다.

5. **DB손보는 표 자체가 안 나온다.** `2c2c4f679faa` p24 의 `find_tables` 산출물은
   `[["구  분","항목"]]` 뿐이다. 참값 8행이 통째로 없다. DB손보 ok율 0.078 의 원인.

6. **`담보종목` 열을 못 읽어 `입통원`·`상해질병` 축이 사실상 비었다**(§4.6).
   계획서가 든 예시 질문에 아직 답하지 못한다는 뜻이다.

7. **삼성생명 조판은 축 라벨을 놓친다.** 병합셀 글자가 여러 행에 쪼개져 첫 값 행보다
   **아래**에 놓인다. 위 행에서 끌어오지 않기로 했으므로 `항목=None` 이 된다.
   금액은 맞다. **틀린 라벨보다 빈 라벨이 낫다**는 판단이다.

8. **held-out 정답셋이 없다.** §4.1 의 48/48 은 자기 표본이고,
   §4.4 의 49/49 는 **파서가 성공한 쪽에서 뽑은 8쪽**이다(회사당 1쪽).
   계획서 L3 검증 기준(`자기부담금 정답셋 별도 구축, 층당 2표`)은 **채우지 못했다.**
   ★특히 **`unparsed` 5,108건 중 몇 건이 "진짜 못 읽는 표"이고 몇 건이 "놓친 표"인지 안 셌다.**
   재현율은 지금 **모른다.**

9. **`한도금액`·`통화`·`단위` 필드는 전량에서 한 번도 안 채워졌다**(§4.6-4).
   스키마에 정의해 놓고 **동작을 확인하지 않았다.** `_CAP`·`_UNIT_RULES` 를
   실제 셀로 검증해야 한다. 지금 상태로는 **죽은 필드**다(RULE.md §3.3).

10. **`_INST_CELL_MAX = 320` 은 거친 문턱이다.** 196문서 2,159레코드에서 잰
   `ok` 최대 240 · `partial` 최대 307 을 근거로 잡았다. 표본이 커지면 다시 재야 한다.

11. **판정 경로에 연결하지 않았다**(L3-4). `to_clauses.py` 를 건드리지 않았다.
    산출물은 아직 **어디에도 저장되지 않는다** — CLI 가 화면에 찍을 뿐이다.

12. **계획서·`CLAUDE.md` 상태표·`docs/history/` 를 갱신하지 않았다.**
    이번 세션 범위가 두 파일(`coverage_limits.py`, 이 리포트)로 못 박혀 있었다.

## 6. 다음 작업 제안 (우선순위 순)

1. **적재 경로 결정** — §2.4 가 이번 발견의 핵심이다. 자기부담금 값의 96.4%가
   `pages[].tables` 에 있는데 그 키는 조항에 실리지 않는다. 둘 중 하나를 골라야 한다.
   - (가) `pages[].tables` 를 `coverage_limit` 레코드로 변환해 **별도 배열**로 조항에 싣는다
   - (나) `table_coords` 의 `선` 경로가 이 표들을 잡도록 고친다(무테두리라 어려울 것)

   ★어느 쪽이든 **`parse_status != "ok"` 인 레코드는 판정 근거로 쓰지 않는다**는 게이트가 먼저다.

3. **자기부담금 정답셋**(계획서 L3 검증 기준) — 층당 2표.
   §3.2(가)의 10표와 §4.4 의 8문서를 **빼고** 뽑아야 held-out 이 된다.
   ★**`unparsed` 쪽에서도 뽑아야 한다.** 지금 재현율을 모르는 이유가 그것이다(§5-8).

   ★각주에서 채운 값은 `inferred=true` + 근거로 남긴다.

5. **`담보종목` 열 복원**(§4.6·§5-6) — `입통원`·`상해질병` 축을 사실로 채우는 유일한 길.
