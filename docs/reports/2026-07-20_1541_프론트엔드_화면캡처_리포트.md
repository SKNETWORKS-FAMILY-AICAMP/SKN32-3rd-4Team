# 프론트엔드 확장 + 실 화면 캡처 (docs/) — Phase 10 이후 발견된 공백 메우기

- 작성일시: 2026-07-20 15:41
- 계기: 사용자 지적 "목업화면 어디갔어? 프론트 이런 거 없어? docs에 화면 스크린샷 넣어야 하는 거
  아니야? 구현 다 된 거 맞아?"

## 1. 정직한 진단 — 실제로 놓친 것
- `app/static/index.html`(원본 프로젝트에서 승계된 채팅 UI)이 이미 존재했는데, Phase 1~10
  내내 **한 번도 열어보지 않았다**. Phase 0 이후 파일 날짜가 그대로였다.
- 그 UI는 `/api/agent/chat`(Phase 0 기본 ReAct) 하나만 호출한다 — 하이브리드/그래프 RAG,
  커머스 승인 루프, MCP, 관리자 RBAC 중 **어느 것도 화면에서 쓸 수 없었다.**
- `docs/`는 이미 있었다(`asset_manifest.md`, `data_manifest.md`). plans/history/reports는
  원본 프로젝트도 저장소 루트에 두는 방식이라(확인함, `docs/` 아래가 아님) 그대로 승계한 게
  맞았지만, 화면 산출물이 `docs/`에 없었던 건 명백한 공백이었다.
- 결론: **백엔드·테스트는 구현됐지만("구현 다 된 거 맞아?"의 절반), 사용자가 브라우저로 열어
  볼 수 있는 화면 관점에서는 구현되지 않았다(나머지 절반).**

## 2. 한 일
### (a) 프론트엔드 4페이지 신규 추가 (`app/static/`)
기존 `index.html`(채팅)에 상단 네비게이션을 추가하고, 같은 바닐라 HTML/CSS/JS 패턴(빌드
도구 없음)으로 4페이지를 새로 만들어 **실제 API를 직접 호출**한다:
- `rag.html` — backend(faiss/hybrid/graph) 선택 + 벡터검색/QA
- `orders.html` — 회원가입 → 상품목록 → 미리보기 → 승인(Idempotency-Key) →
  거부 경로 4종(키없음/충돌/재고초과) → 주문목록
- `admin.html` — 로그인 + RBAC 사다리(401→403→200), 관리자 4개 엔드포인트
- `mcp.html` — 도구 목록 + get_price 실 호출

RULE(무폴백) 준수: 관리자 승격 버튼을 UI에 두지 않았다(CLI 전용 유지, 권한상승 방지).
알 수 없는 backend는 이미 서버가 422로 거부하므로 UI는 그대로 노출한다(조용한 대체 없음).

### (b) 실 화면 캡처 — Playwright로 진짜 스크린샷
`scripts/capture_screenshots.py` / `_admin.py` / `_mcp.py`: 실행 중인 dev 서버
(`scripts/run_dev_server.py`)에 대해 **실제 클릭·입력**으로 API를 호출하고 그 결과가 뜬
화면을 PNG로 저장한다(가짜 데이터 없음). 14개 스크린샷을 `docs/screenshots/`에 저장하고
`docs/index.html`(갤러리)에서 각각 무엇을 보여주는지 설명과 함께 정리했다.

### (c) 캡처 중 발견·수정한 버그 2건(내 스크립트 버그, 앱 버그 아님)
1. **결과 잔존(staleness)**: 버튼 클릭 후 이전 단계의 응답이 화면에 남아있는 채로
   스크린샷을 찍은 경우가 있었다(예: 로그인 200인데 관리자 응답은 이전 403 그대로).
   클릭 전에 결과 영역을 비우고 새 결과가 실제로 나타날 때까지 기다리도록 고쳤다.
2. **뷰포트 잘림**: 뷰포트 높이보다 긴 페이지를 `full_page=True` 없이 찍어 답변 JSON
   뒷부분이 잘렸다. 전체 페이지 캡처로 바꿨다.
- **토큰 비노출**: 회원가입/로그인 응답에 실 JWT가 그대로 찍혔다 — 캡처 직전에 해당
  패널 내용을 상태 배지로 대체해 토큰이 문서에 남지 않게 했다(계정 자체는 로컬
  데모용 SECRET_KEY로 발급된 것이라 위험은 낮지만, 굳이 남길 이유가 없어 가렸다).

### (d) `.claude/launch.json` + `scripts/run_dev_server.py` 신규
프리뷰 도구가 dev 서버를 띄우려면 워크스페이스 루트에 `launch.json`이 필요했다. dev 서버는
`.env` 없는 로컬 환경에서 `SECRET_KEY` 미설정으로 회원가입이 막히는 문제(이전 세션에서도
한 번 겪음)를 다시 겪지 않도록 데모 전용 기본값을 `setdefault`로 채우는 래퍼로 만들었다.

## 3. 검증
- `tests/test_ui.py`에 신규 3개 테스트 추가: 4페이지가 실제로 서빙되는지, 각 페이지의
  JS/HTML이 **실제 엔드포인트 경로**를 호출하는지(장식용 목업 방지), 홈 화면 네비게이션이
  4페이지 전부로 연결되는지.
- 전체 **CI 323**(+3, 회귀 0) 통과.
- 실제 dev 서버 + 로컬 Gemma + PostgreSQL을 다시 띄워 14개 화면을 **전부 라이브로 재현**했다
  (성공 경로 8종, 거부/권한 경로 6종 — 성공만 보여주지 않았다).

## 4. docs/ 폴더 구조 — plans/history/reports는 왜 안 옮겼는가
원본 `_unified_mall_agent_project`를 확인한 결과 그 프로젝트도 `plans/`, `history/`,
`reports/`를 **저장소 루트**에 둔다(`docs/`는 별도 목적 — asset/data manifest 등). RULE.md의
"기존 프로젝트 규칙 승계" 지시를 따라 `_unified_mall_2`도 동일하게 뒀다. 이건 계획대로였다.
다만 `docs/`에 **화면 산출물**이 없었던 건 계획에 없던 진짜 공백이었고, 이번에 채웠다. 만약
plans/history/reports 자체를 `docs/` 하위로 재배치하는 걸 원하면 후속 작업으로 가능하나,
~35개 리포트 상호 참조 경로가 전부 바뀌는 기계적 작업이라 별도 요청 시 진행한다.
