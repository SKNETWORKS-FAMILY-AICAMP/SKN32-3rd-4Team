# 지식 바운티 L1 기계 검증 구현 리포트

- 일자: 2026-07-22
- 계획: [`docs/plans/2026-07-22_2100_지식바운티_검증모델_재설계.md`](../plans/2026-07-22_2100_지식바운티_검증모델_재설계.md) L0·L1
- 범위: L0 등급화 + L1 기계 검증. **L2(escrow·slash)·L4(결과연동)는 미구현.**

## 1. 무엇을 만들었나

| 파일 | 역할 |
|---|---|
| `app/application/bounty.py` | L0 등급·L1 검증 유스케이스(프레임워크 무의존) |
| `app/routers/bounty.py` | `/api/bounty/grades·open·submit` (운영 전용) |
| `app/composition.py` | `build_verify_bounty_submission` — 기존 리트리버·SelfVerify 주입 |
| `app/core/config.py` | 임계값 2종(하드코딩 금지) |
| `tests/test_bounty.py` | 18개 결정론 테스트 |

기존 자산을 재사용했고 새 인프라를 만들지 않았다: 인용 대조·중복성은 `RetrieverPort`,
정합성은 `SelfVerify`(SupportCheck), 바운티 후보는 `KnowledgeGap`(abstention 큐).

## 2. 검사 순서 (싼 것 → 비싼 것)

```
등급 게이트(opinion이면 즉시 제외)
→ 근거 제시 여부 (무료)
→ 인용 대조    (검색)
→ 중복성       (검색)
→ 정합성       (LLM 호출 — 가장 비싸므로 마지막)
```
앞 단계에서 걸리면 뒤 단계를 돌리지 않는다(테스트로 고정: 중복 반려 시 LLM 미호출).

## 3. Codex 검토에서 잡힌 치명적 결함과 수정

### (1) 재현성 검사가 위조를 못 걸렀다 — 핵심 수정
**최초 구현**: `retriever.search(인용문, source=출처)`의 **임베딩 유사도**가 임계 이상이면 통과.

**Codex 지적**: 이건 외부 원문 재조회가 아니라 내부 색인에서 *의미가 비슷한* 청크를 찾는 것이다.
공격자는 **실제 문서명**을 쓰고 원문과 의미만 비슷한 **허위 문장**을 지어내면 통과한다.
`locator`는 아예 무시돼 페이지 위조도 막지 못한다. → **"위조 출처를 걸러낸다"는 내 설명이 과장.**

**수정**: 의미 유사도 → **문자 수준 원문 대조**로 교체.
- 정규화 후 **부분문자열이면 1.0**(정상 부분 인용 허용), 아니면 `SequenceMatcher` 비율
- `locator`를 제시했으면 색인의 locator와 **일치해야** 통과
- 검사 이름도 `reproducible` → `citation_match`로 바꿔 **무엇을 확인하는지** 정확히 표현

회귀 테스트 신설: `test_plausible_but_fabricated_quote_is_rejected`(허위 인용 차단),
`test_forged_locator_is_rejected`(페이지 위조 차단), `test_exact_and_partial_quote_pass`(정상 인용 허용).

### (2) 임계값 검증 부재 — NaN이면 전부 통과
`float("nan")`과의 비교는 항상 False라 **모든 검사가 통과**할 수 있었다.
→ `_validate_threshold`로 유한한 `[0,1]`만 허용, 아니면 `ValidationErr`.

### (3) 입력 경계 부재
근거 개수·길이 상한, 공백 근거·빈 출처 검사가 없었다 → 무제한 입력으로 검색·LLM 연산 유발 가능.
→ 상한과 공백 검증 추가.

### (4) `/grades`에 인증 누락
운영 전용 계약과 어긋났다. → **라우터 전역 의존성**(`dependencies=[Depends(require_admin)]`)으로
전환. 엔드포인트마다 붙이면 새로 추가할 때 누락되므로 관리자 라우터와 동일 패턴을 따랐다.

## 4. 설계 원칙 준수 확인

- **사실성 판정 안 함**: 통과 상태 이름이 `verified`가 아니라 `grounded`. 정적 테스트
  (`test_module_never_claims_factuality`)로 `"verified"` 문자열 부재를 고정.
- **무폴백**: 미지 등급·빈 입력·잘못된 임계값 전부 `ValidationErr`. 반려 사유는 고정 코드
  (자유 서술 유출 금지).
- **무하드코딩**: 임계값 2종 config.
- **클린 아키텍처**: `app/application/bounty.py`는 FastAPI·SQLAlchemy 미import
  (`test_arch` 통과).
- **고객/운영 분리**: 고객 포트에서 `/api/bounty/*` 404.

## 6. 한계 (정직 기록)

- **인용 대조는 "우리 색인과의 일치"만 확인한다.** 외부 원본 문서가 진짜인지, 그 내용이
  참인지는 확인하지 않는다. 색인 자체가 오염되면 통과한다.
- 정합성 검사(SelfVerify)는 **같은 모델의 자기 점검**이라 독립 검증이 아니다.
- 임계값(인용 대조 0.85 / 중복 0.95)은 **실 제출 데이터로 튜닝되지 않은 시작값**이다.
- L2(escrow·이의제기·slash)·L4(결과연동) 미구현 → **정산은 수행되지 않는다.**
  `settleable`은 "정산 단계로 넘길 후보"라는 뜻일 뿐 지급이 아니며, 응답에 이를 명시한다.
