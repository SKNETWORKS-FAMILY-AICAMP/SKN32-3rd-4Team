## 2. 결함 A — 번호 체계 오판 (35% 손상의 원인)

### 무엇이 문제였나

로직이 이랬다.

> `제N조` 를 줄머리에서 찾는다. **0개일 때만** `N. (제목)` 으로 넘어간다.

그런데 그 문서의 줄머리 `제N조` 8개는 **전부 법령 인용**이었다.

```
"「의료법」 제3조(의료기관)에서 규정한 국내의 의료기관에서 발급한 것이어야 합니다."
```

긴 문장이 줄바꿈되며 `제3조` 가 줄머리로 왔다.
진짜 조항은 `1. (보장종목)` 꼴로 **93개**였는데, `제N조` 가 0이 아니라서
`article` 방식으로 판정했다.

### 어떻게 고쳤나

두 후보를 다 모아 **제목이 붙은 머리 수**로 비교한다.
제목 없는 `제N조` 는 인용일 가능성이 높다(코덱스 지적).
점수 차가 작으면 `ambiguous` 로 표시해 자동 판정에서 뺀다.

## 3. 결함 B — 항 번호 ①②③ 이 사라져 있었다

### 무엇이 문제였나

```
'\U000f02b1위 \U000f02b2의 사고증명서는 …'
```

`①②③` 이 **보조 사용자영역**(U+F0000~) 문자로 들어와 있었다.
BMP 사용자영역(U+E000~U+F8FF)만 지우던 규칙에 안 걸려 깨진 채 남았고,
항 번호 정규식 `[①-⑳]` 이 매칭되지 않아 **"제N항"을 특정할 수 없었다.**

실측: `U+F02B1` 221회 · `U+F02B2` 104회 … 표본 250문서 중 **144개(58%)**.

### 코덱스가 PDF 를 직접 렌더링해 검증했다

- `U+F02B1~U+F02B9` 는 화면상 `①~⑨` 가 맞다
- 같은 문서에 정상 `①~⑨` 도 섞여 있다
- ★**`⑩` 은 `U+F02BA` + `U+F02C3` 두 문자가 같은 자리에 겹쳐** 나온다
  → `U+F02B0+n` 산술식을 10 이상으로 늘리면 **틀린다**

### 어떻게 고쳤나

**1~9 만 매핑하고, 나머지는 지우지 않고 세어 남긴다**(`stats.unmapped_glyphs`).
지우면 뭘 잃었는지 알 수 없게 된다.

## 4. 새로 넣은 것 — 사후 검증

**"조항을 만들었다"가 "제대로 만들었다"는 뜻이 아니다.**
96쪽에서 조항 3개, 그중 하나가 90,385자인 결과를 v3 는 **성공으로 내보냈다.**

이제 스스로 확인한다.

| 조건 | 판정 |
|---|---|
| 조항 하나가 30,000자 초과 | `suspect` |
| 본문 30쪽 이상인데 조항이 본문쪽수/10 미만 | `suspect` |
| 번호 체계를 확신할 수 없음 | `suspect` |

`suspect` 108건은 **판정에서 제외**된다(`precheck.run()` 이 `parse_status == "ok"` 만 쓴다).

> p95 가 31,017자라 임계값 30,000 을 살짝 넘는 문서가 많다.
> 임계값이 다소 빡빡한 편이므로, 표본 검수 후 조정을 검토해야 한다.

| 버전 | 결함 | 실측 |

| v3 | 본문 조립 시 목차 페이지를 안 건너뜀 | 조항 하나가 42,632자, 안에 조 머리 194개 |

`\x01` 건이 특히 위험했다. 그 상태로는 `"보험금을 지급하지 않습니다"` 로 검색해도
안 걸린다 — **면책 조항을 못 찾는다는 뜻**이다.

## 6. 내가 반복한 실수

1. **고정 창·고정 임계값으로 판단했다.** 목차 판정 비율 200, 문맥 창 160자 —
   둘 다 실제 문서에서 무너졌다. **구조를 보는 규칙**으로 바꿔야 했다.
2. **"0개일 때만"류의 배타 분기.** `제N조` 가 하나라도 있으면 그것으로 갔다.
   오탐이 섞이는 데이터에서는 **점수로 비교**해야 한다.
3. **성공을 검증하지 않았다.** 만들어졌으면 됐다고 봤다. 사후 검증을 넣고서야
   90,385자짜리가 잡혔다.
4. **비원자적 쓰기.** 실패가 0바이트 파일을 남겼고, 그걸 고치는 스크립트가
   같은 방식으로 소스 파일을 날렸다. git 으로 복구했다.
