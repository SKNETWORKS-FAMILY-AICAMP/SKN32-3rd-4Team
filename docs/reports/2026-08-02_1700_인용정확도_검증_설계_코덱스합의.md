## 0. 왜 또 만드나 — 기존 지표와 겹치지 않는 곳

[`scripts/eval/struct_audit.py`](../../scripts/eval/struct_audit.py) 는 **텍스트만 본다.**
`locator` · `page_from` · `char_offset` 을 **한 번도 읽지 않는다**(전 함수 확인).

| | 재는 것 | 못 재는 것 |
|---|---|---|
| T축 (`text_fidelity`) | 문서 전체 8-gram 보존율 | **어느 조항이 몇 쪽에서 왔는가** |
| S축 (`structure_faults`) | 재진입·헤더 매몰·부록 흡수 | 〃 |
| C·N축 | 인용 중복·PUA·U+FFFD | 〃 |

그런데 [v5 개선계획 1단계](../plans/2026-08-02_0812_전처리_v5_개선계획.md)가 이렇게 선언해 놨다:

> 2단계부터는 **인용 정확도**(무작위 조항의 `citation` 이 원문 쪽과 맞는가)로 잰다.

**약속만 있고 구현이 없다.** 그리고 이건 제1원칙에 직결된다 — `"제9조 · 12쪽"` 이 틀리면
답변 전체가 옳아도 **인용이 거짓**이다.

---

## 1. 순서

라벨이 필요 없는 것부터. 앞 단계가 뒤 단계의 표본을 만들어 준다.

| | 단계 | 라벨 | 대상 | 무엇을 확정하나 |
|---|---|---|---|---|
| **L0** | 스키마·범위 검증 | 0 | 전량 | 값 자체가 말이 되나 |
| **L1** | 시작 앵커 검증 | 0 | 전량 | `char_offset` 이 진짜 그 문장의 시작인가 |
| **L2** | 중간 페이지 포함 검증 | 0 | 전량 | 본문이 그 쪽 범위에서 왔나 |
| **L3** | 커버리지 3분할 | 0 | 전량 | 소실·중복·정상을 **합이 맞게** 센다 |
| **L4** | s4 ↔ s5 짝지은 차분 | 0 | 전량 | v5가 나아졌나 나빠졌나 |
| **L5** | 층화 표본 라벨링 | **소량** | 두 갈래 | 자동 지표가 못 보는 것 |

★**L0~L4는 하루치 스크립트 하나다.** L5만 사람이 붙는다.

# 자세히

## L0 — 스키마·범위 검증

가장 싸고, 걸리면 **확정 결함**이다.

| 검사 | 실패의 뜻 |
|---|---|
| `char_length == len(text)` | 저장이 어긋났다 |
| `page_from <= page_to` | 조립 순서 오류 |
| `char_offset >= 0` · 해당 페이지 길이 이내 | 오프셋 계산 오류 |
| `page_to <= stats.pages` | 존재하지 않는 쪽을 가리킨다 |
| `content_hash == _clause_hash(section, title, norm(text))` **재계산** | 저장 무결성 |
| ★`page_from` 이 `toc_pages` 에 들어 있나 | **아래 참조 — 설계상 모순** |

### ★마지막 항목이 핵심이다

본문 조립은 이렇게 한다 ([`to_clauses.py`](../../scripts/extract/to_clauses.py)):

```python
for p in range(page, end_page + 1):
    if p in toc_pages:      # ← 목차 페이지는 건너뛴다
        continue
    a = off if p == page else 0
    ...
locator = {"page_from": page, "page_to": end_page, "char_offset": off}
```

`page_from` 이 `toc_pages` 에 포함되면 **그 페이지는 본문에서 빠지는데 `locator` 는 여전히
그 페이지를 가리킨다.** 그러면 인용이 *"12쪽"* 이라고 하는데 본문은 13쪽에서 시작한다.

몇 건인지 아직 세지 않았다. **L0에서 제일 먼저 셀 것.**

---

## L1 — 시작 앵커 검증

조립 방식이 슬라이스라서, 첫 조각은 **정확히 일치해야 한다.**

```
page_text = pages[page_from].text
assert page_text[char_offset : char_offset + K] == clause.text[:K]
```

`K` 는 200자 정도면 충분하다. 어긋나면 `char_offset` 이 틀린 것이고,
**인용 위치가 틀렸다는 뜻**이다.

> ★코덱스 지적을 받아 범위를 좁혔다. 처음에는 *"본문 전체를 재구성해 완전 일치시키자"* 고
> 했는데 — **그건 지금 불가능하다.** §"확인된 결함" 참조.

---

## L2 — 중간 페이지 포함 검증

`page_from < p < page_to` 인 페이지는 **통째로** 들어간다(`a=0, b=len(t)`).
따라서 이건 정확 검사다.

```
for p in (page_from, page_to) 사이, p ∉ toc_pages:
    assert pages[p].text  in  clause.text     # 부분문자열
```

끝 페이지(`page_to`)는 끝 오프셋을 모르므로 **접두 포함만** 본다.

---

## L3 — 커버리지 3분할

기존 T축(8-gram 재현율)과 다른 것을 잰다. **합이 맞는지**를 본다.

```
목차·제외 영역을 뺀 "조항 후보 본문" 을 분모로 두고

  미포함    어떤 조항에도 안 들어간 문자
+ 1회 포함  정확히 한 조항에
+ 중복 포함 둘 이상의 조항에
─────────
= 후보 본문 전체            ← 안 맞으면 계산 자체가 틀렸다
```

- **미포함** = 검색에서 사라진 텍스트. NH 「보상하지 않는 사항」이 이렇게 없어졌다
- **중복 포함** = 경계 겹침. 같은 조항이 두 번 인용될 수 있다
- ★분모가 **PDF 전체가 아니라 후보 본문**이어야 한다 (코덱스). 목차를 많이 뺄수록
  점수가 오르는 함정이 이미 두 번 있었다

---

## L4 — s4 ↔ s5 짝지은 차분

같은 sha 를 두 버전에서 나란히 놓고 **문서별 delta** 를 본다.

```
문서 sha  |  L1 실패율 s4 → s5  |  L3 미포함 s4 → s5  |  parse_status s4 → s5
```

★**총량 비교 금지.** 이미 폐기한 기준이다 —
*"조항 수는 품질 지표가 아니다. 많아도 가짜일 수 있고 줄어도 개선일 수 있다."*

★**한계 (코덱스)**: 두 버전이 **같은 방식으로 틀리면 이 대조는 아무것도 못 잡는다.**
그래서 L5가 필요하다.

### s5에서 `ok` 가 132건 줄어든 것을 여기서 해명한다

`s4 ok → s5 non-ok` 로 바뀐 문서를 **별도 층**으로 두고 원인별로 센다.
지금은 `parse_status` 말고 판단 근거가 없는데, L1·L3 값이 붙으면
**엄격해진 것인지 나빠진 것인지** 갈린다.

---

## L5 — 층화 표본 (여기만 사람이 붙는다)

★**두 갈래를 나누고, 섞어서 하나의 오류율로 계산하지 않는다** (코덱스 — 이게 핵심).

| 갈래 | 목적 | 뽑는 법 |
|---|---|---|
| **무작위** | 전체 오류율 추정 | 층화 후 무작위 |
| **위험 기반** | 희귀하지만 치명적인 오류 발견 | L0~L4 최악 문서 · `s4 ok→s5 non-ok` · `no_clause_heads` · 장문/다페이지 조항 · 번호 재시작 문서 |

두 표본의 결과를 합치면 **오류율이 부풀려진다.** 따로 보고한다.

### 단위와 상한을 명시한다

- **"30~50건"이 문서인지 조항인지 반드시 적는다** (코덱스 지적 — 내 초안은 모호했다)
- 층화 표본에 **단순 rule-of-three 를 그대로 적용할 수 없다.** 층별 또는 가중 추정이 필요하다
- 이미 설계된 **정답셋 48패킷**(문서 48건이 아니라 원문 3쪽 창 48개 ≈ 144쪽)이
  [1500 리포트](2026-08-02_1500_전처리_품질지표_설계와_실측.md) §5.5-5 에 있다. 그걸 쓴다

## ★확인된 결함 — `locator` 로는 본문을 재구성할 수 없다

코덱스가 *"locator 만으로 재구성이 유일하지 않다면 `end_offset` 이 필요하다"* 고 지적했고,
**코드로 확인한 결과 맞다.**

```python
b = end_off if p == end_page else len(t)      # 조립에는 end_off 를 쓴다
...
"locator": {"page_from": page, "page_to": end_page, "char_offset": off}
                                              # ← end_off 가 저장되지 않는다
```

`end_off` 는 계산해 놓고 **버린다.** 그래서:

| | 가능한가 |
|---|---|
| 시작 앵커 검증 (L1) | ✅ |
| 중간 페이지 포함 (L2) | ✅ |
| **본문 완전 재구성** | ❌ **불가능** |
| 조항 끝 경계가 맞는지 기계 검증 | ❌ 불가능 |

**권고**: 산출물 `locator` 에 `end_offset` 을 추가한다. 한 줄이고, 다음 전처리 실행부터
완전 재구성 검증이 가능해진다. 기존 s5 산출물은 L1·L2 로만 검증한다.

## 쌍방 합의 기록

| 항목 | 클로드 초안 | 코덱스 | 합의 |
|---|---|---|---|
| 왕복 검증 | *"슬라이스 이어붙이기라 **정확 일치**로 검사 가능"* | **조건부** — `"\n"` 삽입·오프셋 기준 불명확·재구성 불가 | ★**초안 과장 인정.** L1(앵커)+L2(포함)로 분할. 완전 재구성은 스키마 보강 후 |
| 미포함 커버리지 | 동의 | 동의 — 단 **분모는 후보 본문** | 반영 |
| 본문 내 `제N조` | 결함 신호 | 인용문·별표 때문에 **정상도 걸린다** | **suspect 신호**로 격하 (기존 `S3` 와 중복이라 L에서는 제외) |
| `qualified_no` 충돌 | 문서 전체에서 검사 | 특약·별표 재시작은 정상 | **같은 번호체계/section 범위 안에서만** |
| locator 단조성 | 동의 | 범위 유효성·역전·중첩·비정상 공백도 | L0에 흡수 |
| 동일 hash 자기대조 | *"공짜 교차검증"* | **효과 제한적** — hash가 text에서 나왔으니 무결성 검사에 가깝다 | ★**격하.** `hash 재계산 일치` 를 L0에 넣는 것으로 대체 |
| s4↔s5 대조 | 동의 | 동의 — 단 **공통 오류는 못 잡는다** | 한계로 명시 |
| 표본 30~50건 | 동의 | **단위 불명 · rule-of-three 오용** | 단위 명시 + 층별 추정 |
| **금지 지표** | 조항 수·길이비율·`parse_status` **쓰지 마라** | ★**반대** — 품질 점수로 쓰면 안 되지만 **회귀 경보·이상치 탐색·층화**에는 유용 | ★**코덱스 수용.** "점수로 쓰지 않는다"로 표현 수정. L4·L5의 층화 축으로 사용 |
| 순서 1→2→3 | | **동의** | 유지 |

### 코덱스가 추가로 제안한 것 중 채택

- 중복 커버리지 → **L3에 흡수**
- 범위 보존(합이 맞나) → **L3에 흡수**
- 스키마/범위 검증(음수 offset, `page_from>page_to`, `char_length≠len(text)`) → **L0**
- 버전 전환 분석(`s4 ok→s5 non-ok` 별도 층) → **L4·L5**

### 보류

- **헤더 정합성**(`clause_no`·`title` 이 실제 첫머리와 맞나) — 좋은 지표지만
  기존 `S3_embedded_header` 와 겹치는지 확인 후 결정
- **경계 품질**(문장 중간 시작/끝) — [1600 리포트 §4](2026-08-02_1600_무참조_품질지표_구성과_코드.md) 가
  같은 발상(`B1`)을 **이미 만들었다가 폐기**했다. 조항이 표·목록으로 끝나 정상까지 절단으로 셌다.
  같은 실수를 반복하지 않는다

## 한계 — 정직 기록

- **이 문서는 설계다. 아직 한 번도 돌리지 않았다.** 여기 숫자는 하나도 없다
- L0~L4가 전부 통과해도 **내용이 맞다는 뜻이 아니다.** 위치와 보존만 본다.
  "제9조인데 제목이 틀렸다" 같은 것은 L5에서만 잡힌다
- [1600 리포트 §4](2026-08-02_1600_무참조_품질지표_구성과_코드.md) 의 교훈이 여기에도 적용된다 —
  **지표는 만들자마자 믿으면 안 된다.** L0~L4 각각에 대해 실패 사례 3~5건을 **눈으로 열어**
  진짜 결함인지 확인하고 나서 수치를 보고한다
- 검색 품질을 보장하지 않는다. 인용이 정확해도 검색이 못 찾으면 소용없다
