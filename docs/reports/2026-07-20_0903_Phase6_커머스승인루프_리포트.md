### Codex 지적 처리 (정직)
**설계 라운드(FIX)** 3건 전부 반영: (a) 멱등키는 별도 테이블(요청지문 저장), (b) 헤더 누락 시
서버 UUID 생성은 **무폴백 위반** → 422 거부, (c) 재검증+차감+키기록 단일 트랜잭션·경합은 재조회 수렴.

**구현 라운드** 지적 9건 반영:
1. `PreviewOrder`가 같은 상품 중복 라인을 합산하지 않아 과다판매 미탐 → 누적 수요로 판단.
2. `PlaceOrder`가 멱등 조회 **전에** 수량 검증을 안 해 `A×2, A×-1`(순수량 1)이 기존 주문으로
   재생됨 → 조회 전 수량≤0 거부.
3. 지문 직렬화 `code:qty;…`가 구분자 포함 코드에서 모호 → JSON 배열 직렬화.
4. `inv.stock if inv else 0`이 재고레코드 부재를 0으로 조용히 대체 → `InfraError`(불변식 위반).
5. 재고 검증·차감에 잠금/조건부 갱신 없어 동시 초과판매 가능 → `UPDATE … WHERE stock>=qty` +
   rowcount 확인(조건부 원자 차감).
6. 경합 재조회 시 지문 미비교 → 지문 일치할 때만 재생, 불일치는 409.
7. `IntegrityError`를 전부 멱등 경합으로 오분류 → 멱등레코드 삽입만 **savepoint 격리** +
   `_is_unique_violation`(SQLite 메시지 / PG sqlstate 23505)로 판별, 그 외는 전파.
8. 조건부 차감 0건 후 재조회 결과가 `None`이면 `None.stock` 접근(AttributeError) → `InfraError`.
9. 멱등레코드가 가리키는 주문 부재는 클라이언트 404가 아닌 내부 불변식 위반 → `InfraError`.

**지적이지만 수정 불필요 1건**: "타인주문 4xx 유스케이스 미제시"는 리뷰에 보낸 파일 범위 밖 —
`order_service.get_order`(변경 없음)와 기존 403 테스트가 계속 보장.

## 3. ★ 정직한 finding / 한계
- **계약 변경(의도적)**: `POST /api/orders`가 `Idempotency-Key` **필수**가 됐다. 기존 주문
  테스트 8곳을 헤더 제공하도록 갱신했다. 이는 "조용한 서버 UUID 폴백"을 제거한 결과로,
  무폴백 원칙과 멱등 보장을 위해 감수한 **호환성 파괴**다(문서화된 의도적 변경).
- **동시성 검증의 한계(과장 금지)**: 조건부 원자 차감·savepoint·unique 수렴을 **구현**했지만,
  실제 병렬 요청 경합은 **테스트로 재현하지 않았다**(동시성 테스트 인프라 필요). 현재 검증은
  단일 스레드 결정론·통합 테스트 + 정적 리뷰 수준이다. "동시성 안전"은 설계·구현 근거이지
  실측이 아니다. 병렬 부하 테스트는 후속(Phase 10 안정화 후보).
- 기본 DB는 SQLite(쓰기 직렬화). PG 경로에서의 동시성은 `_is_unique_violation`이 sqlstate
  23505를 인식하도록 대비했으나 역시 병렬 실측은 미수행.
- `order_service.create_order`(구 경로)는 더 이상 라우터에서 쓰이지 않는다(읽기 `list/get`만 사용).
  완전 제거는 Phase 8 레거시 수렴에서.
