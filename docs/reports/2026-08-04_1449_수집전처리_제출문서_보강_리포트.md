임베딩 revision은 완료 성과로 쓰지 않았다.

## 2. 주요 보강 사항

### 2-1. 수집

- `2,121 SourceOccurrence → 1,703 고유 SHA → 336 격리 → 1,367 전처리 대상` 계보를 명시했다.
- `1,817건·5.16GB`를 2026-08-01 중간 체크포인트로 분리했다.
- 12개 보험사별 발생·고유 SHA·전처리·격리 수를 싣고 삼성생명 전처리 수를 200으로 바로잡아
  합계를 1,367로 맞췄다.
- API, HTML, 세션·브라우저 수집 방식과 사이트별 장애·대응을 정리했다.
- 매니페스트 유실, HTTP 206 65,536바이트 잘림, 중복 프로세스, 분류 오탐, 자연 중복,
  세션 토큰 URL 사건과 재발 방지를 기록했다.
- `update_all.py`는 삼성화재·DB손해보험 두 어댑터용이며 `--recheck`는 현행 로직에서 사용되지
  않는다고 한정했다.
- 수집 완료 시점의 `2,121 발생행`과 `2,030 물리 PDF(5.75GB)`를 서로 다른 단위로 구분했다.

### 2-2. 좌표 기반 전처리

- `run_all.py → to_page_json.py → table_coords.py/table_signals.py → to_clauses.py` 실제 본선 흐름을
  코드 책임과 함께 설명했다.
- PyMuPDF native table, 단어 bbox·벡터선 기반 좌표 복원, T1~T9 신뢰도 게이트, 조항·항·호
  구조화와 fail-closed 보류 정책을 설명했다.
- 전수 OCR 대체가 아니라 좌표 추출이 축 관계를 확정하지 못한 고가치 표만 OCR-hard 후보로
  보낸다는 경계를 명시했다.
- s6 1,367문서, 조항 204,098개와 `ok 1,306 / suspect 52 / no_clause_heads 9`를 현재 실측으로
  정리했다.

### 2-3. OCR 모델 선정과 승격

- 동일 보험약관 7쪽에서 OvisOCR2, PaddleOCR-VL, MinerU2.5, GLM-OCR, BizOnAI-OCR를 비교한
  표를 추가했다.
- 최종 모델 `opendatalab/MinerU2.5-Pro-2605-1.2B`와 revision
  `bff20d4ae2bf202df9f45284b4d43681555a97ed`를 명시했다.
- MinerU의 KCD 코드 22/22, 같은 행 결합 21/22, 자기부담금 표 7/7, 평균 29.055초/쪽,

### 2-4. 임베딩 문서 경계

임베딩은 넓은 의미의 전처리에는 포함될 수 있으나, 이 프로젝트에서는 승인된 구조화 데이터를
검색 표현으로 바꾸는 후속 색인 단계로 정리했다. 이 문서에는 다음 입력 계약만 남겼다.

- chunk, occurrence, locator, content hash
- 미승인 candidate의 임베딩 입력 제외
- 현재 Arctic-ko 프로필의 차원·청크·overlap 스냅샷

21회 모델 비교, bootstrap, title/tail/exclusion 평가와 배포 판단은
`docs/submission/05C_사용_LLM_모델.md §3`, `docs/submission/03_RAG_LLM_벡터DB_구현.md`,
`docs/handoff/13_임베딩모델_선정_브리핑.md`를 정본으로 연결했다. 현행 accepted config의
임베딩 revision이 비어 있다는 미해결 사항도 숨기지 않았다.
