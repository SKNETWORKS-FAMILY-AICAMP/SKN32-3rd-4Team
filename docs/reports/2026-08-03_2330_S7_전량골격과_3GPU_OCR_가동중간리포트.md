# S7 전량 골격 생성·3GPU OCR 가동 중간 리포트

## 1. 목표

`docs/plans/2026-08-03_2208_S7_실사용_데이터셋_생성계획.md`의 S7-1~S7-4.
평가 패킷이 아니라 판정 대상 1,367문서 전량의 S7 candidate release를 만들고,
12시간 제한 안에서 고우선순위 자기부담금 OCR을 최대한 결합한다.

## 2. 실제 수행

- `scripts/extract/build_s7_hybrid.py` 신설
  - frozen s5 page + s6 clause 입력을 SHA/스키마로 검증
  - page별 selected mode/reason과 upstream 해시 기록
  - OCR fact를 candidate/serving false/citation false로 강제
  - atomic write와 다른 기존 출력 overwrite 거부
- 전량 산출
  - `data/extracted/*/s6_hybrid-table-v1/`: 1,367건
  - `data/structured/*/s7_hybrid-table-v1/`: 1,367건
  - page mode: native_layout 61,464 · verified_line_grid 777 · text_only 100,437
- `scripts/eval/prepare_s7_ocr_batch.py` 신설
  - frozen 자기부담금 scan 4,538쪽을 missed/withheld 우선순위화
  - atomic PNG render, 이미지/PDF SHA manifest, production ZIP 생성
- production 입력 3,000쪽 생성
  - batch0: missed 1,000 · 428문서
  - batch1: missed 1,000 · 481문서
  - batch2: missed 118 + withheld 882 · 565문서
- `ocr_sota5_runner.py`, `selfpay_axis_binder.py`에 모델 provenance와 candidate 이중 차단 추가
- GPU 가동
  - x600: 기존 144쪽 packet resume, GPU 실가동
  - RunPod 1: batch1 1,000쪽 production 실가동
  - RunPod 2: batch2 1,000쪽 production 실가동
  - x600용 batch0 1,000쪽 packet 전송 완료, 144쪽 뒤 실행 예정

## 3. 검증 결과

- S7 builder 실제 생성: 입력쌍 1,367, page 1,367, clause 1,367, 생성 실패 0
- production render smoke: 3/3 PNG decode·크기·manifest·ZIP 성공
- OCR/binder 집중 테스트: `22 passed`
- 원격 packet
  - RunPod 1 batch1: 로컬/원격 ZIP SHA-256 일치, ZIP test 1,002엔트리 정상
  - RunPod 2 batch2: ZIP test 1,002엔트리 정상
- 동일 10쪽 smoke
  - x600 신규 9쪽 평균 51.15초
  - RunPod 1 10/10 평균 44.39초
  - RunPod 2 10/10 평균 38.09초
  - 합산 약 246쪽/시간
