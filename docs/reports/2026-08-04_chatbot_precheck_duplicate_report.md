# 챗봇·사전판정 중복 표시 점검 보고서

## 결론

사용자가 제보한 두 화면은 원인이 달랐다. 챗봇 용어 카드는 문서 버전별 동일 정의의 중복이었고, 사전판정 카드 두 개는 서로 다른 특약이 같은 `별표2/제4조` 라벨을 가진 표시 문제였다. 동일 정의만 묶고, 서로 다른 특약 근거는 담보 범위를 밝혀 모두 유지했다.

## 반영 내용

1. 챗봇 용어 인용
   - 같은 보험사 안에서 줄바꿈, 공백, 페이지 번호, 목차/표 머리말을 제거한 문구가 정확히 같은 경우만 대표 인용으로 묶는다.
   - `병원`과 `의료기관`처럼 문언이 달라지면 합치지 않는다.
   - 묶은 건수와 서로 다른 정의 중 표시한 건수를 경고에 명시한다.

2. 사전판정 근거
   - `보상하지 않는 사항` 원문에서 실제 담보 범위를 추출한다.
   - 화면에는 `보상하지 않는 사항 · 상급병실료차액보험금`, `보상하지 않는 사항 · 요양병원 의료비`처럼 표시한다.
   - 같은 조항 안에서 면책 범위와 예외 범위가 동시에 매칭돼도 코드별 인용은 한 건만 반환한다.
   - API에 `scope`와 `occurrence_id`를 포함한다.

3. 상품명 검증
   - 입력 상품명이 보험사의 어떤 후보에도 맞지 않으면 `product_not_matched`로 기권한다.
   - 잘못된 상품명을 무시하고 가입일만으로 다른 약관을 선택하던 폴백을 제거했다.

4. 검증 자산
   - 개명된 MCP 테스트를 가리키던 요구사항·보안 매트릭스의 오래된 노드명을 수정했다.
   - 독립 검증 에이전트의 원본 PDF/S6/S7 대조 결과를 반영했다.

## 검증 결과

관련 회귀 묶음은 모두 통과했다. 실데이터 스모크에서 제보된 DB손해보험 세 구절은 안전하게 두 정의 그룹으로 분리됐고, 삼성생명 F32 근거는 특약별 한 건씩 총 두 건으로 유지됐다.

## 잔여 배포 조건과 위험

- 배포 체크아웃만으로 전체 테스트를 실행하면 저장소에 포함되지 않은 S7/평가 산출물, 로컬 LLM, PG, 얼굴 모델 의존 테스트가 실패한다. 배포 검증 환경에는 승인 산출물 마운트와 의존 서비스를 준비해야 한다.
- S6/S7 구조화 데이터가 새 특약의 상위 제목을 잃고 `별표2`를 반복 사용하는 원천 문제는 남아 있다. 이번 변경은 원문 담보 범위를 표시해 사용자 오인을 막지만, 다음 추출 릴리스에서는 특약 경계를 구조 필드로 보존해야 한다.
- 의미 기반 퍼지 중복 제거는 적용하지 않았다. 보험 약관은 단어 하나의 차이도 유지해야 한다.
