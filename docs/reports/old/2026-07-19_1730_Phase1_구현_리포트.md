## 1. 작업 목표
기존 `rag/qa.py`(FAISS+프롬프트+LLM 혼합)를 **개념적 Clean Architecture 경계 뒤로** 옮긴 첫 수직 슬라이스.
이후 pgvector/GraphRAG 어댑터를 같은 포트로 교체·비교하는 토대(v3.2 ADR-005').

## 2. 수행 내용 (변경/신규 파일)
**신규 — Application 계층**
- `app/application/ports.py`: `Evidence`(중립 DTO, 정규화 score[0,1]·백엔드필드 비노출), `RetrieverPort`, `ModelGateway`.
- `app/application/answer_question.py`: `AnswerQuestion` 유스케이스 + `AnswerResult`/`Citation`. 빈질문→ValidationErr,
  근거없음→abstention(NO_ANSWER, 모델 호출 안 함), 빈응답→LLMOutputError, 출처 결정론 구성.

**신규 — Adapter 계층**
- `app/adapters/faiss_retriever.py`: `RetrieverPort` 구현. 기존 `rag.service.search` 호출 후 Evidence 매핑 +
  점수 정규화(FAISS L2제곱 [0,4] → score=1-d/4). page(0-based)→locator(1-based 문자열).
- `app/adapters/llm_gateway.py`: `ModelGateway` 구현. 모델 ID를 **레지스트리**에서 해석(하드코딩 아님).
  연결/HTTP 실패→InfraError 전파.

**신규 — 모델 레지스트리**
- `model_registry.yaml`: 프로필(local_gemma4_e4b, local_qwen35_4b). checksum/verified_at=null→verified=false(정직).
- `app/core/model_registry.py`: Pydantic 스키마 + 로더. latest alias·빈 provider_model_id 거부, 중복 profile_id 거부.
- `app/core/config.py`: `ACTIVE_MODEL_PROFILE` 선택자 필드 추가(모델ID 아님).

**변경 — 경계 정리·배선**
- `app/core/errors.py`: FastAPI import를 **지연 import로** 옮겨 모듈 레벨 순수화(Application이 예외타입만 안전 import).
  핸들러 등록 동작·기존 import 경로 불변.
- `app/routers/rag.py`: `/api/rag/qa`가 `AnswerQuestion`(composition) 경유. 응답 shape는 레거시와 동일 유지.
- `app/composition.py`: 어댑터→유스케이스 조립 루트.

**신규 — 테스트 페이크·계약**
- `tests/fakes/`(FakeRetriever, FakeModelGateway) — 런타임 선택 불가.
- `tests/test_answer_question.py`(7), `tests/test_arch.py`(2), `tests/test_model_registry.py`(7).

**전략(strangler)**: 레거시 `rag/qa.py`는 MCP가 아직 사용하므로 **이 Phase 한정 공존**. Phase 8에서 수렴.
