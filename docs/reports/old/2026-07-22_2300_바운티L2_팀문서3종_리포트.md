## 2. 수행 내용

### 2-1. L2 구현 — `app/application/bounty_settlement.py`
- **상태 전이표**: 허용된 전이만 통과, 나머지는 `ConflictErr`(409).
  차단되는 대표 경로: L1 건너뛴 `open→escrowed`, 기간 건너뛴 `escrowed→settled`,
  종료 상태 되돌리기(`settled→dispute_window`).
- **`PointLedger`**: 음수 잔액 금지, 부분 예치 금지(잔액 부족 시 전체 실패), escrow에 묶인
  포인트는 잔액에서 빠져 이중 사용 불가, 멱등키 재사용은 409.
- **`reject`**: escrow를 요청자에게 환불하고 stake는 **보존**(부정행위가 아닌 기각 경로).
- **`slash`**: `SLASHABLE`(위조 인용·미확인 출처·중복)에만 적용. 주관적 사유는 원장을
  건드리기 **전에** `ValidationErr`로 거부.
- **`settle`**: 이의제기 기간 경과 확인 후 provider 지급.

## 3. Codex 검토와 수정 (2문서 모두 첫 판정 **불합격**)

### 논리 오류 교정 (가장 중요)
초판은 “**사실성을 자동 검증할 수 있다면 그 지식을 살 이유가 없다**”는 논리를 썼는데,
Codex 지적대로 **일반적으로 성립하지 않는다** — 발견 비용과 검증 비용은 다를 수 있다.
→ 문제의 본질을 **“정답(ground truth)의 부재”**로 재서술하고, **재설계 문서(§1)까지 함께 교정**했다.
이 논리는 세션 내 여러 곳에서 반복 사용됐던 것이라 원본 문서를 고치는 것이 필요했다.

### 사실 오류
- “4가지 거부 경로” → 실제 **3가지**(06·07·08).

### 과장 완화
- “거짓을 경제적 손해로 만든다” → “**확인 가능한 위반**에 비용을 붙인다”
  (근거가 갖춰진 그럴듯한 허위는 통과함을 명시)
- “동시 요청에도 초과판매가 나지 않는다” → **설계·단위 테스트 범위**로 한정(부하 실측 미수행)
- “CI 현재 초록” → **확인 시점(2026-07-22)** 명시
- 운영 앱 기능 목록의 “바운티” → “**바운티 API**(전용 UI 없음)”
- 바운티 미구현 범위에 **DB 영속화·전용 UI** 추가 표기

### 누락 보강
- **이의제기 절차** 표 추가: 제기 주체(요청자·운영자만) · 기간 · **필요 근거**(확인 가능한 3사유) ·
  판정 주체 · 결과 3갈래(`settled`/`rejected`/`slashed`) · “틀린 것 같다”는 몰수 사유가 아님.
  → 문서가 코드보다 앞서가지 않도록 `reject`/`slash` 함수를 **실제로 구현**해 일치시켰다.
- 팀 작업 시작용: **환경변수·외부 의존성 표**(없으면 어떤 오류가 나는지), **최소 검증 명령**,
  **미구현 우선순위 + 완료 조건**.

### 사용자 지적 반영 (문서 A §01 전면 재작성)
“한 문장 정의”가 설계 속성만 나열해 **팀원이 무슨 서비스인지 알 수 없다**는 지적을 받았다.
정당한 지적이므로 다음으로 교체했다.
- 평범한 말 한 줄: “AI 상담원이 붙어 있는 온라인 쇼핑몰”
- **실제 데이터 기준 예시 3개**: 정책 질문(근거 있음 → “7일”, 출처 `환불교환정책.pdf`) /
  문서에 없는 질문(→ 지어내지 않음) / 주문(미리보기 → 승인)
- 구성 요약(화면 9개=고객4+운영5, 라우터 16, 로컬 AI), 왜 이렇게 만들었는지(무폴백 설명)
- ★검증 중 **자체 오류 발견**: abstention 문구를 `"제공된 근거만으로는 답변을 확정할 수 없습니다"`로
  썼는데 이는 **자기검증 차단** 메시지였다. RAG 근거 없음은 `NO_ANSWER =
  "제공된 문서에서 찾을 수 없습니다."` → 코드 확인 후 수정.
