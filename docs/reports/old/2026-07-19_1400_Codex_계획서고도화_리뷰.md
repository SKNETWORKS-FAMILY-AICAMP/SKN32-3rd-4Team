# A. 총평

진행 판단: **v3.0 그대로는 구현 착수 금지(No-Go), 범위를 줄인 v3.1은 진행(Go)**.

현재 제품의 핵심 가치는 다음 닫힌 루프다.

> 인증 사용자 질문 → 근거 문서 RAG/상품 도구 조회 → 추천·비교 → 주문 미리보기 → 명시적 승인 → 주문 생성 → trace 기반 관리자 확인 → 동일 조회 기능을 MCP로 재사용

여기서 빼면 제품가치가 죽는 것은 출처 기반 RAG, 결정론적 가격·재고, 승인 주문, REST/MCP 유스케이스 공유, 최소 관리자 추적 기능이다. 음성·화상·Passkey·풀 바운티경제·4모델 실시간 라우터는 없어도 이 루프는 성립한다.

가장 큰 리스크 3개:

1. **현행 자산을 과대평가한 범위**

   v3.0은 장바구니·역할 권한·관리자·바운티·Realtime·WebAuthn이 이미 있거나 짧게 연결 가능한 것처럼 취급한다. 실제 DB는 User/Product/Inventory/Order/OrderItem/Payment 6개 모델뿐이고 Cart·Role·Admin·Bounty 엔티티가 없다. [v3.0 MUST 범위](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_2/AI_에이전트_커머스_지식바운티_통합_구현계획서_LLM용.md:55), [실제 DB 모델](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/db/models.py:17)

2. **YAGNI를 깨는 아키텍처·데이터 전환**

   기존은 SQLite+FAISS인데 v3.0은 30여 테이블, PostgreSQL+pgvector, Hybrid/Rerank/claim checker, 다수 포트를 한 번에 도입한다. 검증된 182개 자산을 활용하는 strangler가 아니라 사실상 재개발이 된다. [pgvector 전제](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_2/AI_에이전트_커머스_지식바운티_통합_구현계획서_LLM용.md:709), [현행 FAISS](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/rag/service.py:24)

3. **RULE·하드웨어·검증 기준의 충돌**

   v3.0은 자동 모델 fallback을 MUST로 두지만 RULE은 폴백을 금지한다. 또한 약 5GB/CPU 환경에 Qwen3.6-27B·35B와 Gemma 4 12B를 로컬 MUST로 두는 것은 배치 불가능하다. DoD의 95% supported claim rate도 평가셋 크기·판정기·명령·산출물 연결이 없다. [RULE 폴백 금지](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/RULE.md:58), [v3.0 fallback](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_2/AI_에이전트_커머스_지식바운티_통합_구현계획서_LLM용.md:177)

검증 한계: 저장소 리포트에는 최종 **182개 통과**가 기록되어 있다. [최종 인수 리포트](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/reports/2026-07-18_1745_최종_인수점검_반영_리포트.md:83) 이번 검토 환경은 쓸 수 있는 임시 디렉터리가 없어 pytest가 수집 전에 중단됐으므로, 182개는 파일 근거로 확인했지만 독립 재실행하지는 못했다.

# D. RULE 정합 지적

## 치명

1. **자동 fallback 명시**

   v3.0은 모델 및 STT/LLM/TTS fallback을 요구한다. [모델 fallback 요구](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_2/AI_에이전트_커머스_지식바운티_통합_구현계획서_LLM용.md:177), [음성 fallback](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_2/AI_에이전트_커머스_지식바운티_통합_구현계획서_LLM용.md:925)

   v3.1 조치: 자동 교차모델 전환을 삭제한다. 선택한 프로필이 실패하면 명시 오류를 반환한다. 다른 프로필 사용은 관리자/사용자가 새 요청으로 명시 선택한다.

2. **YAGNI 위반 범위**

   Realtime, video, Passkey, 7역할, 30여 테이블, 바운티경제, 4모델, remote MCP를 모두 MUST로 둔다. 단일 개발자의 검증 가능한 최소 작업 단위가 아니다.

3. **현행 기능 오인**

   “기존 장바구니 유지”는 실제 코드와 불일치한다. 현재 인증도 username/password/JWT뿐이며 역할 필드가 없다. [User 모델](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/db/models.py:17), [JWT payload](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/auth/security.py:33)

## 높음

1. **모델 ID 하드코딩**

   현행 `config.py` 소스에 `gemma-4-e4b`, `gpt-4o-mini`, `gemini-2.5-flash`, 임베딩/감성 모델명이 들어 있다. 설정 모듈에 모았더라도 RULE 문언상 소스 하드코딩이다. [config](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/core/config.py:29)

2. **모델·하드웨어 불일치**

   Qwen3.6-27B/35B-A3B와 Gemma 4 12B를 5GB 환경의 로컬 MUST로 둘 수 없다. 구동 검증 없는 adapter와 contract test는 가짜 완료가 된다.

3. **DB 전환 근거 부재**

   동시 사용자, corpus 크기, 업데이트 빈도, p95, FAISS 장애 사례가 전혀 없다. 따라서 PG/pgvector 전환은 “미래 교체 가능성”만을 위한 구현이다.

4. **주문 승인·멱등성 계약 부족**

   현재 주문 POST는 즉시 주문 생성과 재고차감을 수행하며 idempotency key가 없다. [create_order](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/routers/orders.py:35) v3.0 NFR에 멱등성을 적었지만 API/DB unique key/TEST ID가 없다.

5. **DoD가 자동검증과 연결되지 않음**

   “supported claim rate 95%” 등의 수치에 dataset version, 분모, evaluator, 명령, 결과 파일이 없다. 체크박스만으로는 RULE의 검증·리포트 의무를 만족하지 못한다.

## 중간

1. **불필요한 포트 선제 생성**

   `PaymentGateway`, `RealtimeGateway`, `ReportRenderer`, `UnitOfWork` 등을 skeleton부터 만들면 미사용 코드가 된다. 실제 다음 Phase에서 교체할 경계만 생성해야 한다.

2. **이중 에이전트 운영**

   수동 ReAct와 LangChain ReAct가 같은 목적의 두 API로 노출된다. RULE은 같은 기능의 두 구현을 통합하도록 요구한다.

3. **RAG의 검증 수준 과장**

   현행 출처는 모델 문장별 binding이 아니라 검색 결과의 `(source,page)` 목록이다. [source 구성](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/rag/qa.py:53) v3.0의 “문장별 출처 완료”와 동일하지 않다.

4. **기동 시 자동 DB·인덱스 변경**

   앱 시작 시 테이블 생성·seed·인덱스 재빌드를 자동 수행한다. [lifespan](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/main.py:37) 개발 편의에는 맞지만 운영에서는 명시적 migration/ingestion 명령과 readiness 실패로 분리해야 한다.

5. **직접 호출에서의 `k or default`**

   HTTP/MCP는 `ge=1` 검증하지만 `service.search(..., k=0)` 직접 호출은 기본값으로 조용히 바뀐다. [RAG search](/C:/Users/playdata2/Documents/llm_workspace/_unified_mall_agent_project/app/rag/service.py:43) `k if k is not None else default`로 바꿔야 한다.

6. **데이터 카탈로그 부재**

   현재 문서 데이터는 TXT 3개와 PDF 1개 수준이며 source license, checksum, sensitivity, expected use가 없다. 이 상태로 95% 품질 목표를 선언할 수 없다.

| 환경 | 모델 정책 |
|---|---|
| 결정론 CI | `FakeModelGateway`만 사용. 실제 모델 자동 fallback 없음 |
| 기본 로컬 후보 | 기존에 검증한 **Qwen3.5-4B Q4** 1개. 정확한 GGUF repo/revision/SHA256을 registry에 기록한 뒤 승인 |
