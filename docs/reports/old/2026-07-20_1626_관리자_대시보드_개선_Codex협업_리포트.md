# 관리자 대시보드 UI 개선 — Codex CLI 협업 설계 반영

- 작성일시: 2026-07-20 16:26
- 계기: 사용자 요청 "대쉬보드 ui 부분은 코덱스 cli 랑 의논해서 개선해봐. 코덱스가 짜게 해보고
  그거 반영해도 되고 일단 해봐" (같은 메시지에 A2A/화상채팅/고객화면 질문도 포함 — 별도 절 참조)

## 1. 진행 방식
1. 기존 `admin.html`(버튼 클릭식, 4개 엔드포인트를 개별 버튼으로 호출) 구조와 한계를 정리해
   Codex CLI에 프롬프트로 전달 — 요구사항: 로그인 후 자동 새로고침되는 요약형 대시보드,
   401/403/200 RBAC 사다리 유지, 기존 로그인 폼/무폴백 원칙(관리자 승격 버튼 없음) 유지.
2. Codex가 HTML 850줄 + JS 1124줄을 생성(`model_reasoning_effort` 미지정 시 xhigh로 동작,
   CLI가 출력을 통째로 두 번 echo하는 현상 확인 — `diff`로 바이트 동일함을 검증 후 한 벌만 채택).
3. 생성물을 그대로 쓰지 않고 리뷰 후 직접 통합(아래 3절 — Codex가 실제 프로젝트의 `common.js`
   내용을 못 봤으므로 API 응답 형태를 잘못 추측한 부분 등 발견·수정).

## 2. Codex 설계의 장점(채택)
- 상태(`state`) 객체 하나로 orders/events/knowledgeGaps/indexStatus/loading을 관리하고,
  로그인 성공 시 `Promise.allSettled`로 4개 엔드포인트를 병렬 호출 → 패널별 독립 에러 처리
  (한 API가 실패해도 나머지 패널은 정상 표시).
- `storage`/`focus`/`auth:changed` 이벤트로 로그인 상태 변화에 자동 반응(다른 탭에서 로그인해도
  갱신) — 기존 버튼식 UI에는 없던 기능.
- 주문 상태 배지, 이벤트 타임라인(trace_id 표시), 지식갭 필터(상태/검색) 등 실제 운영자가 볼
  요약 화면에 필요한 정보 구조를 자체적으로 잘 설계함.

## 3. 통합 중 발견·수정한 버그 3건 (Codex 결과물, 반영 전 검증)
1. **`fetchApi()` 응답 형태 오추측**: 이 프로젝트의 `apiFetch`(common.js)는
   `{status, ok, body}`를 반환하는데, Codex는 프롬프트에 실제 코드를 못 받아 `fetch Response`
   (`.json()` 있음)일 수도 있다고 방어적으로 추측 — 실제 형태에서는 그 추측 분기를 타지 않고
   잘못된 래퍼 객체를 그대로 반환하는 버그였다. 내가 `common.js`를 직접 아는 상태라 재문의 없이
   직접 수정(`result.body` 반환하도록 정정).
2. **401/403 메시지 혼용**: 원래 코드는 두 상태를 모두 `showAuthenticationRequired()`
   (“로그인이 필요합니다”)로 처리 — 403(로그인은 됐지만 권한 없음)에 오해의 소지가 있는 문구였다.
   분기를 나눠 403 전용 메시지(“관리자 권한이 없는 계정입니다…”)로 교체.
3. **로그인 폼 부재**: Codex 프롬프트에 “기존 로그인 폼 재사용”을 명시했기 때문에 의도된
   결과(버그 아님) — `#adminUsername/#adminPassword/#adminLoginBtn/#logoutBtn/#loginStatus` +
   CLI 전용 승격 안내문을 직접 이식하고, `cacheElements()`에 참조를 추가한 뒤 로그인/로그아웃
   핸들러(`apiFetch("/auth/login", …)` → `setAuth` → `auth:changed` 디스패치)를 새로 작성했다.

## 4. 통합 후 라이브 테스트 중 발견·수정한 버그 1건 (내 통합 작업의 버그)
지식갭 패널 헤더(`.panel-header`)가 우측 컬럼(380~420px)에서 필터(select+input, 고정폭
~300px)와 제목("지식갭 · N건")을 한 줄에 억지로 배치하다 보니, 제목 영역이 거의 0px로
찌그러져 **한글이 한 글자씩 세로로 줄바꿈**되는 렌더링 버그가 실제 로그인 화면에서 확인됐다
(스크린샷 촬영 중 발견). `flex-wrap: wrap` + `.filters { flex-shrink: 0 }`로 수정 —
좁은 화면에서는 필터가 다음 줄로 내려가고 제목은 항상 온전히 보이도록 정정.

## 6. 별도 처리한 부수 이슈 — main.py 오염 발견
작업 도중 `_unified_mall_2/app/main.py`가 **커밋되지 않은 상태로 다른 실습 프로젝트**
(`_0719_ai_agent_1/research_agent_fastapi_final`)의 `main.py` 내용으로 통째로 덮어써져 있는
것을 발견했다(dev 서버가 `ModuleNotFoundError: No module named 'app.api'`로 기동 실패해서
드러남). git reflog 확인 결과 이 저장소의 커밋 이력에는 원인이 없었다 — 순수 워킹트리 상의
비커밋 변경이었고, 이번 세션에서 내가 건드린 적도 없다. 사용자에게 상황을 보고하고 승인을 받은
뒤 `git checkout HEAD -- app/main.py`로 마지막 커밋(`fa32fb5`) 상태로 복원했다(데이터 손실
없음 — 애초에 커밋된 적 없는 오염이었으므로).

- **고객용 화면/모바일 화면**: 아직 미착수. 이번 메시지의 실행 지시("일단 해봐")는 "대쉬보드
