# Phase 15 — A2A(Agent-to-Agent) 에이전트 간 위임

- 일자: 2026-07-22
- 범위: 외부 참조 프로젝트(`_0722_ai_agent_3`, `_0721_ai_agent_2`)와 기술 격차 대조 후,
  우리에게 없던 **A2A** 기법을 우리 스타일로 구현.
- 워크플로: 격차분석 → 구현 → 회귀 → Codex 점검 → 수정 → 리포트 → 커밋.

## 1. 기술 격차 대조 결과

두 폴더의 하위 프로젝트(final_system_…langgraph_mcp, business_agent_fastapi_final,
coding_agent 등)를 우리 `_unified_mall_2`와 대조:

| 기술 | 그쪽 | 우리 | 격차 |
|---|---|---|---|
| **A2A(에이전트 카드 발견 + 위임)** | ✅ | 없음 | ✅ **유일한 실제 격차** |
| LangGraph StateGraph | ✅ | ✅ `app/workflow/ticket_graph.py` 보유 | 아님 |
| LangChain ReAct | ✅ | ✅ `app/agent/lc_agent.py` 보유 | 아님 |
| MCP/RAG/FAISS | ✅ | ✅ 보유(+pgvector·GraphRAG·reranker로 더 많음) | 아님 |
| React | 폴더명뿐, 실제 Jinja2(package.json 없음) | 바닐라 정적 JS | 허명, 아님 |

결론: 실제 미구현 기술은 **A2A 하나**. 나머지는 이미 보유했거나 실체가 없음.

## 2. 구현 (우리 스타일로)

- `app/a2a/cards.py` — `AgentCard`(name/description/skills/endpoint/version) + `AGENT_CARDS`
  레지스트리 + `list_agent_cards()`. **프레임워크 무의존**(dataclass·stdlib만).
- `app/a2a/gateway.py` — `delegate_to_agent(db, target, message)`. 전문 에이전트 4종이
  **기존 서비스를 재사용**(중복 없음): order→`get_order_status`, catalog→`get_price`/`get_stock`/
  `search_product`(의도 분기), knowledge→`search_knowledge_base`(RAG), recommend→`recommend_products`.
- `app/routers/a2a.py` — `GET /api/a2a/agents`(발견), `POST /api/a2a/message`(위임).
- `app/main.py` — A2A는 **운영/통합 표면**(MCP와 동급) → 고객 공개 포트 미탑재(404).

### 참조 대비 우리가 개선한 점
- 참조는 미등록 에이전트에 **문자열을 반환하는 폴백** → 우리는 `ValidationErr`(422) 무폴백.
- 주문번호/입력 누락도 문자열 안내가 아니라 422.
- 카드-핸들러 이중 레지스트리가 어긋나면 **import 시점 fail-fast**(카드만 추가 시 호출 KeyError 방지).
- 카드가 광고한 '가격 조회' 능력을 실제 `get_price`로 분기(카드-실행 계약 일치).

## 3. Codex 점검 (2라운드)

- 1차: "카드 발견+명시적 위임은 실구현. 무폴백 422·고객포트 404는 참조보다 낫다"고 확인하되,
  ①카드가 광고한 가격조회 미분기 ②이중 레지스트리 드리프트 위험 ③`search_knowledge_base`
  중복 구현 ④운영 API 무인증을 지적.
- 조치: ①가격 의도 분기 ②import fail-fast 불변식 ③기존 도구 재사용으로 교체.
  ④는 운영 포트=VPN 내부 가정(rag/mcp와 동일 모델)이라 단독 인증을 두지 않고 문서화.
- 한계 정직 기록(`docs/architecture.md §9`): A2A는 **인프로세스 함수 위임 façade**(참조와 동급)
  — 원격 HTTP·작업 수명주기·표준 Agent Card 상호운용까지의 완전한 A2A 프로토콜은 아님.

## 4. 원칙 준수

- 무폴백: 미등록·빈입력·식별자 누락 전부 ValidationErr. 비즈니스 실패(없는 주문/상품)는
  기존 서비스의 구조화 관찰({ok:false})을 그대로 반환(정의된 관찰, 폴백 아님).
- 무하드코딩: 주문/상품 형식 정규식은 실데이터 형식(O+6/P+4)에 명명 상수화.
- 클린아키텍처: cards는 프레임워크 무의존, 위임은 기존 서비스 재사용(중복 없음).
