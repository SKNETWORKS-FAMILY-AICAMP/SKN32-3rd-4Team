# Phase 13 — 얼굴 로그인 2차 인증 (패시브 라이브니스 포함)

- 작성일시: 2026-07-20 21:30
- 계기: `프로젝트설명.txt` [추가 서비스 제안] 5번(얼굴 로그인 2차 인증). 사용자 지시로 웹서치로
  최신 방식 조사 + Codex 2라운드 논의 후 원안(임베딩만) 대비 **라이브니스 추가**로 강화.

## 1. 방식 결정 (웹서치 + Codex)
- **채택(옵션 B, Codex 추천)**: insightface(onnxruntime/CPU, 512차원 정규화 임베딩) +
  **Silent-Face MiniFASNetV2 ONNX**(MiniVision, Apache-2.0, 1.7MB, onnxruntime만·tensorflow
  불필요)로 패시브 라이브니스. DeepFace(옵션 A)는 tensorflow/tf-keras를 끌고 와 CPU 환경에
  무거워 제외.
- **라이브니스 깊이(사용자 확정)**: 패시브 단일 프레임만(액티브 챌린지 제외) — 데모 범위에서
  과설계 회피, 한계는 문서화.

## 2. 구현
- `app/ml/face.py`: insightface FaceAnalysis + Silent-Face ONNX 세션 lazy 싱글턴.
  `analyze_face()`가 게이트 순서(디코드 → 단일 얼굴 → 라이브니스 → 임베딩)를 강제. Silent-Face
  원본 크롭 로직(bbox 중심 scale 2.7 확대)을 정확히 구현. 모델 로드 실패 ConfigError, 얼굴
  없음/복수/이미지 파손 ValidationErr(무폴백).
- `app/db/models.py` `FaceCredential`(user당 1개, 원본 사진 미저장·512 float32 임베딩만).
- `app/services/face_service.py`: 등록/검증 + **감사 이벤트**(record_event: liveness_fail/
  mismatch/ok/locked) + **인메모리 시도 제한**(FACE_MAX_ATTEMPTS, 데모: 재시작 시 초기화 한계
  명시). 라이브니스·매칭 실패는 **동일 일반 메시지**("얼굴 인증에 실패했습니다")로 정보 노출 최소화.
- `app/auth/security.py`: 토큰 `stage` 클레임 추가 — `full`(정상)/`pre2fa`(얼굴 대기 단명).
  `get_current_user`는 pre2fa 거부, `get_pre2fa_user`는 pre2fa 전용. 구 토큰(stage 없음)은
  full로 간주(하위호환).
- `app/routers/auth.py`: `/auth/login`이 얼굴 미등록이면 토큰, 등록이면 `face_2fa_required` +
  단명 challenge_token(5분) 반환. 신규 `/auth/login/face`가 challenge + 얼굴로 최종 토큰 발급.
- `app/routers/face.py`: `/api/face/status|register|register(DELETE)` — 모두 로그인 세션 전용
  (`get_current_user`) → 체인 잠김 방지(미인증 상태에서 얼굴만으로 등록/로그인 경로 없음).
- 프론트: `mypage.html`/`mypage.js`(로그인 2FA 분기 → 얼굴 촬영 인증 → 등록/삭제 생애주기),
  `common.js`에 `captureFrameBlob()` 웹캠 정지프레임 캡처 추가. 전 페이지 nav에 마이페이지 링크.
- `scripts/fetch_face_model.py`(ONNX 다운로드), requirements에 insightface/onnxruntime/opencv 고정.

## 3. 게이트 순서·무폴백 (Codex 권고 반영)
비밀번호 → 촬영 품질/단일 얼굴 → 라이브니스 → 임베딩 비교 → 토큰. 어느 단계든 실패하면 토큰
없이 종료, 얼굴 실패 시 비밀번호만으로 폴백 금지. 라이브니스 실패 입력으로 신원 비교를 하지
않아 연산·노출도 감소.

## 4. 검증
- `pytest -m ml tests/test_face.py` — **7 passed**: 동일인 코사인 0.985(≥0.40)·타인 0.083(<0.40),
  라이브니스 확률 유효, 전체 2FA 흐름(등록→로그인 챌린지→얼굴 매칭 토큰 발급, 타인 얼굴 401),
  얼굴 미등록 계정 2FA 미적용, 등록은 인증 필요(401), pre2fa 토큰 보호 리소스 거부(401).
- `pytest -m "not llm and not ml and not pg and not mcp"` — **323 passed**(회귀 0). auth
  응답 스키마 변경(TokenResponse→LoginResponse)은 얼굴 미등록 계정에 access_token을 그대로
  주므로 기존 테스트/프론트 호환.
- 실 dev 서버 + 브라우저(fetch): signup 200, login(미등록)→face_2fa_required=false+토큰,
  얼굴상태 {registered:false}, 얼굴 없는 이미지 등록→422 "얼굴이 감지되지 않았습니다"(실
  insightface 동작). 페이지 상태머신(로그아웃=로그인패널) 확인.

## 5. 정직한 한계 (과장 금지, README/리포트 명시)
- **라이브니스 실검증 불가**: 이 헤드리스 환경은 실 웹캠 라이브 얼굴 vs 사진/화면 쌍을 만들 수
  없어 라이브니스 정확도를 검증하지 못했다. 실제로 정지 사진 크롭은 전부 spoof로 판정됨(0.0002~
  0.005) — 이는 "사진=위조"라는 **의도된 동작**일 수 있으나, 실 라이브 얼굴 수용은 미검증. 그래서
  흐름 테스트는 라이브니스 임계를 0으로 낮춰 신원/토큰 로직만 확인했다.
- **단일 모델**: 원본 Silent-Face 2모델 앙상블이 아니라 2.7 단일 모델. 임계값은 라이브러리 근사
  기본이며 실데이터 튜닝 아님.
- **미방어**: 재생영상·딥페이크·카메라 주입 공격, 공인 PAD(iBeta) 성능 보장 안 함.
- **insightface 사전학습 모델은 비상업 연구용 라이선스** — 포트폴리오/학습 용도임을 명시.
- 시도 제한은 인메모리(프로세스 재시작 시 초기화·멀티프로세스 미공유).
- 다른 페이지(admin/orders)의 단순 로그인 폼은 2FA 단계를 구현하지 않음 — 얼굴 등록 계정은
  마이페이지에서 로그인해야 함(후속 통합 여지).
