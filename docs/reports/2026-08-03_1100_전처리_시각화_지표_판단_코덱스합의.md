## 2. "안 좋아 보이는" 진짜 이유 — 넷

### 2-1. ★`s6` 라는 이름이 특정 산출물을 가리키지 않는다

**같은 태그로 최소 3판이 존재한다.**

| 시점 | 조항 | `parse ok` | 출처 |
|---|---:|---:|---|
| 09:00 | 204,121 | 1,288 | `2026-08-03_0900_전처리_s6_부록분리_결과.md` |
| 10:05 | **204,098** | **1,306** | `preprocess_viz.html` |
| 10:24~ | 측정 불가 | — | 지금 재실행 중 |

`CLAUDE.md §1` 이 *"경로에 버전을 넣어 **덮어쓰지 않고 공존**시킨다"* 고 한 규칙이 s6 에서 깨졌다.

★**이것 때문에 무효가 되는 것은 "run 을 특정하지 않은 s6 수치와 그에 따른 채택 판단"이다.**
안정된 s5, 원문 코퍼스, 코드 수준 안전장치까지 무효인 것은 아니다.
(초안에서 "나머지 모든 판단을 무효로 만든다"고 썼다가 코덱스 지적으로 좁혔다)

### 2-2. 성격이 다른 셋이 한 화면에 있다

| 화면 요소 | 실제 성격 |
|---|---|
| 헤더 6개 지표 | **미채택 s6 후보**의 품질 |
| G 표 (수록 74% · 고유 3.5%) | **DB 적재 진행률** — "품질이 나쁘다"가 아니라 "아직 안 넣었다" |
| 법령 31,283 · KCD 43,154 | **정상 데이터 규모** — 결함이 아니다 |

세 성격이 나란히 있으니 전처리가 실패한 것처럼 읽힌다.
게다가 G 표의 `211,131` 은 **s5 값**인데 헤더는 s6 다 — 문서 스스로 *"시점이 다른 숫자를 섞지 말 것"* 이라 경고해 놓고 표에서 섞였다.

> 단 코덱스 단서: 법령·KCD 규모는 결함은 아니지만 **급증·급감은 분류 경계 회귀를 잡는 모니터링 신호**로 유용하다. 지우지 말고 **줄을 나눠** 둔다.

### 2-3. 분모가 없고, 있어도 단위가 안 맞는다

`8,554` · `2,414` · `31,283` · `43,154` 는 전부 절대수다.
**그런데 전부 204,098 로 나누면 안 된다** — 단위가 다르다.

| 지표 | 올바른 분모 |
|---|---|
| `parse ok` · `suspect` | 문서 1,367 |
| 인용 모호 | 전체 인용 건 또는 인용 보유 조항 |
| 번호 못읽은 **항** | 전체 **항** 수 (조항 수가 아니다) |
| 법령 원문 | 조항 수 — 단 **결함률이 아니다** |
| KCD 범위 언급 | 언급 건이면 조항 수와 직접 나눌 수 없다 |

→ 조치는 "분모 병기"가 아니라 **단위별 올바른 분모 정의**다.

### 2-4. 비교군이 없다

s5 대비 개선이 `H-1`("133행 → 7행") 하나뿐이다. 나머지는 절대수만 남는다.

★**`parse ok 1,306/1,367 = 95.5%` 는 좋아 보이지만 정확도가 아니다.**
`parse_status=ok` 여도 두 버전이 같은 방식으로 틀리면 잡지 못한다 — **구조 상태 지표**다.
(초안에서 "실제 품질도 좋다"고 썼다가 코덱스 반박으로 정정)

## 3. 완료 후 조치 — 합의된 순서

```
1. 불변 run 경로로 동결        재실행 산출을 s6 에 덮어쓰지 않는다
                              run_id · 코퍼스 해시 · 코드 commit · 종료코드 · 파일 해시 manifest
2. 출처/상태 표시              모든 수치에 run_id · 코퍼스 해시 · 측정 시각 · 단위/분모 · pipeline 상태
3. ★지표 정의·단위·분모 계약    표시가 아니라 정의. 이게 있어야 5·6 이 성립한다
4. fallback 종단 격리 증명      438건 중 폰트 깨진 문서가 검색·인용 경로에서 실제로 차단되는가
                              ★증명 실패 시 즉시 P0
5. s5 ↔ s6 짝 비교             총량 말고 문서별 손실·신규·경계 이동·인용가능 변화
6. 정답셋 gate                 분모(패킷/span) 명시 · 신뢰구간 · 사전 임계값
                              ★치명 유형은 1건이라도 실패하는 zero-tolerance gate 별도
7. accept / hold / reject      기준은 "완벽"이 아니라 s5 대비 우월 + 알려진 위험이 안전 격리
8. 색인                        모델 선정 → 청킹 정책 → 평가셋 비교 → 전량 색인
9. 화면 표시 개선              섹션 분리 · 비율 표기
```

  pg 쪽 주석은 *"citation_eligible 로 걸러 **161문서만** 넣었다"*

**기본 file 경로에는 그 게이트가 아예 없다.** 없는 안전장치를 배너로 주장하면 안 된다.
