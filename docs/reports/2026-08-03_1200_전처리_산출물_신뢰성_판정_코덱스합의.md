# 전처리 산출물을 믿고 쓸 수 있나 — 실측 판정

작성 2026-08-03 12:00 · **코덱스 교차검증(최종 "이견" 수용)** · 검토만, 수정 없음

질문: *"시각화 수치가 안 좋아 보여서 — 이걸 전처리 자료로 신뢰하고 쓸 수 있는지 모르겠다"*

## 0. 답

> **지금 그대로는 안 된다. 단 데이터 품질이 나빠서가 아니라 릴리스 계약이 깨져 있어서다.**
>
> ★**승인 기록과 디스크 내용이 다르다.** `accepted_extraction.json` 은 s5 를
> `ok 1,108 / suspect 250` 으로 승인했는데, 지금 디스크는 **`ok 1,183 / suspect 175`** 다.
> **판정 근거 게이트가 기록 없이 움직였고, 75개 문서가 "믿지 말라"에서 "믿어도 된다"로 넘어갔다.**

게이트 4개를 채우면 **검색 + 사람 검토가 붙은 인용**부터 쓸 수 있다(§4).

## 1. ★최대 발견 — 승인 기록 ≠ 서빙 데이터

| | `parse_ok` | `suspect` | `no_clause_heads` | 조항 |
|---|---:|---:|---:|---:|
| `config/accepted_extraction.json` (승인 기록) | **1,108** | **250** | — | 211,131 |
| 디스크 현재 (12:00 실측) | **1,183** | **175** | 9 | 211,131 |
| 차이 | **+75** | **−75** | | 0 |

**조항 수는 같은데 `parse_status` 분포만 바뀌었다.** 즉 조항 추출은 그대로이고
**suspect 판정 규칙이 승인 이후에 완화**됐다.

근거 — `scripts/extract/to_clauses.py`:

```
L1118  실측(s5 전량): 이 경고로 `suspect` 가 된 135문서 중 85문서(63%)가 [목차가 아니다]
L1127  이걸 `suspect` 로 내리면 정상 문서 85건이 [불필요하게 배제된다]
L1194  parse_status = "ok" if not warnings else "suspect"
```

**규칙 개선 자체는 타당하다**(과탐을 줄인 것). 문제는 **승인 기록을 갱신하지 않은 것**이다.

★왜 이게 중대한가 — `parse_status == "ok"` 는 **"판정 근거로 써도 되는가"를 가르는 유일한 게이트**다
(`file_clause_store._to_clause`). 그 게이트가 **기록 없이 75문서를 통과시켰다.**
그리고 `app/core/release.py:113` 의 준비도 검사는 **문서 수 1,367 만 확인**하므로 이 변화를 못 잡는다.

> **같은 `s5` 라는 이름이 어제와 오늘 다른 데이터를 가리킨다.**
> `CLAUDE.md §1`("경로에 버전을 넣어 덮어쓰지 않고 공존시킨다")이 여기서도 깨졌다.

## 2. ★내가 틀린 것 — "구조 정합 불일치 0건"은 동어반복이었다

초안에서 **"제N조 조항 본문이 자기 조항머리로 시작 — 187,372건 중 불일치 0건"** 을
신뢰의 핵심 근거로 제시했다. **이 근거는 무효다.**

`to_clauses.py` 는 **같은 머리 매치에서 조 번호를 만들고(L926·L928), 그 머리의 offset 부터 본문을 자른다.**
따라서 이 검사는 **슬라이싱 버그가 있을 때만 실패**한다 — 머리 탐지가 틀려도 통과한다.

**정확한 표현**: *"포착된 제N조 블록에서, 부여된 번호와 블록 시작 머리가 모순된 사례는 없다."*
여기까지다. 아래는 **전혀 못 본다**(코덱스 지적, 전면 수용):

- 목차 줄도 유효한 조 머리로 시작하는 **false positive**
- 시작은 맞지만 **다음 조·부록까지 삼킨 종료 경계 실패**
- 조항 자체가 누락된 **false negative**
- 올바른 조항을 **잘못된 특약·section 에 귀속**
- OCR 누락 · 부정어 변형 · 표 본문 손실
- 본문은 맞지만 **페이지·offset 이 틀린** 경우
- `제N조` 가 아닌 **23,759청크**의 구조 문제

**반증도 이미 있다** — `accepted_extraction.json` 이 별도 구조 감사 신호를 기록해 뒀다:
`ABA 재진입 4,721` · `매몰된 조 머리 575` · `부록 흡수 4,789`.
정답셋이 없어 전부 결함이라 단정할 수는 없지만, **시작 머리 0건으로 종료 경계 건전성을 주장할 수 없다는 반증**은 된다.

## 4. 용도별 판정 (코덱스 이견 반영해 강도를 낮춤)

| 용도 | 판정 | 조건 |
|---|---|---|
| **검색(RAG) 후보 생성** | ⚠ **게이트 붙이면 가능** | 목차 조각 9,727 을 거르는 규칙이 **서빙 경로에 없다** |
| **인용 근거** | ⚠ **occurrence 식별자 도입 후 조건부** | 지금 키는 내용 키다. 위치가 특정되지 않는다 |
| **자동 보장 판정의 유일 근거** | ❌ **아니다** | 종료 경계·귀속 정확도를 잰 적이 없다 |

> 초안에서는 검색을 "✅ 쓸 수 있다"로 썼다가 **"⚠ 게이트 붙이면"** 으로 낮췄다.
> 근거였던 "구조 정합 0건"이 §2 에서 무효가 됐고, 목차 조각이 검색 상위에 못 온다는 것도
> **가정일 뿐 측정한 적이 없다**(코덱스 지적).

## 5. 지금 쓰기 시작하기 위한 **최소선 4가지** (코덱스 안 채택)

### 5-1. 서빙 산출물 고정
승인 manifest 에 **파일별 해시 또는 릴리스 digest + 상태·청크 집계**를 박는다.
지금은 같은 `s5` 이름의 내용이 바뀌어도 통과한다(`release.py` 가 문서 수만 본다).

### 5-2. 공통 eligibility 게이트 — 파일·PG·검색·인용이 **같은 규칙**을 쓴다
```
parse_status == ok
page_fallback 제외
본문 없는 목차형 조각 제외          ← 지금 없다
20,000자 초과 경계 붕괴는 인용·자동판정에서 제외
eligibility 를 모르면 fail-closed   ← 지금은 필드 부재가 fail-open 이다
```

### 5-3. occurrence 식별자 도입
`clause_id` 는 **내용 정체성 키로 남기고**, 인용에는 별도 키를 쓴다:
`(release_id, sha, ordinal)` 또는 `(sha, qualified_no, page, offset, full_content_hash)`.
★**검증기는 이 키로 정확히 한 행이 조회될 때만 통과**시킨다.
`to_clauses.py:871` 에 이미 `(sha, ordinal)` 을 결정적 식별자로 쓰겠다는 설계가 있다.

### 5-4. 작은 실제 검색 검증셋
전체 정상률 대신 아래를 잰다.
- **목차형 질의의 contamination@k**
- 면책·예외·KCD 핵심 질의의 **recall@k**
- 중복 occurrence 인용의 **페이지 해소 정확도**

**이 넷을 채우면 → 검색 + 사람 검토가 붙은 인용**을 시작할 수 있다.
자동 판정의 유일 근거로 올리려면 **업무 정답셋 + fail-closed 기권 검증**이 별도로 필요하다.

## 6. 이 검토에서 내가 과대·과소 평가한 것

**과대평가**
- `94.9%` 를 "정상"이라 부른 것 → 정확히는 **세 규칙에 안 걸린 비율**이다
- 짧은 목차 조각은 검색 상위에 못 온다는 **가정**(측정한 적 없다)
- 시작 머리 일치 0건을 **전체 경계 정확성**으로 확장한 것
- 중복 ID 영향이 "쪽수 문제로만 끝난다"는 평가 → 검증 비결정성·정상 인용 거절도 생긴다

**과소평가**
- **suspect 게이트는 코드 수준에 이미 있다** — `file_clause_store` 도 유스케이스도 `ok` 만 허용한다.
  필요한 건 운영 설정을 포함한 **end-to-end 증명**이지 게이트 신설이 아니다
- ★**가장 큰 신규 위험은 승인 메타데이터와 현재 s5 의 불일치**다. 이 상태면
  **오늘의 실측이 내일도 같은 데이터를 뜻한다고 보장할 수 없다**
- `citation_eligible` 부재는 게이트 문제가 아니라 **산출물 계약 문제**다.
  적재기가 `False` 만 제외한다면 **필드 누락은 사실상 fail-open** 이다
