## 1. 작업 목표

앞선 리포트가 남긴 문제는 이것이었다.

> 계획서가 든 예시 질문 *"상급종합병원 **통원** 자기부담금"* 을 아직 답할 수 없다.
> `ok` 4,471건 중 `입통원` 이 사실로 채워진 것이 **22건(0.5%)** 뿐이다.
> 원인은 표 맨 왼쪽 `담보종목` 열을 `find_tables` 격자가 대개 포함하지 않는 것이다.

이번 세션에서 한 일은 셋이다.

1. **원인을 리포트가 아니라 데이터로 다시 확인한다.**
2. **축을 채운다.** 단, 되찾은 값이 사실인지 추론인지 갈라서 저장한다.
3. **죽은 필드(`한도금액`·`한도단위`·`단위`)를 실측으로 판정하고 처리한다.**

## 2. ★원인 확인 — 리포트의 진단은 **절반만 맞았다**

### 2.1 `tables_coords` 는 이 문제의 답이 아니다 (경로 (c) 기각)

`ok` 레코드가 나온 쪽 **1,439쪽**을 전수로 봤다.

| 측정 | 값 |
|---|---:|
| `ok` 레코드가 나온 쪽 | **1,439** |
| └ `pages[].tables_coords` 가 **비어 있는** 쪽 | **1,329 (92.3%)** |
| └ `tables_coords` 가 있는 쪽 | 110 |
| └ 그중 `tables_coords` 안에서 담보종목 낱말이 걸린 표 | **0** |

> **좌표 표로 갈아타도 이 축은 안 채워진다.** 자기부담금 표가 있는 쪽에는
> `tables_coords` 자체가 거의 만들어지지 않았고, 만들어진 곳에서도 담보종목은 없었다.
> 계획서가 제시한 경로 (c)는 **실측으로 기각**한다.

### 2.2 담보종목은 **격자 밖이 아니라 옆 격자에 있었다**

`find_tables` 는 같은 표를 **격자 두 개**로 낸다. 파서는 안쪽만 보고 있었다.
(KB손보 `6060b8bda3fa` p10 · `pages[].tables` 원문)

```
tables[0]  ['보장종목', '보상하는 사항']
           ['(2)\n상해통원', '<표1> 항목별 공제금액\n구분 항목 공제금액\n「의료법」…']   ← 담보종목이 여기 있다
tables[1]  ['구분', '', '항목', '공제금액']
           ['표\n준\n형', '외래\n(외래\n제비용…', '「의료법」 제3조 제2항 제1호…', '1만원과 보상\n대상 의료비의\n20%중 큰 금\n액']
```

즉 담보종목 열은 **PDF 에서 잘려 나간 것이 아니라 다른 격자에 들어가 있었다.**
"격자가 그 열을 포함하지 않는다"는 앞선 진단은 *안쪽 격자만* 놓고 보면 맞지만,
**같은 쪽 다른 격자를 보면 남아 있다.**

### 2.3 그러면 얼마나 되찾을 수 있나 — 값 있는 격자 **1,606개**의 담보종목 소재

| 분류 | 격자 |
|---|---:|
| **A** 자기 격자 안에 이미 있다(4세대 조판) | 122 (유일 24 · 여러 개 98) |
| **B** 같은 쪽 **다른 격자 셀**에 있고 유일 | **251** |
| **C** 같은 쪽 다른 격자 셀에 있으나 여러 개 | 4 |
| **D** 쪽 **본문 텍스트**에만 있고 유일 | **154** |
| **F** 쪽 어디에도 없다 | **1,075 (67.0%)** |

F 1,075개는 무엇인가 — 회사별로 흥국화재 397 · 현대해상 282 · 삼성화재 139 · 삼성생명 95 …
항목 분포는 `외래` 1,573 · `처방조제비` 535 · `None` 1,372.
앞 쪽에도 라벨이 없는 것이 **686개**다.
즉 F 는 담보종목 절 밖에 홀로 놓인 **`<표1> 항목별 공제금액` 참조표**가 대부분이다.
`<표1>` 은 상해통원 절과 질병통원 절이 **함께 참조**하는 표라
상해/질병이 원문에서도 결정되지 않는다. **비워 두는 것이 정답인 자리다.**

> ★**되찾기의 천장은 A+B+D ≈ 527/1,606 = 32.8%다.** 나머지는 파서를 고쳐서 될 일이 아니다.

## 3. 수행 내용

### 3.1 변경 파일

| 파일 | 상태 |
|---|---|
| `scripts/extract/coverage_limits.py` | 담보종목 복원 추가 · `한도금액`/`한도단위`/`단위` 필드 삭제 · `상해질병_추론` 신설 |
| `docs/reports/2026-08-03_L3_자기부담금_축채우기.md` | 이 문서 |

다른 파일은 건드리지 않았다.

### 3.2 담보종목 복원 — **사실 경로와 추론 경로를 나눈다**

`parse_page` 가 쪽 단위로 두 격자를 맞붙인다. 새 함수는
`_dambo_of` · `_grid_lines` · `_dambo_rows` 셋이다.

**(가) 사실 경로 — `근거_locator.담보종목_출처 = "바깥격자"`**

같은 쪽 **다른 격자**의 짧은 셀(≤40자)이 담보종목 라벨이고,
그 **행의 나머지 칸**이 지금 파싱 중인 격자를 감싸면 → 그 라벨은 이 표의 맨 왼쪽 열이다.

"감싼다"는 것은 **안쪽 격자의 각 줄(공백 제거·4자 이상)이 바깥 행 안에 부분문자열로 들어
있는 비율**로 잰다. ★문턱을 지어내지 않았다 — 라벨 후보가 있는 격자 **262개**의 분포가
이렇게 **깨끗하게 갈린다**:

| 포함비 | 격자 |
|---:|---:|
| 1.0 | **253** |
| 0.9 | 6 |
| 0.2 | 2 |
| 0.0 | 1 |

0.8 은 이 골짜기 안이다. 259개가 걸리고 3개가 빠진다.

> ★처음에는 "줄 집합의 교집합"으로 쟀는데 143개밖에 안 걸렸다.
> 바깥 칸에서는 두 열이 **한 줄에 붙어** 나오는 조판이 있어 줄이 정확히 일치하지 않는다
> (`합병원, 병원, 치과병원, 한방병원, 요양병원 1만 5천원과`).
> **부분문자열**로 바꾸니 분포가 위처럼 갈렸다. 이 오진을 코드 주석에 남겼다.

**(나) 추론 경로 — `근거_locator.담보종목_출처 = "같은쪽유일"`**

포함관계를 확인하지 못했지만 쪽 전체(표 셀 + 본문 텍스트)에서 담보종목 라벨이
**정확히 하나**일 때. 이때는 `입통원_추론`·`상해질병_추론` 에만 넣고
`inferred=true` + `추론근거` 를 남긴다. **사실 칸에 넣지 않는다**(CLAUDE.md §0).

> ★왜 이건 사실이 아닌가 — 쪽 아래쪽에서 새 담보종목 절이 시작하는데
> 표는 앞 절 것일 수 있다. **자리가 가깝다는 것은 같은 표라는 증거가 아니다.**
> 실제로 삼성생명·흥국화재 조판은 담보종목이 표 열이 아니라 **절 표제**(`《질병통원형》`,
> `(4)질병통원형`)라서 이 경로로만 잡힌다.

**(다) 우선순위** — 격자 **안**의 라벨 > 바깥격자(사실) > 같은쪽유일(추론) > 항목 기반 추론.
격자 안 라벨과 되찾은 라벨이 다르면 **격자 안이 이기고**, `담보종목_충돌` 로 세고
`미파싱_사유` 에 문장을 남긴다(전량에서 **0건**).

### 3.3 죽은 필드 제거 — `한도금액`·`한도단위`·`단위`

앞선 리포트 §5-9 가 "정의만 있고 한 번도 채워진 적이 없다"고 남긴 필드다.
**원문에 있는지 전수로 확인하고** 지웠다(RULE.md §3.3).

| 측정 (전량 10,726레코드) | 값 |
|---|---:|
| `_CAP`(`…원 한도`)가 걸린 **금액 셀** | **0** |
| `한도` 라는 낱말이라도 든 금액 셀 | 77 (**전부 `unparsed`** — 격자가 무너져 본문이 칸에 들어온 것) |
| `_UNIT_RULES`(방문1회·처방전1건·1일·1회)가 걸린 금액 셀 | 14 (**전부 `unparsed`**) |
| 격자 셀 **전체**로 넓혀 `…원 한도` | 194 — **전부** `연간 300만원 한도` · `보험가입금액 한도` |

즉 `한도`·`단위` 는 **다른 표의 필드**였다. 원문 PDF 에서도 그렇게 보인다 —
현대해상 `71fda3fa0924` p19 · 동양생명 `f22c9173215a` p82 · NH생명 `a73abdc9edf9` p20 모두
`방문 1회당`·`처방전 1건당`·`20만원 한도` 는 **`보상한도` 표**에 있고,
`<표1> 항목별 공제금액` 표에는 없다.

> ★**"원문에 아예 없다"는 뜻은 아니다.** 흥국화재 4세대의
> `비급여 병실료의 50%, 1일 평균금액 10만원 한도` 는 **쪽 본문에는 있는데
> `find_tables` 격자가 그 열을 통째로 잃는다**(앞선 리포트 §5-1).
> 값이 없는 이유는 "원문에 없어서"가 아니라 **"이 파서의 입력에 안 들어와서"** 다.
> 4세대 금액 열 유실을 고칠 때 **필드를 다시 만든다.**
> 그때까지 비워 둔 채로 두면 판정이 "한도 없음"으로 읽는다 — 그게 더 위험하다.

`한도` 가 든 **줄**을 금액 읽기에서 빼는 가드는 **남겼다**(`_CAP_LINE`).
그건 죽은 코드가 아니라 `연간 300만원 한도` 를 공제액으로 읽지 않게 하는 살아 있는 가드다.

`통화` 는 남겼다. 채움률 99.1% 지만 **값이 늘 `"KRW"` 인 상수 필드**다 — 정직하게 적어 둔다.

**읽는 법**

1. **`입통원` 사실 1,081건은 전부 `통원`이다. `입원`은 0건이다.**
   3세대 `<표1> 항목별 공제금액` 은 **통원(외래·처방조제비) 전용 표**다.
   입원 자기부담금은 표가 아니라 본문 문장(`… 20%에 해당하는 금액`)이라 이 파서가 안 잡는다.
   `상해질병` 은 질병 581 · 상해 535 로 갈린다.

2. **출처 내역** — `바깥격자`(사실) 1,059 · `같은쪽유일`(추론) 643 · 없음 2,769.
   `입통원` 사실 1,081 중 22건은 원래부터 격자 안에 있던 것이다.

3. **`급여구분` 0%는 결함이 아니라 사실이다.** 급여/비급여로 갈리는 축은 **4세대에만** 있고,
   4세대는 `find_tables` 가 금액 열을 통째로 잃어 `ok` 레코드가 아예 안 나온다
   (`unparsed` 쪽에는 833건 채워져 있다). 3세대 표에는 그 축이 **원문에도 없다** —
   선택형Ⅱ 는 한 셀 안의 `급여 10% + 비급여 20%` 라서 `자기부담률_급여`/`_비급여` 로 들어간다.
   원문 PDF 9쪽에서 확인했다(§4.5).

4. **회사별 `입통원` 사실 채움률이 크게 갈린다.**

| 회사 | `ok` | `입통원` 사실 | 비율 |

축 채움률·담보종목 출처를 다시 재려면:

```bash
python - <<'EOF'
import collections, glob, json, sys
sys.path.insert(0, ".")
from scripts.extract.coverage_limits import parse_page
fill, src, n = collections.Counter(), collections.Counter(), 0
for f in sorted(glob.glob("data/extracted/*/s5_pymupdf-1.28.0/*.json")):
    for pg in json.load(open(f, encoding="utf-8"))["pages"]:
        t = pg.get("text") or ""
        if "상급종합병원" not in t or ("공제" not in t and "자기부담" not in t):
            continue
        for r in parse_page(pg):
            if r["parse_status"] != "ok":
                continue
            n += 1
            src[r["근거_locator"].get("담보종목_출처")] += 1
            for k, v in r.items():
                if v not in (None, "", []) and not isinstance(v, dict):
                    fill[k] += 1
print("ok", n, "출처", src.most_common())
for k in ("기관종별", "입통원", "상해질병", "급여구분", "입통원_추론", "상해질병_추론"):
    print(f"  {k:14s} {fill[k]:5d}  {fill[k]/n*100:5.1f}%")
EOF
```
