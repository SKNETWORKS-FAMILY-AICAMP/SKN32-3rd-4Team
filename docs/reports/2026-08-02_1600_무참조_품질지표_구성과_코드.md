## 1. 왜 새로 만들었나

기존 두 "커버리지"는 **품질 지표가 아니다.**

| | 실제로 재는 것 | 왜 못 쓰나 |
|---|---|---|
| `_3rd_project_4` `coverage_pct` | 첫 재매칭 헤더 이후 정제텍스트의 **내부 재수록률** | 구조가 망가져도 100%. 첫 헤더를 늦게 찾을수록 **분모가 작아져 점수가 오른다** |
| v5 목차 제외율 | PDF 쪽 중 목차로 **안 뺀 비율** | **목차를 덜 뺄수록 올라간다.** 빈 페이지와 면책 페이지를 같은 1쪽으로 센다 |

2026년 기준 연구를 확인해도 **전처리 단독 품질 지표에는 표준이 없다** —
청킹 평가 논문들은 경계 정확도를 독립적으로 재지 않고 검색 성능으로만 잰다.

### 빌려온 발상

| 출처 | 쓴 것 |
|---|---|
| OmniDocBench (CVPR'25 · v1.6 2026-04) **MGAM** | 정답은 고정하고 **예측 쪽 granularity 만 맞춘다** → v5(조 단위)와 3rd(항 단위 1,500자)를 **문자 8-gram 집합**으로 환원해 단위를 지웠다 |
| HiCoBERT (2026) | 계층적 법률 문서 분할에 Boundary/Span 계열 지표 |
| DOCR-Inspector (2025) | 정답 없이 **오류 유형별로 센다.** 단일 종합 점수를 만들지 않는다 |

## 2. 지표 구성 — 3축 · 8지표

### T축 · 원문 보존 (`coverage_pct` 를 대체하는 정직한 버전)

원문(페이지 JSON)과 산출물을 각각 **공백 제거 후 문자 8-gram 집합**으로 만든다.

```
T1_recall    = |원문 ∩ 산출물| / |원문|      본문 소실
T2_precision = |원문 ∩ 산출물| / |산출물|    겹침·헤더 접두 인플레
```

- 페이지가 아니라 **문자**로 잰다
- 집합이라 **중복은 1회만** — 같은 조항을 여러 번 담아도 재현율이 오르지 않는다

### S축 · 구조 모순 ★확정 신호

| 코드 | 잡는 것 | 못 잡는 것 |
|---|---|---|
| `S1_aba_reentry` | `제4 → 제5 → 제4` 재진입. **부모 오귀속의 가장 선명한 신호** | 처음부터 끝까지 한 잘못된 부모에 붙으면 못 잡음 |
| `S3_embedded_header` | 블록 **안**에 다른 조 머리가 매몰 — 경계 누락 확정 | 헤더 글자가 소실되면 못 잡음 |
| `S4_annex_absorption` | 붙임·별표·분류표가 조항 안으로 | 마커가 깨지거나 무표식 부록이면 누락 |
| `S2_number_gap` | `제18 → 제20` 누락 | ★**저정밀.** 원문 결번·발췌도 걸린다. **단독 사용 금지** |

★번호 체계(`제N조` / `N-M.`)를 **섞어서 비교하지 않는다.**
  `제5조` 다음 `4-1.` 을 역행으로 세면 거짓 경고가 쏟아진다(코덱스 지적).

### C·N축 · 인용·오염

| 코드 | 내용 |
|---|---|
| `C1_dup_citation` | 같은 인용이 한 문서에서 여러 곳을 가리킨다 |
| `N1_pua_per_1m` | 복구 못 한 PUA 글리프 |
| `N2_replacement_per_1m` | `U+FFFD` 인코딩 손실 |

### 판정

```python
citation_eligible = not (S1_aba_reentry or S3_embedded_header or S4_annex_absorption)
```

★**확정 신호만** 쓴다. 저정밀 신호(`S2` · `C1`)는 **검수 우선순위**일 뿐 자동 실패가 아니다.
★**단일 종합 점수를 만들지 않는다.** 정답셋이 없으면 가중치를 정당화할 수 없다(코덱스).

## 4. ★지표가 나를 세 번 속였다 — 그때마다 실물을 열어 고쳤다

정직하게 남긴다. 무참조 지표는 **만들자마자 믿으면 안 된다.**

| # | 초안 | 실물 확인 | 조치 |
|---|---|---|---|
| 1 | `B1 문장중간 절단` — 종결어미+마침표로 끝나지 않으면 절단 | v5 0.381 / 3rd 0.379 — **신호가 없었다.** 조항이 표·목록으로 끝나는 경우가 많아 정상까지 절단으로 셌다 | **폐기** |
| 2 | `C3 법령 미분리` — 조 번호 100↑인데 법령 표시 없음 | 3rd 도 0 → "둘 다 잘한다"로 읽힐 뻔. 실은 3rd 의 `_filter_sequence` 가 조 번호 150 초과·+15 점프를 **버려서** 헤더가 아예 안 생기고 **법령 본문이 앞 조항에 흡수**된다 | 정의를 "헤더를 만들었나"로 **뒤집어야 함**(미반영) |
| 3 | `S4 부록 흡수` — 마커가 조항 안에 있으면 흡수 | 표본 5건 중 **3건이 문장 안 인용**(`제9조([별표1] 비급여대상)에 의한…`) | **줄머리 + 뒤 300자 이상**으로 수정. 11,478 → **4,789건** |

★공통 교훈: **위치(줄머리)를 안 보면 과탐한다.** 조 머리·항 마커에 적용한 원칙과 같다.

## 5. 표(表)는 어떻게 정리돼 있나 — 부분적으로만

| 단계 | 상태 |
|---|---|
| `data/extracted/**/s4_*/` | 표가 **셀 배열**로 있다. 표본 300문서에 13,196개, 추출 실패 0 |
| `data/structured/**/s5_*/` | 조항에는 `tables_on_pages: {"12": 3}` — **개수만.** 셀 내용은 없다 |

의도된 설계다(`to_clauses.py` 독스트링: *"표가 어느 조항에 속하는지 **추정하지 않는다**"*).
그러나 결과적으로 **보장한도·자기부담금 표가 검색 단위로 만들어지지 않는다.**

`_3rd_project_4` 는 `table_extract.py` 로 마크다운 표를 만들어 같은 쪽 조항에 붙인다 —
방법은 추정이지만 **그 칸을 채우긴 했다.** 우리는 비어 있다.

## 7. 이 지표의 한계 — 정직하게

| | |
|---|---|
| **문서 전체가 조용히 누락된 경우를 못 잡는다** | 산출물만 보기 때문. 원본 PDF 대비 쪽별 보존 recall 을 sidecar 로 따로 계산해야 한다(코덱스) |
| `C3` 정의가 뒤집혀 있다 | §4-2. 아직 안 고쳤다 |
| 항·호 번호열 이상 신호가 없다 | 코덱스는 쟀는데(v5 971/1천) 내 구현엔 없다 |
| 층화·신뢰구간 없음 | 전량이라 표본 문제는 없으나, **신호별 precision/recall 을 주장할 수 없다** — 정답셋이 없다 |
| 검색 품질을 보장하지 않는다 | 잘못 크게 합쳐진 청크가 오히려 hit@k 를 **높일** 수 있다. 올바르게 세분화하면 MRR 이 일시 하락할 수 있다(코덱스) |

★**정답셋 48패킷**(문서 48건이 아니라 원문 3쪽 창 48개 ≈ 144쪽) 설계는
`docs/reports/2026-08-02_1500_전처리_품질지표_설계와_실측.md` §5.5-5 에 있다.
48건 전부 무오류여도 **"오류율 6% 미만"** 까지만 말할 수 있다.
