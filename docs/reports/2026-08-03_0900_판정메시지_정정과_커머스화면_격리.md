## A · "약관을 보유하고 있지 않습니다" — 사실이 아니었다

**증상**

```
POST /v1/prechecks {"insurer":"DB손해보험","enrolled_on":"20200301","kcd_codes":["F32"]}
→ reason_code: insurer_not_supported
  message: "'DB손해보험' 약관을 보유하고 있지 않습니다."
```

**DB손보 약관만 236건 갖고 있다.** 수집이 아니라 **식별**이 안 끝난 것이다.

**원인** — 확정 게이트(`usable_for_judgment`)가 `confirmed` 만 통과시키는데 확정이 0건이라
`pool` 이 통째로 빈다. `resolve()` 가 그 빈 pool 을 "이 보험사가 없음"으로 보고했다.

**고친 것** ([`manifest_policy_resolver.py`](../../app/adapters/manifest_policy_resolver.py))

빈 pool 을 먼저 가려 새 사유로 답한다.

```
reason_code  documents_not_confirmed
message      "판정 가능한 약관이 아직 0건입니다. 약관을 보유하고 있지 않은 것이 아니라,
              '이 파일이 무엇인가'를 사람이 확정하는 절차가 남아 있습니다."
```

★**사용자가 할 일이 다르다.** 확정 대기면 **기다리면 되고**, 미보유면 **다른 곳을 찾아야 한다.**
같은 문구로 답하면 안 된다. CLAUDE.md §3 — *오류 메시지가 사실을 잘못 전하지 않게 한다*
(통신 실패를 "robots 거부"로 보고해 한참 헤맨 것과 같은 종류).

기존 분기는 살아 있다 — 다른 보험사 약관이 있는데 요청한 곳만 없으면 여전히 `insurer_not_supported`.

## B · ★고치다가 나온 것 — `reason_code` 가 조용히 사라지고 있었다

A 를 넣었더니 응답의 `reason_code` 가 **`None`** 으로 나갔다. 범인:

```python
_REASON_MAP.get(got.reason_code)      # 표에 없으면 소리 없이 None
```

**CLAUDE.md §3 "조용한 스킵을 만들지 않는다" 위반**이다. 그리고 **표가 하나 더 있는 구조 자체가
결함**이라, 새 사유를 추가할 때마다 같은 일이 반복된다.
에이전트는 `reason_code` 로 분기하므로 **왜 기권했는지 통째로 잃는다.**

**고친 것** ([`usecases/precheck.py`](../../app/core/usecases/precheck.py)) — 표를 없애고
enum 을 직접 쓰되, 못 맞추면 `ValidationErr` 를 낸다.

```python
def _reason(code: str | None) -> ReasonCode | None:
    if not code:
        return None
    try:
        return ReasonCode(code)
    except ValueError as e:
        raise ValidationErr(f"알 수 없는 reason_code '{code}' — ReasonCode enum 에 추가하세요.") from e
```

★이 값은 사용자 입력이 아니라 **우리 코드가 만든다.** 기권 응답에 `reason_code` 가 비는 것보다
**개발 중에 터지는 편이 낫다.**

## C · 커머스 화면 격리 — 범위가 세 번 바뀌었다

### ★내가 처음에 크게 틀렸다

초안은 **10개 파일 일괄 격리**였다(`admin`·`mypage`·`rag`·`facebench`·`common.js`·`style.css`).
코덱스가 1라운드에서 **정면 반대**했고, 확인해 보니 맞았다.

| 화면 | 실제로 무엇인가 | 판정 |
|---|---|---|
| `admin.*` | `/api/admin/events`(감사로그) · `knowledge-gaps`(지식갭 검수큐) · `report` | ★**MVP §3 졸업릴리스 필수의 UI.** 잔재 아님 → **유지** |
| `mypage.*` | `/api/face/register` · `status` — 얼굴 등록 | 얼굴 2FA 트랙 → **보류** |
| `facebench.*` | `/api/face/backend` · `benchmark` — 인식 벤치 | 개발 도구 → **보류** |
| `rag.*` | `/api/rag/qa` · `search` — 커머스 RAG | **격리 대상** |
| `common.js`·`style.css` | admin 이 의존 | **유지** |

그리고 `admin_app = create_app("admin")` 로 **관리자 포트 8081 이 실재**한다.
초안대로 갔으면 **운영 대시보드를 통째로 날릴 뻔했다.**

### ★두 번째로 틀린 것 — "깨진 링크 0건"

1라운드에서 코덱스가 *"admin.html 에 `orders.html`·`mcp.html`·`shop.html` 죽은 링크가 있다"* 고
했는데 내가 **"0건"이라고 반박했다. 내가 틀렸다** — 내 grep 정규식이
`href="/static/..."` 형태를 못 잡았다(`/?[a-z]+\.html` 로 `/static/` 을 커버 못 함).

제대로 재니 **죽은 링크 12개**였다.

```
admin.html      mcp.html · orders.html · shop.html
facebench.html  mcp.html · orders.html · shop.html
mypage.html     index.html · shop.html · video.html
rag.html        mcp.html · orders.html · shop.html
insurance.html  ★깨끗함
```

### 실제로 한 것

| | |
|---|---|
| P1 | `rag.html`·`rag.js` → `legacy/_unified_mall/app/static/` (RULE §2-4·§4.1) |
| P2 | 활성 HTML 3개에서 죽은 링크 + `rag.html` 링크 제거 → **죽은 링크 0건** |
| P3 | `main.py` `_OPS_STATIC` 에서 `rag.*` 제거 (없는 파일을 막는 척하지 않는다) |
| P4 | ★`test_static_ui.py` 에 **`<a href="/static/...">` 실재 검사** 추가 |
| P5 | `README.md` 관리자 표 정정 · `capture_screenshots.py` 에 "지금 안 돎" 명시 |

**P4 가 이 작업에서 제일 값어치 있다.** 기존 테스트는 `<script src>` 와 API 만 봤다 —
**네비게이션 링크는 아무도 안 봤다.** 화면은 열리는데 메뉴를 누르면 404 다.
`video.html` 때와 같은 실패이고, 그때도 사람이 눈으로 세어 찾았다.

★`legacy/` 는 검사 범위 밖이고 **파일명 예외를 만들지 않는다** — 예외가 다음 구멍이 된다(코덱스).

### README 는 없는 화면을 현행처럼 적고 있었다

관리자 표 5줄 중 `RAG 실험실`·`MCP 도구`·`주문 관리` 3줄이 있었는데
**`mcp.html`·`orders.html` 은 파일이 애초에 없다.** 2줄로 줄이고 경위를 남겼다.
