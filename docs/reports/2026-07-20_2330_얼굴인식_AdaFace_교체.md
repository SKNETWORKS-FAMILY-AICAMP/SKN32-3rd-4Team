# 얼굴 인식 모델 교체 — insightface(ArcFace r50) → AdaFace IR-101 (실측 검증)

- 작성일시: 2026-07-20 23:30
- 계기: 사용자 재지적 "insightface가 최선이 아닌 것 같다, 예전에 인식률이 너무 구려서 못 쓴 적
  있다. 실제 검증된 최신의 더 좋은 모듈 없냐 다시 생각해봐." → 웹서치(벤치마크) + 실측 비교.

## 1. 조사(벤치마크 근거)
- ArcFace R50(=insightface buffalo_l 기본)은 IJB-C 95.29%로 **베이스라인**이며, 특히 **저품질
  (TinyFace/IJB-S)에 약하다는 게 문헌에서 명확** — 사용자의 "인식률 구렸다" 경험과 일치.
- **AdaFace(CVPR2022)**: 저품질 특화. "ArcFace가 IJB-C에서 못 맞히는 케이스를 AdaFace는 맞힌다",
  저품질 벤치마크 SOTA. LVFace(2025)가 더 높지만 ViT라 CPU 배포 무거움.
- **antelopev2(glintr100) 교체는 오히려 나쁨**: 커뮤니티/문헌상 buffalo_l(r50 WebFace600K)이 더
  많은 데이터·좋은 스케줄로 학습돼 antelopev2(r100 Glint360K)보다 정확. → insightface 안에선
  buffalo_l이 이미 최선이라 팩 교체는 답이 아님.

## 2. 실측 비교(이 프로젝트 셋업, 동일 정렬 crop, 동일인 열화 매칭 코사인 — 높을수록 좋음)
| 열화 | insightface(buffalo_l r50) | AdaFace IR-101 |
|---|---|---|
| 블러 k21 | 0.578 | **0.665** |
| 저조도 ×0.12 | 0.869 | **0.923** |
| 저해상 0.25배 | 0.711 | **0.772** |
| 저해상 0.15배 | 0.299 | **0.389** |
| 타인 분리(낮을수록 좋음) | -0.030 | -0.032 (동일 우수) |

→ AdaFace가 **모든 열화에서 우위**(+0.05~+0.09)이면서 타인 분리는 그대로 우수. 사용자가 겪은
저품질 인식률 문제를 정면으로 개선. (정상광 동일인은 둘 다 높음.)

## 3. 배포 경로 조사(정직)
- AdaFace CVLface HF wrapper(`AutoModel trust_remote_code`)는 `omegaconf` + 내부 `models` 패키지에
  결합돼 깔끔한 로딩 불가.
- **standalone ONNX**(InsightFace-REST 배포본, ir101 webface12m, 260MB)는 onnxruntime로 **프레임워크
  없이 직접 구동** — 이게 가장 깔끔. gdown(Google Drive)로 다운로드. 전처리는 RGB 112×112,
  [-1,1] 정규화. 판별: 동일영상 자기유사도 1.0, 타인 -0.03으로 전처리 정확.

## 4. 구현
- **검출·정렬·자세·품질은 insightface RetinaFace 유지**(우수), **인식 임베딩만 AdaFace ONNX로 교체**.
- `app/ml/face.py` `_embed()`가 `FACE_RECOGNITION`("adaface" 기본 / "insightface")에 따라 분기 —
  AdaFace ONNX 세션 lazy 싱글턴. 모델 파일 없으면 ConfigError(무폴백: insightface로 조용히 안 넘어감,
  fetch 안내).
- config: `FACE_RECOGNITION`, `FACE_ADAFACE_ONNX`, 임계 `FACE_MATCH_THRESHOLD` 0.40→**0.30**
  (AdaFace 타인 유사도 ~0이라 여유 큼; insightface로 바꾸면 재튜닝 필요 명시).
- `scripts/fetch_face_model.py`가 AdaFace ONNX도 gdown으로 받음(FACE_RECOGNITION=insightface면 건너뜀).
  requirements에 gdown 추가. 모델은 gitignore(data/models).

## 5. 검증
- `pytest -m ml tests/test_face.py` — **8 passed**(AdaFace 기본으로 동일인 매칭·타인 불일치·전체
  2FA 흐름·품질 게이트·pre2fa 거부 전부 통과).
- `pytest -m "not llm and not ml and not pg and not mcp"` — **323 passed**(회귀 0).

## 6. 정직한 한계
- AdaFace ONNX는 **Google Drive 배포본**이라 HTTP 호스팅보다 다운로드 재현성이 약함(gdown 의존).
  상용 시 AdaFace/insightface 모델 라이선스 확인 필요.
- 임계 0.30은 AdaFace 타인분포(~0) 기준 여유값이며 실 genuine/impostor 분포로 튜닝 필요.
- 실 웹캠 라이브 매칭·라이브니스 정확도는 헤드리스 환경에서 여전히 미검증(열화 비교는 합성 열화).
- LVFace(2025 SOTA)는 더 높으나 ViT라 CPU 데모엔 과함 — 채택 안 함(문서화).
