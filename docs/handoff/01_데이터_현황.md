## 2. 격리한 336건 — 왜 뺐나

`data/raw/excluded/<사유>/<보험사>/` 에 옮겨 두었다. **지우지 않았다.**

| 사유 | 건수 | 왜 |
|---|---:|---|
| 비의료실손 | 159 | `실손·비례보상 주택 풍수해보험`, `아파트화재보험(실손형)` 등. 여기서 `실손` 은 **"실제 손해를 보상한다"는 방식**이지 의료비가 아니다 |
| 여행실손 | 158 | 세대 구분 대상이 아니고 코호트 성격이 다르다 |
| 사업방법서 | 19 | 약관이 아니라 **회사 내부 업무 기준**이다. 이걸 "약관 제○조"라고 인용하면 틀린 근거가 된다 |

매니페스트에 `doc_type` · `excluded_reason` 이 남아 있어 되돌릴 수 있다.

## 4. 상품 라인 — **세대 축이 다르다**

| 라인 | 문서 | 세대 |
|---|---:|---|
| `standard` 일반 실손 | 1,004 | 1~5세대 |
| `simplified_issue` 유병력자 | 173 | **별도 라인** (2018-04-02~) |
| `senior` 노후실손 | 153 | **별도 라인** (2014-08~) |
| `unknown` | 37 | 판정 불가 |

**노후실손·유병력자실손에 "3세대"를 붙이면 안 된다.** 자기부담금 체계가 다르다.
그래서 상품 라인이 갈리면 API가 `ambiguous_product_line` 으로 되묻는다.

## 6. 판매시점 신뢰도

| 등급 | 뜻 | 처리 |
|---|---|---|
| `exact` | 사이트·URL·표지에 날짜가 **적혀 있다** | 그대로 쓴다 |
| `month` | 상품코드에서 **월까지만** 유도했다 | 세대 판정엔 충분. 경계달이면 `ambiguous` |
| (없음) | 원래부터 있던 값 | 수집 당시 사이트 값 |

날짜를 끝내 못 찾은 것은 **4건**이다(제도성 특약 — 자체 판매기간이 없는 문서).

**결정적 단서는 URL이었다.** 삼성생명 약관 URL 경로에 판매개시일이 박혀 있다:
```
/uploadDir/doc/2021/0401/LP0525006/…   →  2021-04-01
```
사이트에서 직접 읽은 40건과 대조해 **40/40 일치**를 확인한 뒤 173건에 적용했다.

## 7. ★약관이 KCD 코드를 직접 쓴다

이게 이 프로젝트의 핵심 자산이다.

```
② 회사는 '한국표준질병사인분류'에 따른 다음의 의료비에 대해서는 보상하지 않습니다.
   ① 정신 및 행동장애(F04∼F99). 다만, F04∼F09, F20∼F29, F30∼F39, F40∼F48,
      F51, F90∼F98과 관련한 치료에서 발생한 …요양급여에 해당하는 의료비는 보상합니다.
   ③ 피보험자가 임신, 출산으로 입원한 경우(O00∼O99)
   ⑤ 비만(E66)   ⑥ 요실금(N39.3, N39.4, R32)
```

**표본 300문서 중 239개(80%)** 에 코드가 있다.
진료비 내역서에도 코드가 적혀 있으므로, **외부 KCD 표 없이 면책 판정이 된다.**

> 외부 KCD 표가 필요한 곳은 따로 있다 — **질병명 → 코드**.
> 사용자가 "우울증"이라고 입력하면 `F32` 를 찾아 줘야 한다. 그건 아직 없다.

## 8. 알려진 한계 (정직 기록)

| 항목 | 상태 |

| 조 번호 충돌 | 부까지 포함해도 같은 번호가 겹친다. `(문서, 특약ID, 조번호)` 식별키가 필요 |
| 표(table) 의미 | 셀만 뽑았고 "무슨 표인지"는 모른다. **보장 한도·자기부담금이 표에 있다** |
| 별표 귀속 | 장해분류표 등이 어느 조항에 속하는지 미정 |
| 준용 해소 | 참조의 **2/3이 문서 밖**을 가리킨다. 아직 따라가지 않는다 |
| 임베딩 검색 | 없다. 지금은 낱말 포함 검색만 한다 |
| 질병명→코드 | 없다. 코드 입력만 받는다 |

## 9. 공유 가능 여부

| 자료 | 팀 내부 | 외부·공개 저장소 |
|---|---|---|
| **매니페스트** `data/raw/manifests/*.jsonl` | ✅ 가능 | ⚠ 출처 URL 포함. 공개 무방하나 팀 합의 후 |
| **조항 JSON** `data/structured/` | ✅ 가능 | ❌ 약관 원문 파생물이다 |
| **약관 PDF** `data/raw/insurance_terms/` | ✅ 가능 | ❌ **재배포 금지** |
| 수집·전처리 스크립트 | ✅ | ✅ |

매니페스트는 **메타데이터만** 담는다(보험사·상품명·판매기간·URL·해시).
약관 본문은 들어 있지 않으므로 팀 공유에 문제가 없다.

> 다만 조항 JSON은 **v4 기준으로 다시 뽑은 것**을 써야 한다.
> v2·v3 산출물은 목차 오인·번호체계 오판 결함이 있다.
