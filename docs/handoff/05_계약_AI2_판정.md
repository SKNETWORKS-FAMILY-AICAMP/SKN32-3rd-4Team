## 0. 당신이 만드는 것

근거 묶음을 받아 **판정하고, 사람이 읽을 설명을 쓴다.**
그리고 그 설명이 **근거를 벗어나지 않았는지 검사**한다.

def explain(assessment: RuleAssessmentV1, bundle: EvidenceBundleV1) -> ExplainedResultV1:
    """설명문 생성 + ★인용 검증. 검증에 걸리면 폐기하고 기권한다."""

---

## 2. 지켜야 할 경계

| 하면 안 되는 것 | 왜 |
|---|---|
| **`not_mentioned` 를 `covered` 로 올리기** | 면책 목록에 없다 ≠ 보장된다. 보장은 '보상하는 사항' 조항이 정한다 |
| 근거에 없는 조항 인용 | `citation_guard` 가 걸러 내지만, 애초에 만들지 않는다 |
| 근거를 넘어선 추론 | 조항에 "우울증"이 없는데 "정신과 질환이니 비슷하게…"는 금지 |
| 기권을 부끄러워하기 | **`unknown` 은 정상 결과다.** 억지로 판정하면 사람이 손해를 본다 |
| 자유 텍스트만 반환 | 구조화 출력이어야 검증할 수 있다 |

## 3. ★인용 검증 — 이미 만들어져 있다

```python
from app.insurance.citation_guard import EvidenceClause, verify

r = verify(
    cited_clauses=llm_output.cited_clauses,   # LLM 이 인용했다고 한 것
    evidence=[EvidenceClause(qualified_no=c.qualified_no, text=c.text)
              for c in bundle.clauses],
    answer_text=llm_output.reason,
    quotes=llm_output.quotes,
)
if not r.ok:
    # ★답을 버리고 기권한다. 재시도는 1회까지.
    return abstain(ReasonCode.CITATION_UNVERIFIED, r.reason)
```

| 검사 | 위반 시 |
|---|---|
| 인용 조항이 근거에 실재하는가 | **폐기** |
| 본문에서 `제N조` 를 말했는데 선언 안 했는가 | 경고 |
| 인용문이 조항 원문의 실제 일부인가 | 경고 |

**프롬프트로 "추측하지 마라"라고 적는 것만으로는 부족하다.**
그건 지켜지길 바라는 것이고, 이 검사는 강제된다.

## 4. LLM 출력 형식 (강제)

```json
{
  "verdict": "covered | not_covered | conditional | unknown",
  "cited_clauses": ["보통약관/제9조", "특별약관/제3조"],
  "quotes": { "보통약관/제9조": "실제 원문에서 따온 문장" },
  "reason": "사람이 읽을 설명"
}
```

`cited_clauses` 가 비어 있으면 `covered`/`not_covered` 를 낼 수 없다.

## 5. 모델 평가 지표 — 이걸로 모델을 고른다

| 지표 | 방향 |
|---|---|
| **인용 정합률** — 인용한 조항 중 근거에 실재하는 비율 | 높을수록 |
| **근거 초과율** — 근거에 없는 내용을 답에 넣은 비율 | 낮을수록 |
| **적절한 기권율** — 근거 부족 시 `unknown` 을 낸 비율 | 높을수록 |
| **과잉 기권율** — 근거 충분한데 `unknown` 을 낸 비율 | 낮을수록 |
| **스키마 준수율** — 구조화 출력을 형식대로 낸 비율 | 높을수록 |

> "지시를 잘 따르는 모델인가"보다 **"구조화 출력을 안정적으로 내는가"** 가 중요하다.
> 그게 코드로 검증 가능한 형태이기 때문이다.

## 6. 이미 있는 것

```python
from app.insurance import kcd, precheck

kcd.scan_clause(text)      # 조항에서 코드 범위 + 면책/예외/불명
kcd.judge(code, mentions)  # excluded / exception / not_mentioned / invalid_code
precheck.run(req)          # 규칙 기반 전체 흐름(참고 구현)
```

`precheck.run()` 이 이미 규칙 판정을 한다. **당신이 채울 곳은 셋이다.**

1. **자기부담금 계산** — 세대별로 다르다. 조항의 표에서 뽑아야 한다
2. **한도·대기기간** — `conditional` 의 조건을 구체화
3. **설명문 + 인용 검증** — LLM 을 붙이는 곳

## 7. 골든 세트 (당신이 만든다)

20~30건. 각 건에 **기대 verdict 와 기대 인용 조항**을 적는다.

```yaml
- id: golden-001
  request: {insurer: DB손해보험, enrolled_on: "20200301", kcd_codes: [F32],
            product_name: "프로미라이프 실손의료비"}
  expect:
    verdict: conditional
    reason_code: exception_applies
    must_cite: ["보통약관/4.1"]
```

**반드시 넣을 실패 케이스:**
- 근거 없음 → `unknown`
- 잘못된 조항 번호 인용 → 폐기
- 다른 버전 혼입 → 검출
- 면책 예외 누락 → 검출
- 표본 부족 → 통계 안 냄
