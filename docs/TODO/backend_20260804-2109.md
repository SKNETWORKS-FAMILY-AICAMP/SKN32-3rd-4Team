```
503  검색·저장소 장애 — 이때만 "우리 잘못"
```

## 하지 않기로 한 것

- **기동 시 자동 create_all/seed/index 를 하지 않는다.** 명시적 `scripts.manage` 로 준비하고
  `/api/health/ready` 로 확인한다.
- **폴백 금지.** postgres 를 골랐는데 장애가 나면 파일로 내려가지 않고 503 이다.
- **고객 앱에 관리자·운영 라우터를 싣지 않는다.**
- 예외를 삼키지 않는다 — `except: continue` 는 실패를 세어 보고해야 한다.

## 겪은 함정 (되풀이 금지)

- ★**두 프로세스라는 걸 잊었다.** 관리 서버(8081)에서 바꾼 것이 고객 서버(8080)에
  안 닿는다. 인메모리 관측 스트림·버전 캐시 둘 다 이걸로 한 번씩 깨졌다 —
  해법은 같다: **파일을 진실의 출처로** 두고 변경 시각을 지문으로 쓴다.
- `_OPS_STATIC` 에 **없는 파일 이름**이 남아 있으면 차단이 잘 되는 것처럼 보인다.
