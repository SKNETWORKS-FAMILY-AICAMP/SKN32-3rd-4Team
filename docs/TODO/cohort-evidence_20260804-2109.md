## 지금 상태 (실측 2026-08-04 21:09)

```
합성 트랙  제출 77 · 승격 40 · 대기 37     (data/demo/, data/cohort/synthetic/)
실제 트랙  제출 13 · 교차검증 5 · 대기 8   (data/external/, data/cohort/verified_real/)
최소표본   30 미만이면 비율을 계산하지 않는다
```

**5층 물리 분리가 되어 있다** — 저장·수집·집계·API·보증:

| | 실제 | 합성 |
|---|---|---|
| 제출 | `POST /v1/observations` | `POST /v1/demo/observations` |
| 저장소 | `external_submission_store` | `demo_submission_store` |
| 승격 | `POST /api/admin/verifications` (근거 필수) | `POST /api/admin/demo/verifications` |
| 등급 | `admin_attested` | `document_backed` |
| 조회 | `GET /v1/cohorts` | `GET /v1/demo/cohorts` |

★두 저장소 모듈은 **서로의 경로 문자열을 실행 코드에 갖지 않는다.**
토큰 단위 검사 테스트로 고정돼 있다 — 섞으려면 코드를 새로 써야 한다.

★**`verified` 라고 부르지 않는다.** 관리자가 할 수 있는 건 교차검증뿐이라
`admin_attested` 로 두고, 코호트 응답이 `by_verification` 으로 등급별 건수를 함께 낸다.

## 하지 않기로 한 것

- **합성과 실제를 합치는 코드를 만들지 않는다.** 합계 필드도 만들지 않는다.
- **`unverified` 를 집계에 넣지 않는다.** 제출은 검증이 아니다.
- **클라이언트가 보낸 `verification` 을 믿지 않는다.** 언제나 `unverified` 로 고정한다.
- **최소표본 미만에서 비율을 말하지 않는다.** 넘겨도 점추정 대신 **구간**으로 말한다.
- **"당신은 얼마 받습니다"를 하지 않는다.** 과거 분포만 제시한다.

## 겪은 함정 (되풀이 금지)

- 유스케이스가 `CohortStats` 를 **필드 하나씩 옮겨 재구성**하다가 새 필드(`by_verification`)를
  흘려 화면에 `{}` 로 나갔다 → `dataclasses.replace` 로 바꿨다.
- 실제 제보 원본이 `payload` 아래 **중첩**돼 있어 `rec.get("insurer")` 가 전부 None 이었다.
  승격 이벤트가 빈 값으로 쌓일 뻔했다 — 파일을 직접 열어 보고 발견.
