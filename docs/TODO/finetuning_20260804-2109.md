### P0

- [ ] **무엇을 파인튜닝할지부터 다시 정한다.** 지금 코드는 커머스 CS 분류를 가리킨다.
      완료 기준: 대상 태스크·데이터 출처·평가 기준이 한 문단으로 적힌다.
      후보:
      - (A) 약관 용어 설명 문체 정렬 — 데이터를 우리가 만들 수 있다
      - (B) 판정 근거 생성 — ★규칙엔진이 하는 일이라 **중복이고 위험**하다
      - (C) 분쟁사례 분류 — 금감원 자료 필요(핸드오프 14)
      - (D) 하지 않는다 — 4주 안에 의미 있는 데이터가 없다면 이게 정직한 답이다

### P1 — (A) 또는 (C) 를 고른 경우

- [ ] 데이터셋 규모를 **먼저** 센다. 몇 건인지 모른 채 학습 스크립트를 돌리지 않는다.
      완료 기준: train/valid/test 건수와 고유 건수(중복 제외)가 기록된다.
      ★"60행 중 고유 15개" 같은 일이 다시 나면 그 자리에서 멈춘다.
- [ ] 베이스라인을 **먼저** 잰다(`eval_baselines.py`). 파인튜닝 전후를 비교할 수 없으면 의미가 없다.
- [ ] 학습 후 **실 사용 경로에 붙일지** 결정. 안 붙일 거면 실험으로 남기고 그렇게 적는다.

- 이 파트는 **한 번 중단됐다.** 그때 멈춘 판단은 옳았다 — 데이터가 없었다.
  다시 시작한다면 같은 이유로 멈추지 않도록 **데이터부터** 확인한다.
