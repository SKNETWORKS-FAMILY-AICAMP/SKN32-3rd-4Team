```
F41.0 → needs_documents / exception_applies   인용 1건 (제4조 보상하지 않는 사항)
N39.4 → unlikely        / excluded_by_clause  인용 1건 (여성생식기 비염증성 장애)
S72.0 → needs_expert    / no_evidence         인용 0건 ← 약관에 언급 없음, 정직한 기권
```

- 근거를 못 대면 `needs_expert` + HTTP **200**. 기권은 오류가 아니다

★현재는 [문서 확정](document-identification_20260804-2109.md)이 0건이라 **모든 요청이 기권**한다.

## 다음에 할 일

### P0 — 발표 전에 반드시

- [ ] **`likely_covered` 가 구조상 나오지 않는 문제를 결정한다.** ★Codex 논의 중
      4단 중 1단이 영원히 안 나온다. 원인: 실손 약관은 보장 대상을 KCD 로 나열하지 않고
      **면책만** 나열하므로 "보장된다"를 조항으로 증명할 방법이 없다.
      선택지:
      - (A) 그대로 두고 "구조상 안 나온다"를 응답·문서에 **명시** — 가장 정직
      - (B) "면책 목록에 없음"을 근거로 낸다 → ★우리 지원범위 문구가 이미
        *"면책 목록에 없다는 것이 보장된다는 뜻은 아니다"* 라고 못박아 **자기모순**
      - (C) 보장 조항(제3조 보상하는 사항) 매칭 경로를 별도로 만든다 —
        서술형이라 KCD→서술 매핑이 필요. 근거 없는 추론의 제도화가 아닌지 검토 필요
      - (D) 4단을 3단으로 줄인다
      완료 기준: 선택과 이유가 이 파일과 `docs/plans/` 에 적히고, 코드·응답이 그에 맞는다.
      ★어느 쪽이든 **발표에서 "왜 보장 가능성 높음이 안 나오나"에 한 문장으로 답할 수 있어야** 한다.

### P1

- [ ] **KCD 마스터(차수 + 코드→한글명) 적재.**
      완료 기준: `KcdCode.version_label` 이 빈 문자열이 아니게 되고, 코드로 질병명을 보여줄 수 있다.
      지금은 클라이언트가 준 코드를 그대로 들고 다니고 차수를 비워 둔다.
      ★약관은 "제8차 개정 … C00~C97" 처럼 **차수와 함께** 범위를 적는다 —
      차수가 없으면 같은 코드가 다른 질병일 수 있다.
- [ ] 면책기간·특약·보장한도 규칙을 **코드로** 계산하는 부분 점검.
      완료 기준: 날짜 경계(가입 당일·면책 만료 당일) 단위 테스트가 있다.
- [ ] `needs_documents` 일 때 `missing_documents` 가 실제로 채워지는지 확인.
      에이전트가 이걸로 분기한다 — 비어 있으면 다음 행동을 정할 수 없다.

## 하지 않기로 한 것

- **이진 판정 금지.** 4단(또는 결정된 단계)만 낸다.
- **개인 예상 지급액 산정 금지** — 손해사정 유사행위 소지. 과거 분포만 제시한다.
- **LLM 에게 날짜·면책기간·한도를 계산시키지 않는다.** 코드가 한다.
- 사례 제출(`/v1/observations`)을 **판정 근거로 쓰지 않는다.** 통계·사후검증용이다.
