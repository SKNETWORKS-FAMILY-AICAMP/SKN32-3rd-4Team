## 지금 상태 (실측 2026-08-04)

- 조항 저장소는 포트로 추상화(`CLAUSE_STORE` 환경변수 → 파일 / PG)
- **인용 자격 게이트가 한 곳에 모여 있다**(`app/core/domain/eligibility.py`) —
  파싱 상태·`citation_eligible`·`chunk_type`·`is_statute`·번호/본문 유무를 본다
- ★**모르면 못 쓴다**(fail-closed). 필드가 없으면 거절한다
- 커머스 RAG(`/api/rag/*`)는 **걷어낼 잔재**다. 보험 경로와 섞지 않는다

## 다음에 할 일

### P0

- [ ] **보장 조항 + 면책 조항을 함께 인용하도록 강제한다.**
      지금은 유사도 상위 k 를 그대로 쓴다 — 상위는 보통 보장 조항이라
      **면책이 밀려난다.** MVP §2-6 과 데모 화면의 *"유리한 조항만 보여주지 않는다"* 가
      코드로 강제되지 않고 있다.
      완료 기준: 면책 조항을 별도로 확보해 합치는 경로 + 그것을 검증하는 테스트.

### P1

- [ ] **`Evidence` 에 약관 버전이 없다.** 필드가 `content/source/locator/score/backend` 뿐이다.
      그래서 "적용 약관 버전 확정" 결과를 인용에 연결할 수 없고 신선도 게이트를 걸 데가 없다.
      ★**현행 약관 조각이 구계약 답변에 조용히 섞여도 아무도 모른다.**
      완료 기준: `policy_version`/`sha256` 이 Evidence 를 타고 응답 인용까지 간다.
      (포트 변경이라 다른 작업보다 **먼저** 결정해야 한다)
- [ ] **abstention 이 문자열이다.** `AnswerResult(answer=NO_ANSWER, sources=[])` 로 돌려주므로
      호출자가 문자열 비교로 판별해야 한다. 4단 판정·지식갭 큐로 이으려면
      `abstained: bool` + `reason` 같은 구조화 필드가 필요하다.
- [ ] `answer_question.py` 프롬프트의 역할 문구가 **"CS 상담원"** 이다.
      보험에서는 상담원 역할을 주면 모델이 **판정을 말하려 든다.**
      판정은 규칙엔진이 하고 이 유스케이스는 조항 제시·인용만 한다.

### P2

- [ ] 커머스 RAG 라우터·화면 잔재 제거 시점 결정(지금은 운영 포트에만 실림).
- [ ] Hybrid(RRF) 하나만 유지하기로 한 결정 재확인 — 4백엔드 비교는 학습 트랙이었다.

## 하지 않기로 한 것

- **근거가 없으면 생성하지 않는다.** 빈 근거면 모델을 부르지 않고 물러난다.
- **거리 하한 없이 상위 k 를 그대로 근거로 쓰지 않는다.**
- **인용 자격을 두 곳에서 판정하지 않는다.** 게이트가 여러 곳이면 전부 fail-open 이 된다
  (실제로 적재·파일·PG·검색·인용검증 다섯 곳이 서로 다르게 답하고 있었다).

---

## 겪은 함정 (되풀이 금지)

- 적재 게이트가 `citation_eligible is False` 만 제외해 **필드 부재를 통과**시켰다.
  `is True` 여야 한다 — `is not False` 로 쓰면 모르는 것이 통과한다.
- PG 어댑터가 조회 결과를 **무조건 `usable=True`** 로 만들고 있었다.
- 프롬프트 섹션 라벨(`[문서]`·`[질문]`)이 근거 본문에 들어가면
  가짜 경계를 흉내내 모델을 흔든다 → 삽입 전 무력화한다.
