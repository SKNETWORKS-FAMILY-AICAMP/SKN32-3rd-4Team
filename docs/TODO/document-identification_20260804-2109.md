## 지금 상태 (실측 2026-08-04 21:09)

```
수집 대상          1,367건
확정 원장(기계대조)   850건 (62.2%)
사람 최종승인          0건  ← 850건 전부 "…사람 최종승인 대기"
판정 모드          human_signoff (엄격)
판정 가능 약관         0건  ← 그래서 지금 모든 질문이 needs_expert 로 기권한다
```

원장: `config/confirmed_documents.jsonl` · 도구: `scripts/confirm/identify_documents.py`
게이트: `app/core/domain/identification_mode.py` · 적용 지점: `manifest_policy_resolver.load_versions()`

**모드를 `machine_match` 로 바꾸면 즉시 판정이 살아난다**(대시보드 「판정 모드」 스위치).
다만 그건 사람이 확인하지 않은 약관으로 답하는 것이고, 응답·지원범위·화면에 경고가 붙는다.

### 이 파트에서 이미 두 번 틀렸다 — 되풀이 금지

- **너무 엄격**: 계약에 없는 규칙으로 대량 오탈락(`date_confidence` 라벨 부재 +677 ·
  세대 NULL +301 · `parse_status` +36). 핸드오프 02번이 세대 NULL 허용을 못박아 뒀는데 안 읽었다.
- **너무 무름**: 토큰 커버리지만 봐서 확정 1,115건 중 **798건(71.6%)이 다른 상품명과도 일치**했다.
  강한 식별자(전체 상품명 한 덩어리) + 경쟁명 검사로 바꿔 1,115 → 850.

★**기준을 바꾸면 `--rebuild` 로 기존 항목도 재심사한다.** 덧붙이기만 하면
통과율이 「기준 완화 이력의 합」이 된다.

## 하지 않기로 한 것

- **현행 약관으로 폴백하지 않는다.** 가입 시점 약관을 못 찾으면 `NotResolved` 다.
  "일단 최신 약관으로 답한다"가 이 도메인에서 가장 위험한 폴백이다.
- **자동 분석이 `CONFIRMED` 를 만들지 않는다**(`document_identification.py` 가 구조로 막는다).
- 짧은 sha 로 확정하지 않는다. 원장의 sha256 이 64자가 아니면 `InfraError`.
