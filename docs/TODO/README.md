---

## 파일 이름 규칙

```
<area>_<YYYYMMDD-HHMM>.md      예: document-identification_20260804-2109.md
```

- **영문 소문자 + 하이픈.** 폴더가 OS·git·CI 어디서든 안전하게 다뤄진다.
- **날짜시간이 곧 버전이다.** 고칠 때는 **새 파일을 만들고** 옛 파일 맨 위에
  `> 대체됨 → <새 파일>` 한 줄을 남긴다. 덮어쓰지 않는다 —
  "그때 무엇을 하려 했나"가 사라지면 판단이 왜 바뀌었는지 알 수 없다.
- 새 파일을 만들면 **아래 표의 링크를 같이 고친다.** 표가 낡으면 이 폴더가 무용지물이다.

## 각 파일의 형식

```
## 지금 상태 (실측 YYYY-MM-DD)   ← 문서가 아니라 **직접 세어 본 값**만 적는다
## 다음에 할 일                  ← P0/P1/P2 체크박스. 완료 기준을 함께 적는다
## 하지 않기로 한 것              ← 이게 없으면 같은 논의가 반복된다
## 근거 문서                     ← 이 판단이 어디서 왔나
```

★**숫자를 적을 때는 분모를 함께 적는다.** "850건 확정"이 아니라
"수집 1,367건 중 850건 확정(62.2%)". 분모 없는 숫자는 매번 오해된다.

★**"완료"라고 적기 전에 실제로 돌려 본다.** 테스트 통과는 완료가 아니다 —
프론트가 있으면 화면을 열고, API 면 실제로 호출한다.
(2026-08-04 실측: 얼굴 인증은 테스트 14개가 전부 통과하는 동안
**아무도 등록할 수 없는 상태**였다.)
