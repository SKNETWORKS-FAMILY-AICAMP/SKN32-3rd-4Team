## 1. 기능 정의

약관에 나오는 어려운 보험·의학 용어를 사용자가 물어보면, 약관의
용어정의표에 근거해 쉽게 설명해주는 사이트 내부 챗봇.
(예: "면책기간이 뭐예요?" → 용어 정의 + 출처 표기)

## 2. 확정된 구성

| 구성요소 | 확정 내용 | 근거 |
|---|---|---|
| 검색 | terms_e5 컬렉션 (용어 1개=1청크, term 메타필드) | 임베딩 선정 과정 |
| 임베딩 | multilingual-e5-large (query:/passage: 접두사) | 80문항 비교 1위 |
| LLM | **Qwen3 8B (로컬)** — 무료·데이터 외부 전송 없음 | 30문항 평가에서 용어 설명 품질 GPT와 동급 |
| 안전장치 | **용어 일치 가드** (아래 3절) — 필수 | 함정 문항 검증 |
| 대체 LLM | GPT-4.1 (속도 필요 시 교체 가능 — 같은 인터페이스) | |

sLLM(Qwen3 8B)으로 충분하다는 초기 설계 가설("정의 설명은 7~8B급도 충분")이
실측으로 확인됨. 단, 아래 가드 없이는 배치 불가.

## 3. 용어 일치 가드 (핵심 안전장치)

### 왜 필요한가 — 실측된 위험

용어사전에 없는 용어를 물으면(예: "부담보란?") 벡터 검색은 가장 비슷한
**다른 용어의 정의**를 가져온다(오답 근거). 이때:
- GPT-4.1: 매 실행 거부 (안전)
- Qwen3 8B: 대체로 거부하나 **1회 환각 발생** — 무관한 용어("본인부담금
  상한제") 정의를 질문 용어("부담보")의 정의인 것처럼 답변

"가끔 뚫리는" 확률적 방어는 프로덕션에서 수용 불가 → 코드 레벨 차단 도입.

### 동작 방식 (rag_config.search_terms_guarded)

```
질문 → 용어 추출("기왕증이란?" → "기왕증")
     → terms_e5 검색 (top-k)
     → 각 결과의 term과 질문 용어를 정규화 비교 (공백·괄호 제거, 부분 일치)
     → 일치하는 근거만 통과
     → 전부 불일치면 근거 0건 반환 + 차단 사유 로그
근거 0건이면 LLM을 호출하지 않고 즉시 "확인할 수 없습니다" 고정 응답
```

핵심 원칙 2가지:
1. **오답 근거를 LLM에게 보여주지 않는다** — 속을 재료 자체를 차단.
2. **근거 0건이면 LLM 미호출** — "근거 없으면 거부하라"는 프롬프트 지시도
   Qwen에겐 확률적 방어일 뿐임이 실측됨(빈 근거에서 사전지식으로 답변 시도).
   호출 생략은 환각 확률을 정확히 0으로 만들고, 응답 0.0초·비용 0의 부수효과.

### 검증 결과 (terms_only 5문항, 양 모델)

| 문항 | 유형 | GPT-4.1 | Qwen3 8B |
|---|---|---|---|
| L26 진단계약이란? | 정상 | O (정의+출처) | O |
| L27 입원이란? | 정상 | O | O |
| L28 통원이란? | 정상 | O | O |
| L29 보험나이란? | 함정 | O 거부, **0.0s** | O 거부, **0.0s** |
| L30 부담보란? | 함정 | O 거부, 0.0s | O 거부, 0.0s |

가드 도입 전 Qwen이 뚫렸던 L30이 모델 성능과 무관하게 차단됨.
→ **"환각을 모델의 확률이 아니라 아키텍처로 방어"** (보고서 핵심 논점).

## 4. 코드 위치

| 파일 | 역할 |
|---|---|
| rag_config.py | search_terms_guarded / extract_query_term / _norm (가드 본체) |
| rag_llm_eval.py | retrieve()에서 가드 사용 + 근거 0건 시 LLM 미호출 (호출 패턴 참조용) |
| llm_questions.json | L26~L30 용어 문항 (함정 포함) |

서비스 구현 시 rag_llm_eval의 retrieve→생성→응답 패턴을 terms_chat 모듈로
이관하면 됨. 가드는 rag_config에 있으므로 import만 하면 된다.

## 5. 남은 일 (구현 단계 이월)

1. **챗봇 모듈화** — terms_chat.py: 질문 입력 → 용어 라우팅 → 가드 검색 →
   Qwen3 생성 → 응답(정의 + 출처) 반환. 웹 챗봇 인터페이스 연결.
2. **라우팅 정규식 보강** — 현재 패턴(이란|란|뭐야|무슨 뜻|정의)이 못 잡는
   변형("~가 무슨 말이에요", "~설명해줘") 추가. 미매칭 시 policy 검색으로
   흘러가므로 치명적이진 않으나 커버리지 개선 여지.
3. **재색인 후 재검증** — 전체 데이터(12개사) terms 재색인 후 동일 5문항 +
   신규 용어 몇 개로 확인 (통과 예상, 절차상).
4. **엣지 케이스 정의** — 복수 용어 질문("A랑 B 차이가 뭐야?"), 오타 처리
   방침. 오타는 벡터 검색이 어느 정도 흡수하나 가드의 문자열 비교와의
   상호작용 확인 필요.
5. (선택) 가드 차단 시 "혹시 이 용어를 찾으셨나요?" 식으로 검색된 유사
   용어를 **후보로만** 제시하는 UX — 정의를 단정하지 않으므로 환각 위험
   없이 사용성 개선 가능.

## 6. 알려진 데이터 이슈 (용어 담당 흐름과 공유됨)

- 페이지 경계에서 용어명이 잘린 5건 (truncated 표식 유지, 정의는 온전)
- term 필드의 줄바꿈 잔재 공백("본인부 담금") — 검색 중복 접기는
  rag_config에서 정규화로 방어 중, 근본 수정은 terms 재생성 시
- 전체 데이터 재전처리 시 terms도 재생성 예정 → 위 이슈 해소 확인 필요
