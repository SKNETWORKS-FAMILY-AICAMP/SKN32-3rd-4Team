# LLM 선정 — 인수인계 (확정)

작성: 2026-08-03. README_LLM_INTERIM.md(중간 해설)를 대체하는 확정 문서.
30문항 정식 평가 완료 기준의 선정 결과와 근거를 기록한다.
※ 단서: 현 결과는 4개사 색인 기준. 전체 데이터(12개사) 재색인 후 동일 30문항
재평가로 최종 검증 예정 — 결과가 뒤집힐 가능성은 낮으나 절차상 남겨둔다.

---

## 1. 선정 결과 (한 줄 요약)

**주력 LLM: GPT-4.1** (보장 판별 등 핵심 기능).
**티어링 후보: Qwen3 8B** (용어 설명 등 경량 기능 — 조건부, 아래 5절).
결정 요인은 정답률이 아니라 **함정 방어의 일관성과 응답 속도**였다.

---

## 2. 평가 방법

- 평가셋: 30문항 (답있음 20 / 답없음 5 / 용어 5 — 함정 2 포함)
  - 전 문항 사전 검색 검증(check_question.py)으로 정답 존재/부재 확인 후 채택
  - 함정 문항: 용어사전에 없는 용어를 물어 유사 오답 근거가 검색되게 설계
    → LLM이 오답 근거에 속지 않고 거부하는지(근거 충실성) 검사
- 파이프라인: rag_config 검색(top-5, 보험사/세대 자동 필터) → 근거 첨부 생성
  → 자동 채점(출처 표기·거부 표현·환각) → 사람 검토로 최종 판정
- 조건 통제: 동일 색인·동일 문항·temperature 0. 복수 실행으로 변동성 확인.

## 3. 결과 요약

| 축 | GPT-4.1 | Qwen3 8B (로컬, RTX 3060 Ti) |
|---|---|---|
| 정답률 (사람 보정) | **~90%** | ~87–90% (동급) |
| 출처 표기 | 안정적 — 실제 보험사·세대·조항 정확 표기 | 프롬프트 수정 후 합격 (placeholder 27건 → 0건) |
| 함정 방어 (오답 근거 거부) | **전 실행 방어 성공** | **1회 환각 발생** — 무관 용어 정의를 질문 용어의 정의로 답변 |
| 속도 (30문항) | 약 1분 (문항당 1–5초) | 약 12분 (문항당 8–70초, 최악 277초) |
| 비용 | API 과금 (프롬프트 캐싱으로 절감 가능) | 무료 (GPU 전기료) |
| 데이터 보안 | 외부 전송 있음 | 로컬 — 외부 전송 없음 |

공통 실패 3문항(L03·L06·L18)은 모두 데이터 원인(조각 청크, \x01 오염)으로
수렴 — 모델 문제가 아니며 재색인으로 개선 예상. 두 모델이 3회 실행 내내
같은 문항에서 같이 실패한 것이 그 증거.

## 4. 선정 근거 (왜 GPT-4.1인가)

1. **함정 방어의 일관성.** 검색이 틀린 근거를 줘도 GPT-4.1은 매 실행 거부.
   Qwen3는 대체로 방어했으나 1회 뚫림(부담보 질문에 본인부담금상한제 정의를
   답변). 보험금 판별 서비스에서 "가끔 환각"은 수용 불가 — 확률적으로
   뚫리는 방어는 프로덕션에서 가장 위험한 특성.
2. **속도 12배.** Qwen3의 문항당 8–70초(최악 4분+)는 대화형 서비스 기준 미달.
   GPT-4.1의 1–5초는 실서비스 가능 수준.
3. **답변 품질 디테일.** 세대별 상이한 수치(예: 처방조제비 공제 2세대
   8천원/20% vs 5세대 3만원/30%)를 GPT는 구분 답변, Qwen은 뭉개는 경향.
4. 정답률 자체는 동급이므로, 위 3가지 운영 특성이 결정 요인.

## 5. Qwen3 티어링 조건 (경량 기능 배치 시)

Qwen3는 무료·보안 우위가 있어 용어 설명 등 경량 기능 배치 후보로 유지하되,
아래 가드를 전제로 한다:

- **용어 일치 가드(코드 레벨)**: terms 검색 top1의 term과 질문 속 용어가
  불일치하면 근거를 LLM에 넘기지 않고 즉시 "확인 불가" 응답. 환각을
  모델의 확률적 방어가 아닌 아키텍처로 차단. (어느 모델을 쓰든 권장)
- 출처 표기는 프롬프트에 **실제 예시** 포함 필수 (placeholder 형식 지시는
  Qwen이 문자 그대로 복사함 — 실측 확인된 함정).
- 속도 요건이 없는 비동기/배치 작업 위주로 배치.

## 6. 평가 과정에서 확립된 방법론 (보고서용)

1. **답없음 문항은 사전 검색 검증 필수** — "약관에 없을 것"이라는 가정이
   틀린 사례 실재(고객센터 전화번호가 약관에 있었음).
2. **자동 채점은 1차 필터** — 거부 표현 7종 확장, 함정(trap) 플래그 도입
   후에도 부분 거부 언급을 과잉 거부로 오판하는 한계 존재 → 사람 검토 병행.
3. **실행 간 변동성 존재** — temperature 0에서도 경계 문항은 실행마다 뒤집힘.
   1–2문항 차이는 노이즈로 간주, 복수 실행 또는 사람 검토로 판정.
4. **실패 원인의 3분류** — 모델 / 검색(필터 미적용 등) / 데이터(조각·오염).
   두 모델이 같은 문항에서 같이 실패하면 모델 원인이 아니라는 교차 검증 활용.

## 7. 실행 방법

```powershell
pip install langchain-openai langchain-ollama langchain-core
$env:OPENAI_API_KEY="sk-..."       # 또는 사용자 환경변수 영구 등록
# Qwen3: ollama.com 설치 후 ollama pull qwen3:8b

python rag_llm_eval.py --models gpt-4.1,qwen3
# 결과: out\llm_eval_results.csv (answer 원문 포함 — 사람 검토 필수)
```

- 문항: llm_questions.json (30문항, trap 필드 포함)
- 문항 추가 시: check_question.py 로 사전 검색 검증 후 채택
- 모델 추가 시: rag_llm_eval.py 의 build_llm() 에 등록 후 --models 로 지정
