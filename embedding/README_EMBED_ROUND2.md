# 임베딩 2라운드 평가 — 방법·환경·결과 정리

작성: 2026-08-03. 12종 임베딩 모델 비교(2라운드)의 실행 환경, 평가 방법,
결과 산출 과정의 전체 기록. 외부 점검 피드백(12_모델팀_개선사항.md)과
SOTA 10선 제안을 반영해 1라운드 대비 방법을 개선한 버전이다.

---

## 1. 왜 2라운드를 했나

1라운드(6모델 × 80문항, 키워드 포함 채점)에 대해 외부 점검에서 두 가지
지적이 들어왔다:

1. **채점 방식** — "그 낱말이 들어 있는가"(키워드 포함)가 아니라
   "그 조항을 찾았는가"(chunk_id 일치)를 재야 한다.
2. **변별력** — 필터교차 계열 24문항(30%)은 메타필터+생성 조건 때문에
   구조적으로 틀리기 어려워 6모델 중 5모델이 만점이었다.

동시에 SOTA 임베딩 10선 목록이 제안되어 후보를 6종 → 12종으로 확장했다.

## 3. 데이터

- **평가 코퍼스**: `out\eval_sample.jsonl` — 4개사 전처리 청크에서 추출한
  1,433청크 샘플 (1라운드와 동일 샘플, 시드 42 고정 → 라운드 간 비교 가능)
- 한계(점검 지적): 실제 색인 231,270청크의 1/160 규모. 1,433개 중 top-5와
  23만 개 중 top-5는 난이도가 다름 — v5 데이터 최종전에서 전체 규모로 재검증 예정

## 4. 평가셋 생성 (gen_questions.py v2)

- 샘플 청크에서 **역방향 생성**: 조건을 만족하는 청크 집합을 먼저 찾고,
  그 조건을 자연어 질문으로 변환. 조건을 만족한 청크들의 chunk_id를
  `answer_ids`로 문항에 기록 → 채점 근거가 문항 안에 내장됨
- **변별력 장치 2개** (1라운드 대비 신규):
  - 키워드 1개 → **2개 조합** 조건 (예: "통원"+"공제") — 정답 집합이
    자연히 좁아지고 질문도 구체화
  - 정답 수 **하한 3 / 상한 25** — 25개 초과(너무 흔한 조건)는 문항 부적격
- 결과: **44문항** (조항지정 14 / 구어체 8 / 표숫자 1 / 필터교차 11 /
  필터교차2중 10), 정답 청크 수 중앙값 **13** (1라운드 초안은 70이었음 —
  상한 도입으로 변별력 확보)
- 표숫자 1문항은 12모델 전멸 → 문항 무효 판정 (전 모델 공통 실패 = 문항
  문제라는 판정 규칙 적용). 실질 유효 43문항.

## 5. 채점 방식 (embed_eval.py v2)

- 모델별로 1,433청크를 임베딩해 Chroma 임시 컬렉션(chroma_eval)에 색인,
  44문항 각각 top-5 검색
- **정답 판정: top-5 결과의 chunk_id가 문항의 answer_ids에 포함되는가**
  (키워드 포함 판정 폐지). 색인용 접미사(::순번)는 base_id로 제거 후 비교
- 지표: hit@5(top-5 내 정답), hit@1(1위가 정답), MRR(첫 정답의 역순위 평균)
- 메타필터 문항(where)은 Chroma 필터 적용($and 자동 처리), temperature 개념
  없음(임베딩은 결정적)

## 6. 모델별 처리 방식 (공정성 관련)

| 모델 | 입력 처리 |
|---|---|
| e5-large | query:/passage: 접두사 (필수 규칙) |
| qwen3-embed 0.6B/4B | **권장 query prompt 적용** (1라운드 미적용 → 점검 지적 반영) |
| arctic 2종 | 내장 query 프롬프트 적용 |
| jina-v5-small | task="retrieval" + 질문에 prompt_name="query" (v5 전용 API) |
| nemotron-1b | plain 입력 — **권장 instruction 미확인 상태의 참고치** (각주 필수) |
| 나머지 | plain 입력 (모델 기본) |

## 8. 해석

1. **arctic 계열 선두 부상.** 채점이 "조항 도달" 기준으로 엄격해지자 1·2위.
   두 변형이 MRR 동률로 나란히 상위권 — 일관된 신호. 단 e5와의 격차는
   44문항 기준 약 3문항으로 소표본 오차범위 언저리.
2. **e5-large는 3위로 하락했으나 여전히 상위권.** 1라운드 결론이 뒤집힌
   것이 아니라 "채점 기준이 바뀌면 순위가 재편된다"는 방법론적 발견.
3. **ko-sroberta -28%p 폭락** — 키워드 채점에서는 유사 낱말 청크로 점수를
   얻었으나 정확한 조항 도달 기준에서는 정밀도 부족. 채점 개선의 가치를
   가장 극적으로 보여준 사례.
4. **openai-3-small 재확인** — 필터교차 2/11 붕괴 포함 10위.
   "유료 API가 당연히 낫다"는 가정이 두 라운드 연속 반박됨.
5. **jina-v5**: 성능 상위권(677M 소형에 hit@5 84%)이나 CC BY-NC 라이선스로
   실서비스 채택 불가 — 라이선스 검토가 선정 기준임을 보여주는 사례.
6. **체급-성능 곡선**: qwen 0.6B(75%) vs 4B(77%) — 파라미터 7배에 +2%p.
   이 도메인에서는 체급보다 학습 방식(arctic류)이 결정적.

## 9. 공식 결론

**"arctic-l-v2 / arctic-ko 유력 부상. v5 전처리 데이터 기반 최종전
(arctic 2종 vs e5-large 3파전, 전체 코퍼스 규모)에서 확정한다."**

1라운드 교훈(소표본 순위 유동, 8→12→18문항에서 선두 3회 교체)을 지키기
위해 44문항 결과만으로 챔피언을 교체하지 않는다. 단 후보군 12→3 압축은
이 라운드의 확정 성과다.

## 10. 재현 방법

```powershell
# embedding\ 에서 (out\eval_sample.jsonl 필요)
python 2_model_select\gen_questions.py            # 44문항 생성 (시드 고정)
python 2_model_select\embed_eval.py --models <모델들,쉼표구분> `
    --questions eval_questions_v5.json --sample out\eval_sample.jsonl
# 결과: out\results_v2.csv 누적. 신규 모델 추가는 embed_eval.py의 MODELS에 로더 등록
```

## 11. 이 라운드의 미해결 항목

- nemotron-1b 권장 instruction 확인 후 재평가 (참고치 → 정식 결과로)
- 표숫자 유형 보강 (현재 유효 문항 0개 — v5 코퍼스에서 재생성)
- 전체 코퍼스(160배) 규모 조건 재검증 — v5 최종전에서 수행
- jina-v5 라이선스: 팀 프로젝트(비상업)에서는 사용 가능하나 서비스 전환
  시 제외 대상임을 결과표에 항구 명시
