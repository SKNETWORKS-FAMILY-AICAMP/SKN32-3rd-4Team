# 디코딩(LLM) 확장 평가 — 4파전 결과 정리

작성: 2026-08-03. 피드백("gemma·법률 파인튜닝 모델도 확인") 반영으로 디코딩
후보를 2종 → 4종으로 확장한 평가 기록. 기존 확정(GPT-4.1 주력 + Qwen3
티어링, README_LLM.md)이 유지되는지가 검증 목표였다.

**결론: 기존 확정 유지.** 신규 2종은 각각 명확한 사유로 탈락 —
gemma3(품질 양호·속도 미달), ko-llama3(신뢰성 붕괴).

---

## 1. 평가 조건

- 동일 30문항(llm_questions.json: 답있음 20 / 답없음 5 / 용어 5·함정 2),
  동일 색인(4개사, policy_e5/terms_e5), 동일 파이프라인(rag_llm_eval.py),
  temperature 0, 용어 일치 가드 적용
- 환경: RTX 3060 Ti 8GB. gemma3:12b(Q4)·ko-llama3(Q4_K_M)는 ollama 로컬,
  GPT-4.1은 API
- 신규 후보 선정 경위: gemma3:12b(요청 모델, 27b는 8GB 불가로 12b 채택),
  ko-llama3 = Llama-3-Open-Ko-8B-Instruct(한국어 특화 파인튜닝 —
  법률 특화 공개 모델 부재로 인한 대체 축, 조사 기록은 README_EMBED_ROUND2)

| 최악 문항 | 5s | 277s | 154s | **3,236s (54분)** |

폭주(총소요의 96%가 문항 2개). EOS(생성 종료) 제어 불안정의 전형.

## 3. 신규 2종 판정

### gemma3 12B — 품질 합격, 속도 탈락

- 사람 보정 ~28/30으로 **정답률은 4종 중 최상위권.** 보험사별 구분 답변,
  출처 표기 모두 안정적. 답없음 5/5 방어.
- 그러나 문항당 평균 47초·총 24분 — 12B를 8GB에 양자화로 얹은 대가.
  대화형 서비스 기준 미달이며 같은 로컬 티어의 Qwen3(품질 동급, 2배 이상
  빠름) 대비 우위가 없음.
- 기록 가치: "품질은 체급을 따라가나 8GB 인프라에서는 8B가 상한"이라는
  체급-인프라 트레이드오프의 실측점.

### ko-llama3 (한국어 특화 파인튜닝) — 신뢰성 붕괴로 탈락

실측된 붕괴 양상 3가지 (모두 CSV 원문 확인):

1. **답없음 5문항 전부 환각.** 대표: "신용카드 포인트 적립되나요?" →
   "네, 적립됩니다 (근거: DB손해보험 2세대...)" — **없는 사실을 단정하고
   가짜 근거까지 인용.** 4종 중 유일한 전멸.
2. **지시 준수 붕괴.** 출처 표기 누락 13/20문항, 심지어 L14는 질문을
   **영어로 반문** ("Please provide the amount...") — 시스템 프롬프트
   자체가 무시됨.
3. **생성 제어 불안정.** 2개 문항에서 각 54분 폭주(EOS 미생성으로 추정).

해석: 한국어 파인튜닝 과정에서 베이스(Llama 3.1 8B Instruct)의
지시-준수 능력이 훼손된 사례. **"도메인/언어 특화 파인튜닝 ≠ 태스크 성능
향상"이며, 오히려 RAG처럼 규칙 준수가 중요한 태스크에서는 역효과**일 수
있음을 보여주는 실측. (법률 파인튜닝 모델을 도입할 때도 동일한 검증이
선행되어야 한다는 근거 — AI Hub 모델 평가 시 체크리스트로 사용)

### 전 모델 공통 관찰

- **용어 일치 가드는 4종 모두에서 작동** (함정 2문항, 차단 시 0.0초).
  ko-llama3처럼 지시를 무시하는 모델에서도 가드가 환각을 차단 —
  "안전장치는 모델이 아니라 아키텍처에 둔다"는 설계 원칙의 4번째 실증.
- **로컬 모델 3종(Qwen·gemma·ko-llama) 모두 특정 문항 장고/폭주**
  (277s / 154s / 3,236s) — 타임아웃 필수 요구사항의 반복 확인.

## 4. 최종 티어링 (변동 없음 — 확정 유지)

| 기능 | 모델 | 이번 라운드의 함의 |
|---|---|---|
| 기능1 보장 판별 | **GPT-4.1** | 속도·일관성 우위 재확인 |
| 기능2·3·4 툴 변환 | **Qwen3 8B** | 로컬 티어 내 대안(gemma3) 대비 속도 2배 우위 |
| 기능5 용어 챗봇 | **Qwen3 8B + 가드** | 가드의 모델 무관성 재실증 |

## 5. 미실측 항목 (시간 제약 — 계획·기록으로 대체)

| 항목 | 상태 |
|---|---|
| AI Hub 민사법 LLM (Llama 3.1 8B) | **승인 완료·사양 확인 완료** (transformers, 4bit로 8GB 구동 가능 판정). 35GB 수령·평가는 후속 과제. 평가 시 3절의 파인튜닝 검증 체크리스트 적용 |
| gemma3:27b, ExtGemma4-44B, Bllossom-70B | 8GB 불가 — runpod(24–80GB) 세션 계획 수립됨 |
| "3.5/3.6" 모델 | 요청자에게 정확한 모델명 확인 요청 중 |

## 6. 재현

```powershell
# ollama 준비: ollama pull gemma3:12b / GGUF + Modelfile로 ollama create ko-llama3
python rag_llm_eval.py --models gemma3,ko-llama3
# 결과: out\llm_eval_results.csv (sec 컬럼 = 문항별 소요)
```

모델 추가는 rag_llm_eval.py의 OLLAMA_MODELS 딕셔너리에 한 줄 등록.
